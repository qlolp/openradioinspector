# Доля архивных наблюдений выше порога

`POST /api/v1/sessions/{id}/sweep-occupancy` выполняет read-only анализ
ограниченного окна общего архива. `features.sweep_occupancy` объявляет поддержку.
Legacy `/api/occupancy` и его модель PanoramaStore не меняются.

```json
{"sweep_id":"sweep-1","before":2,"after":2,"threshold_dbm":-60}
```

Только эти четыре поля; threshold_dbm — конечное число, не bool или строка.
Остальные ограничения совпадают с [контекстом N1/N2](sweep-context.md):
0–16 соседей с каждой стороны, до 131072 исходных точек, точный ID,
совпадение потока, сетки, dBm и записанных настроек (кроме sequence).
Несовместимые соседи отклоняют всё окно; отсутствующие соседи показываются
в missing. Query string запрещён, тело — не больше 8192 байт строгого JSON.

Ответ API v1 содержит неизменённый снимок sweep-context и объект occupancy:

- `method: "sample_fraction"`, `comparison: "strictly_greater"`, threshold_dbm;
- sample_count — количество реально выбранных свипов, включая якорь;
- exceedance_counts и sample_fractions — массивы по исходной сетке:
  число отсчётов строго выше порога и это число / sample_count;
- acquisition_span_seconds — от самого раннего начала до самого позднего
  конца; acquisition_covered_seconds — длина объединения интервалов свипов,
  без двойного учёта перекрытий;
- acquisition_gap_count и acquisition_gap_seconds — число и суммарная
  длительность разрывов между этими интервалами;
- `rf_time_occupancy: null` — доля времени излучения неизвестна.

Равенство порогу не является превышением. Все свипы имеют одинаковый вес,
независимо от длительности. Повторяющиеся частоты сохраняются как отдельные
индексы. Отсутствие якоря — 404, не фиктивная занятость 0%. Несовместимое
окно — 409 context_incompatible; неверный запрос — 400 invalid_request;
слишком большое тело — 413 request_too_large. Снимок содержит исходные
ID, UTC-интервалы, уровни и настройки, поэтому результат можно воспроизвести.

Интервалы сканирования **не означают непрерывное наблюдение каждой частоты**.
Пробелы архива не считаются тишиной. Это статистика имеющихся отсчётов,
а не нормативное измерение занятости и не оценка вероятности перехвата.
AR-DV1 S-meter не преобразуется в dBm. Команды, события, кандидаты и записи
в архив не создаются; анализ доступен и для заполненного архива.

## Интерфейс и проверка

WebUI: в панели N1/N2 задайте ручной порог и нажмите «Оценить занятость окна».
Отображаются 20 наиболее активных точек с индексом, числителем и знаменателем;
API возвращает все точки. Порог −80 dBm — пример, не норма. Новые свипы
не меняют зафиксированный результат. Изменение формы, области, потеря связи
и таймаут инвалидируют ожидающий ответ. Сервер без нового маршрута даст
понятную ошибку; обычная загрузка контекста продолжит работать.

```sh
bash run_tests.sh -p test_sweep_occupancy.py
bash run_tests.sh -p test_webui_sweep_context.py
```

Реализованы ядро, API, WebUI и панели Windows/macOS. В нативных клиентах
в панели N1/N2 задайте порог dBm и нажмите «Занятость». Числители,
знаменатели и интервалы приходят из общего ядра; UI не выбирает соседей
и не выполняет независимый измерительный расчёт. Windows показывает все
частотные отсчёты в текстовой таблице, macOS — в раскрываемом списке.
Обычная загрузка окна остаётся отдельной операцией.

Во всех трёх клиентах есть «Экспорт JSON»: сохраняется только успешно
проверенный ответ занятости, включая все исходные свипы, настройки, UTC,
частотную сетку, запрос N1/N2, missing и порог. Изменение порога, сеанса,
потока или очистка инвалидируют результат и ожидающее сохранение. Новые
свипы при опросе не меняют ранее полученный снимок. В Windows/macOS
отмена диалога не создаёт файла; сохранение атомарное. В WebUI результат
передаётся механизму загрузок браузера, который подтверждает сохранение.

Проверки — синтетические (memory/SQLite, настоящий HTTP, обработчики
JavaScript, Python и Swift Testing). Аппаратная и визуальная проверка
Windows/macOS/браузера не выполнялась.

## Переносимый результат, версия 1

```json
{"format":"openradioinspector-sweep-occupancy","format_version":1,"data":{}}
```

Здесь `data` — полный объект ответа `/sweep-occupancy`, а не пустой объект
из сокращённого примера. Версия формата 1 фиксирует семантику алгоритма:
`sample_fraction`, строгое превышение, одинаковый вес каждого свипа,
объединение интервалов сбора и неизвестное `rf_time_occupancy`. Изменение
этой семантики требует новой версии формата. Профиль устройства сохраняется
только если он присутствовал в исходных настройках; экспорт не добавляет
выдуманную калибровку или возможности прибора.

Поле `data` копируется из проверенного ответа сервера без повторного
кодирования: сохраняются имена вложенных ключей и числовые литералы,
включая целые больше 2^53. UI может отображать такие настройки с меньшей
точностью, но экспорт сохраняет исходные байты. Это локальный аналитический
артефакт, не второй архив, не формат IQ и не команда записи на сервер.
CSV-сводка доступна через CLI ниже; импорт артефакта в интерфейс пока не реализован.

Воспроизведение расчёта из корня репозитория (без подключения к прибору):

```python
import json
from pathlib import Path
from radioinspector.sweep_occupancy import summarize_occupancy

artifact = json.loads(Path("sweep-occupancy.json").read_text(encoding="utf-8"))
assert artifact["format"] == "openradioinspector-sweep-occupancy"
assert artifact["format_version"] == 1
data = artifact["data"]
assert summarize_occupancy(data, data["occupancy"]["threshold_dbm"]) == data["occupancy"]
```

Общая фикстура `tests/fixtures/sweep-occupancy-v1.json` проверяется в Python,
Swift и исполняемых обработчиках WebUI; содержит пять свипов, четыре разрыва и число 9007199254740993
в настройках. Тесты проверяют неверные параметры ответа, отмену/смену
области, поздний ответ и экспорт исходных данных без потери точности.

```sh
bash run_tests.sh -p test_windows_sweep_occupancy.py
# На macOS с Xcode — полная синтетическая проверка со своими HTTP-фикстурами
python -m tests.run_release_checks --swift
```

Интеграционный тест `test_webui_with_real_core_and_synthetic_archive`
запускает обработчики WebUI через Node и настоящий HTTP API с синтетическим
архивом: окно 5 × 101 точка, порог −90 dBm, четыре временных разрыва,
проверка числителей/знаменателей и неизменности состояния ядра. Это проверка
логики интерфейса и HTTP, не визуальная проверка браузера.

## Проверяемый CSV-экспорт без оборудования

После сохранения JSON в любом клиенте можно построить CSV-сводку общим
модулем ядра, без сервера, последовательного порта или изменения архива:

```sh
python -m radioinspector.occupancy_export sweep-occupancy.json --output sweep-occupancy.csv
```

Это CLI-экспорт; кнопки CSV в клиентах пока нет. JSON остаётся полным
источником исходных измерений и настроек. CSV содержит одну строку на каждый
индекс исходной сетки (повторяющиеся частоты не объединяются), частоты в целых
Гц, числитель/знаменатель, долю, порог dBm, метод, UTC-границы, пропуски
и SHA-256 исходного JSON-файла. `rf_time_occupancy` записывается как `unknown`,
а не 0. `format_version=1` обозначает эту версию CSV-схемы.

Сначала проверяются версия JSON, уникальность ключей, предел размера
2 100 000 байт, предел CSV 16 MiB (включая повторяемые ID), порядок/совместимость исходных свипов и целочисленные поля.
Контекст и статистика заново рассчитываются существующими функциями ядра;
несогласованный результат отклоняется до создания CSV. Это проверка
внутренней согласованности, не доказательство подлинности измерений.

`session_id_json`, `stream_id_json`, `anchor_id_json`, `source_ids_json`
содержат JSON-строки/массивы: кавычки и переносы сохраняются, а текст ID
не превращается в формулу электронной таблицы. CSV — UTF-8, разделитель
запятая, строки CRLF. Для восстановления ID применяется JSON-декодирование
уже прочитанной CSV-ячейки. Выходной файл публикуется атомарно; существующий
файл, включая исходный JSON, никогда не заменяется.

Проверка: `bash run_tests.sh -p test_occupancy_export.py`.

## Повторная аппаратная проверка

2026-11-09 macOS обнаружила USB serial `/dev/cu.usbmodem4001`. Попытка
запуска штатного `tinysa-serial` через отдельное ядро и временную SQLite
остановилась на открытии порта: `Operation not permitted`. Повторный запуск
с запросом расширенного доступа дал тот же результат. Новых аппаратных
свипов в этом запуске не получено; прежний отчёт приёмки не заменяет эту
проверку. Это блокер доступа среды Xcode, а не подтверждённая неисправность
прибора. Исходные измерения и локальные журналы в Git не включены.

Для выполнения в обычном Terminal из корня проекта, при закрытых других
владельцах порта:

```sh
.venv/bin/python tests/check_tinysa_occupancy_hardware.py --port /dev/cu.usbmodem4001
```

Сценарий не входит в автоматический набор тестов. Только служба ядра открывает
порт. Выполняются штатные проверки identity и ACK настройки приёма,
`output off`, затем не менее пяти свипов 88–108 МГц по 101 точке с запрошенным
RBW 30 кГц. Далее — остановка, проверка исходных Hz/dBm, занятости, JSON/CSV
и стабильности числа записей после остановки. Временная SQLite и JSON остаются
в напечатанном локальном каталоге для разбора. PASS относится только к этим
сценариям; он не подтверждает RF-калибровку, физический readback выключения
генератора, визуальный UI, Windows COM или работу других приборов.
