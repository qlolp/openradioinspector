# Доля архивных наблюдений выше порога

`POST /api/v1/sessions/{id}/sweep-occupancy` выполняет read-only анализ
ограниченного окна общего архива. `features.sweep_occupancy` объявляет поддержку.
Legacy `/api/occupancy` и его модель PanoramaStore не меняются.

```json
{"sweep_id":"sweep-1","before":2,"after":2,"threshold_dbm":-60}
```

Только эти четыре поля; threshold_dbm — конечное число, не bool или строка.
Остальные ограничения совпадают с [контекстом N1/N2](sweep-context.md):
0–16 соседей с каждой стороны, до 131072 исходных точек, точный ID,
совпадение потока, сетки, dBm и записанных настроек (кроме sequence).
Несовместимые соседи отклоняют всё окно; отсутствующие соседи показываются
в missing. Query string запрещён, тело — не больше 8192 байт строгого JSON.

Ответ API v1 содержит неизменённый снимок sweep-context и объект occupancy:

- `method: "sample_fraction"`, `comparison: "strictly_greater"`, threshold_dbm;
- sample_count — количество реально выбранных свипов, включая якорь;
- exceedance_counts и sample_fractions — массивы по исходной сетке:
  число отсчётов строго выше порога и это число / sample_count;
- acquisition_span_seconds — от самого раннего начала до самого позднего
  конца; acquisition_covered_seconds — длина объединения интервалов свипов,
  без двойного учёта перекрытий;
- acquisition_gap_count и acquisition_gap_seconds — число и суммарная
  длительность разрывов между этими интервалами;
- `rf_time_occupancy: null` — доля времени излучения неизвестна.

Равенство порогу не является превышением. Все свипы имеют одинаковый вес,
независимо от длительности. Повторяющиеся частоты сохраняются как отдельные
индексы. Отсутствие якоря — 404, не фиктивная занятость 0%. Несовместимое
окно — 409 context_incompatible; неверный запрос — 400 invalid_request;
слишком большое тело — 413 request_too_large. Снимок содержит исходные
ID, UTC-интервалы, уровни и настройки, поэтому результат можно воспроизвести.

Интервалы сканирования **не означают непрерывное наблюдение каждой частоты**.
Пробелы архива не считаются тишиной. Это статистика имеющихся отсчётов,
а не нормативное измерение занятости и не оценка вероятности перехвата.
AR-DV1 S-meter не преобразуется в dBm. Команды, события, кандидаты и записи
в архив не создаются; анализ доступен и для заполненного архива.

## Интерфейс и проверка

WebUI: в панели N1/N2 задайте ручной порог и нажмите «Оценить занятость окна».
Отображаются 20 наиболее активных точек с индексом, числителем и знаменателем;
API возвращает все точки. Порог −80 dBm — пример, не норма. Новые свипы
не меняют зафиксированный результат. Изменение формы, области, потеря связи
и таймаут инвалидируют ожидающий ответ. Сервер без нового маршрута даст
понятную ошибку; обычная загрузка контекста продолжит работать.

```sh
bash run_tests.sh -p test_sweep_occupancy.py
bash run_tests.sh -p test_webui_sweep_context.py
```

Реализованы ядро, API и WebUI. Проверки — синтетические (memory/SQLite,
HTTP и исполняемые обработчики JavaScript). Windows/macOS-панели этого
расчёта остаются следующим этапом. Аппаратная проверка не выполнялась.
