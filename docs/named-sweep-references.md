# Именованные архивные эталоны

Каталог сохраняет имя и ссылку на уже записанный совместимый `dBm` свип.
Это продолжение [сравнения свипов](sweep-comparison.md): расчёт по-прежнему
выполняется в общем ядре, а исходное измерение не переписывается и не копируется
в отдельную панораму.

## Работа оператора

В WebUI, Windows Tk или macOS SwiftUI:

1. Выберите сеанс и спектральный поток. Закрепите свип в панели сравнения.
2. Введите имя и явно сохраните закреплённый свип в каталог.
3. Выберите сохранённую запись и используйте её как эталон.
4. Нажмите сравнение с последним свипом. Цель фиксируется по ID в момент
   действия; обновление live-снимка не пересчитывает результат автоматически.

Сохранённый эталон доступен, даже если его свип уже не входит в последние
40 записей снимка. Каталог общий для клиентов, подключённых к одному ядру.
Новые записи другого клиента появляются после явного обновления каталога.
Первое чтение выполняется при выборе нового сервера/сеанса/потока, а не на
каждом тике live polling.

Клиенты показывают режим хранения: в файловом SQLite каталог переживает
перезапуск ядра, в памяти существует только до завершения процесса. Особый
SQLite-архив `:memory:` также временный: ответ имеет `storage_mode: "sqlite"`
и `persistent: false`. О долговечности сообщает именно `persistent`,
а не одно лишь название backend. Текущий локальный
выбор по-прежнему сбрасывается при смене сервера, сеанса или потока; затем
можно снова выбрать сохранённую запись из каталога.

«Очистить» сбрасывает выбор в окне. Удаления, переименования, перезаписи или
автоматической замены записей каталога в этом срезе нет. Локальное закрепление
и сравнение продолжают работать с сервером PR #69, не поддерживающим каталог.

## API версии 1

```text
GET /api/v1/sessions/{session_id}/sweep-references
GET /api/v1/sessions/{session_id}/sweep-references?stream_id={stream_id}
POST /api/v1/sessions/{session_id}/sweep-references
```

GET возвращает обычную оболочку `api_payload`. Объект `data`:

```json
{
  "session_id": "session-1",
  "stream_id": "spectrum-1",
  "storage_mode": "sqlite",
  "persistent": true,
  "limit": 100,
  "items": [
    {
      "id": "reference-record-1",
      "session_id": "session-1",
      "stream_id": "spectrum-1",
      "sweep_id": "sweep-1",
      "name": "Фон до включения оборудования",
      "created_at": "2026-11-08T08:00:00Z",
      "interval": {
        "started_at": "2026-11-08T07:59:00Z",
        "ended_at": "2026-11-08T07:59:01Z"
      },
      "level_unit": "dBm",
      "points": 101
    }
  ]
}
```

Без фильтра `stream_id` равен `null`, список включает потоки выбранного
сеанса. `limit` равен 100 и относится ко всему сеансу, а не отдельно к каждому
потоку. Каталог ограничен сервером, пагинация не требуется. Пустой каталог
возвращает `items: []`.

Тело POST содержит только имя и ID существующего свипа:

```json
{"name": "Фон до включения оборудования", "sweep_id": "sweep-1"}
```

Создание возвращает `201` и одну запись. Повтор с тем же нормализованным
именем и тем же `sweep_id` возвращает `200` и прежнюю запись с прежними ID и
временем создания. Это работает и при заполненном каталоге. То же имя с
другим свипом не заменяет запись, а возвращает `409 reference_name_conflict`.
Уникальность имени проверяется в пределах сеанса, включая разные потоки.

Имя нормализуется в Unicode NFC. До удаления крайних пробелов проверяются
запрещённые символы: даже завершающие ASCII tab, LF и CR отклоняются, а не исчезают
при нормализации. Затем применяется очистка крайних пробельных символов.
Допускается от 1 до 80 Unicode-кодовых точек; регистр значим. Запрещены символы
категории Unicode C: управляющие, форматирующие, суррогатные, частного
использования и не назначенные символы. Например, составное `е` с диакритикой
и его нормализованное представление относятся к одному имени. Сервер является
источником правил; клиенты не должны считать число UTF-16 единиц или графем
эквивалентом числа кодовых точек.

Ошибки:

- `400 invalid_request`: некорректное имя, тело или query-параметры, включая
  `stream_id`, который не принадлежит выбранному сеансу. POST не принимает
  query-параметры; фильтр `stream_id` применяется только к GET.
- `404 session_not_found` / `sweep_not_found`: сеанс или свип не найдены в
  указанном сеансе; чужое измерение не раскрывается.
- `409 comparison_incompatible`: свип не проходит правила сравнения PR #69,
  включая единицу `dBm`, записанные настройки и максимум 16 384 точки.
- `409 reference_name_conflict`: имя уже связано с другим свипом.
- `409 reference_limit_reached`: в сеансе уже 100 записей, а запрос создаёт новую.

`features.named_sweep_references` сообщает поддержку каталога. Для сравнения
используется `sweep_id` сохранённой записи, а не её собственный `id`:

```text
GET /api/v1/sessions/{session_id}/sweep-comparison?reference_id={sweep_id}&target_id={target_sweep_id}
```

Первое создание публикует `sweep_reference.created` с `payload: {reference: record}`;
повтор существующего
запроса не создаёт событие и не сдвигает его курсор. Запись каталога и событие
SQLite фиксируются атомарно. При ошибке транзакции не появляется ни запись,
ни событие. GET не меняет архив.

## Неопределённый исход сохранения

Операция сохранения выполняется только после действия оператора. Автоматических
повторов POST нет. Таймаут, закрытие окна, отмена запроса или смена сеанса
могут произойти уже после того, как сервер сохранил эталон. Клиент не утверждает,
что такая отмена отменила запись: следует обновить каталог и проверить имя.
Если запись найдена, её можно использовать. Повтор того же имени и свипа
безопасен благодаря серверной идемпотентности, но тоже выполняется явно.

Поздние ответы старого сеанса/потока не заменяют текущий выбор или каталог.
Ошибки каталога, включая `404` старого сервера, не блокируют live-панели,
исходные измерения или уже поддерживаемое локальное сравнение.

## SQLite, обновление и ограничения

Версия SQLite-схемы повышена с 2 до 3. Добавляется таблица ссылок и необходимые
ограничения/индексы; существующие измерения, события и их единицы сохраняются.
Миграция новой схемы и номера версии атомарна. Архив более новой неизвестной
версии отклоняется. Старое ядро, поддерживающее только v2, не открывает v3.
Перед обновлением рабочей установки следует остановить службу и сохранить
резервную копию архива. Автоматического отката или понижения схемы нет.

Каталог хранит ссылки и небольшие метаданные, не массивы уровней/частот.
Миграция, индекс, записи каталога и события занимают дополнительное место.
`--archive-max-bytes` ограничивает приём измерений, а не служебные записи:
сохранение эталона может увеличить логический размер даже при полном архиве.
Не удаляется ни один свип, старый эталон или событие.

Сохранённые эталоны не входят в NDJSON-экспорт/импорт измерений. Перенос
именованного каталога между отдельными архивами, постоянное хранение
усреднённых эталонов и автоматический detector по разности остаются отдельной
работой. Read-only [усреднение мощности](averaged-sweep-reference.md) и
[адаптивный порог](adaptive-sweep-threshold.md) реализованы отдельными срезами.
Совпадение метаданных не подтверждает одинаковый физический тракт.

## Проверка среза

8 ноября 2026 прошли 479 Python/Node-тестов, 76 Swift API-тестов, 28 native-тестов
и полная Xcode-сборка без подписи. Проверены миграция с откатом при сбое,
неизменность будущей неизвестной схемы, лимит/гонки/идемпотентность и атомарный
журнал событий, Unicode, временный SQLite и отсутствие автоматических POST.

Интеграционные проверки обращались к реальному локальному синтетическому API:
каталог восстановился после перезапуска SQLite; WebUI JavaScript, Windows HTTP/Tk
и Swift DTO использовали сохранённый эталон вне rolling snapshot и создавали
именованные записи. Повтор вернул прежний ID без нового события. Сравнение
101 точки сохранило +20 dB на 103 МГц и −10 dB на 107 МГц.

Визуальная проверка браузера/SwiftUI не выполнена: экран Mac был заблокирован.
Tk construction/update/close проверены на macOS; Windows OS и аппаратный стенд
не проверялись. Совпадение метаданных не заменяет метрологическую проверку.

```bash
python -m unittest tests.test_sweep_references
python -m unittest discover -s tests -t .
swift test --package-path macos/SpektrKomandy
swift test --package-path macos
xcodebuild -project macos/DvoynoyObzor.xcodeproj -scheme DvoynoyObzor \
  -configuration Debug -destination 'platform=macOS' \
  -derivedDataPath macos/DerivedData CODE_SIGNING_ALLOWED=NO build
```
