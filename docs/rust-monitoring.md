# Rust monitoring detector

`ori-monitoring` is a pure Rust 1.99.1 / edition 2024 port of
`radioinspector.monitoring.detector` at `96696a0`, detector version
`robust-city-v1`. It consumes `ori_contracts::Sweep`. It does not own hardware,
HTTP, archive transactions, project lifecycle or event IDs.

## Integration API

- `stable(&Value)`, `canonical_fingerprint_json(&Sweep)` and `fingerprint(&Sweep)`
  preserve the Python compatibility fingerprint. Only the existing five volatile
  keys are removed, recursively. Grid frequencies remain integer Hz.
- `build_baseline(&[Sweep]) -> Result<Baseline>` preserves source order, the
  twenty-sweep/sixty-second minimum, median, nearest-rank p95, MAD and median
  adjacent-start cadence. The baseline remains immutable during detection.
- `Detector::new(Baseline, Parameters, Option<Value>)` and `restore_json` validate
  checkpoints. `step(&Sweep, &[AllowedSignal])` returns typed `DetectionStep`
  with regions, `excess_db` and `thresholds_db`. It commits the next in-memory
  state only after validation; an incompatible/invalid input leaves it unchanged.
- Use `checkpoint()` or `checkpoint_json()` for persistence. `state()` is a
  borrowed typed view; the checkpoint methods also preserve explicit null
  presence and unknown JSON extensions. `take_quality_issue()` removes and returns
  gap evidence, matching the Python service's pop before persisting its cursor.

`Baseline.extra["sweep_period_seconds"]` deliberately preserves three states:
absent means the legacy interval/source-count fallback; null means unknown
cadence; numeric zero disables forward-gap checks. Negative time jumps still
reset confirmation. Python baseline/recent-source timestamps use `+00:00`, while
`last_started_at` uses `Z`; zero microsecond fractions are omitted as in Python
`datetime.isoformat`. This compatibility formatting is separate from canonical
SDK wire timestamps, which always have six fractional digits.

The fingerprint/checkpoint encoder follows Python `json.dumps(sort_keys=True,
ensure_ascii=True, allow_nan=False)` with default comma/colon spaces, shortest
IEEE-754 float formatting, explicit float negative zero and arbitrary integer
metadata. Unicode is ASCII escaped, including surrogate pairs for valid astral
characters. Decode untrusted sweeps with the shared strict codec; integer JSON
`-0` must normalize to Python integer `0`, while `-0.0` remains a negative float.
The root codec regression fix is required for that distinction.

## Behavior and bounds

The port preserves detect-before-learn ordering, three-of-five confirmation,
immediate impulses, adaptive offsets clamped to ±3 dB, duration clamping,
allowed/watch rules, broad and dense summaries, and first-bin selection on tied
peaks. Suppressed bins are excluded before broad/dense aggregation but still
participate in the original quiet-learning gate. An impulse below a high robust
threshold is still detected and never learned.

Application parameter limits remain `1 <= confirmations <= window_sweeps <= 15`
and the existing finite margin/impulse/hysteresis ranges. Limits fail closed:
65,536 bins, 4,096 baseline sweeps, 16,777,216 baseline cells, 1,000 allowed
rules, JSON depth 64 and 8 MiB canonical JSON/checkpoints. Restoring checks vector
widths, finite statistics/offsets, offset range, bounded history/source lists,
version and timestamps. It never truncates or repairs corrupt measurements.

Event reconciliation remains with the core's serialized archive transaction.
The Python service interrupts open events on a gap, chooses the first overlapping
open event of the same broad/dense category, updates peak fields only on a strictly
larger excess, counts one source sweep per touched event, and closes after five
quiet sweeps using strict hysteresis. The detector exposes the recent-source
window and pre-learning excess/thresholds for that work. This crate does not
claim an implementation of that event orchestration.

## Verification

The committed fixture is generated by the actual Python module using authored
synthetic sweeps. It covers odd/even baseline statistics, carrier history,
nonconsecutive confirmation, impulses, allowed/background signals, quiet offsets,
broad/dense changes, first/tail peaks, gaps, restart, missing/null/zero cadence,
incompatible settings and negative zero. Every replay compares initial and
per-step Python checkpoint bytes. Fingerprint cases include 2,048 seeded finite
IEEE-754 values, Unicode, nested volatile keys, large integer metadata and raw
numeric lexemes. Additional tests cover invalid restore data and a bounded
500-step lifecycle.

Regenerate with `python crates/ori-monitoring/tests/generate_fixtures.py`.
In the integrated workspace run `cargo test -p ori-monitoring` and
`cargo clippy -p ori-monitoring --all-targets -- -D warnings`.
The final manifest uses portable `../ori-contracts`; a temporary ignored local
manifest can point at the separately owned SDK while worktrees are isolated.
No physical or performance acceptance is claimed by these synthetic checks.
