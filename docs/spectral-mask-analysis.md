# Спектральная маска по таблице

Этот срез добавляет переносимую маску в виде JSON-файла и явную проверку
одного архивного `dBm` свипа. Общее ядро рассчитывает линию маски на частотах
исходной записи и области строгого превышения. Raspberry Pi WebUI, Windows
Tk и macOS SwiftUI позволяют загрузить и редактировать текст маски,
запустить анализ и сохранить проверенный артефакт.

Загрузка файла и редактирование происходят локально. Нажатие анализа явно
передаёт текст маски подключённому ядру. POST используется для передачи
артефакта, но операция **только читает архив**: измерения, события, каталог
эталонов, кандидаты и задачи не меняются. Новая миграция не нужна.

## Формат отдельного артефакта

Пример: [examples/spectral-mask.json](examples/spectral-mask.json).

```json
{
  "format": "openradioinspector-spectral-mask",
  "format_version": 1,
  "name": "Пример маски, не норматив",
  "frequency_unit": "Hz",
  "level_unit": "dBm",
  "interpolation": "linear_dbm",
  "vertices": [
    {"frequency_hz": 100000000, "limit_dbm": -85},
    {"frequency_hz": 102000000, "limit_dbm": -75},
    {"frequency_hz": 104000000, "limit_dbm": -75}
  ]
}
```

- Файл содержит UTF-8 JSON без BOM, до 65 536 байт.
- Все показанные ключи обязательны, неизвестные и повторные ключи
  отклоняются, включая поля внутри каждой вершины.
- Версия формата — целое `1`. Булевы значения не заменяют числа.
- От 2 до 128 вершин с **строго возрастающими** целочисленными частотами.
  Частота от 0 до 9 007 199 254 740 991 Гц включительно. Это граница точного
  представления во всех клиентах, а не заявленный диапазон прибора.
- `limit_dbm` — конечное число; `NaN` и бесконечности запрещены.
- Имя приводится к NFC, внешние пробелы убираются, длина — 1–80 кодовых
  точек Unicode. Символы категорий `C*` запрещены до удаления пробелов,
  поэтому завершающий перевод строки внутри имени не принимается.
- Поддерживаются только `frequency_unit: Hz`, `level_unit: dBm` и
  `interpolation: linear_dbm`.

Файл не содержит ссылок на сеанс, устройство, локальный путь или сервер.
Один проверенный артефакт можно загрузить в любой из трёх клиентов.
Он не сохраняется в SQLite и не добавляется в NDJSON-экспорт измерений.

## Расчёт и границы применимости

Для частоты между соседними вершинами `(f0, L0)` и `(f1, L1)` ядро получает
`t = (f - f0) / (f1 - f0)` и порог `(1 - t) * L0 + t * L1`.
На частоте вершины используется её точный записанный уровень. Интерполяция
идёт в **dBm**, не в линейной мощности. Исходные уровни и частоты свипа
никогда не интерполируются и не меняются.

Весь свип должен находиться между первой и последней частотой маски.
Экстраполяции, частичного анализа или молчаливого усечения нет. Повторяющиеся
частоты исходного свипа сохраняются, но вершины маски повторяться не могут.
Поддерживаются от 1 до 16 384 исходных точек и только известные записанные
настройки измерения, как при [сравнении свипов](sweep-comparison.md).

`excess_levels[i] = sweep.levels[i] - threshold_levels[i]`, единица `dB`.
Области формируются только при превышении **строго больше нуля**; равенство
линии маски не выделяется. Область — максимальная непрерывная
последовательность индексов. Границы включены; пик выбирается по наибольшему
превышению, при равенстве — первый индекс. Расстояние между соседними
частотами не определяет разрыв области, границы не являются измеренной
занимаемой полосой.

Для приведённого файла и частот 100, 101, 102, 103, 104 МГц линия равна
`[-85, -80, -75, -75, -75] dBm`. При исходных уровнях
`[-90, -90, -60, -90, -90] dBm` превышение равно
`[-5, -10, 15, -15, -15] dB`, единственная область — индекс 2.

Маска задаётся оператором. Пример и создаваемый интерфейсом горизонтальный
шаблон −80 dBm **не являются нормативом**. Превышение не доказывает помеху,
тип излучения или несоответствие законодательству. Калибровка тракта и
пригодность маски для конкретной методики отдельно проверяются оператором.
Не выполняются перевод S-метра в dBm, автоматическое обнаружение,
перестройка, handoff или включение генератора.

## HTTP API

```text
POST /api/v1/sessions/{session_id}/sweep-mask-analysis
Content-Type: application/json

{"sweep_id":"sweep-1","mask_json":"{\"format\":\"openradioinspector-spectral-mask\",...}"}
```

Внешний объект содержит ровно `sweep_id` и `mask_json`. Query-параметров нет.
`mask_json` передаётся **строкой с исходным текстом**, а не уже разобранным
объектом: это позволяет ядру обнаружить повторные поля в импортированном
файле. ID сеанса кодируется как один сегмент URL.

Размер HTTP-тела для этого маршрута ограничен 524 288 байт до чтения;
неверная/повторная длина или неподдерживаемое transfer encoding отклоняются.
Сам текст артефакта после декодирования ограничен 65 536 UTF-8 байт.
У старых API поведение приёма тела не изменяется.

Успех — HTTP 200, стандартная оболочка `api_payload` версии 1. `data`:

```text
session_id, stream_id
sweep: { id, interval: { started_at, ended_at }, levels, level_unit, settings }
mask: полный проверенный артефакт с нормализованным именем
frequencies_hz: все исходные частоты
threshold_levels: линия маски в каждой исходной точке
level_unit: "dBm"
excess_levels: знаковая разность исходного уровня и маски
delta_unit: "dB"
comparison: "strictly_greater"
regions: [{ start_index, end_index, start_frequency_hz, end_frequency_hz,
            peak_index, peak_frequency_hz, peak_excess_db, points }]
points, exceedance_points, region_count
```

- `400 invalid_request`: неверный внешний объект, параметры URL, JSON,
  формат/версия/вершины/имя маски, размер артефакта или заголовки тела.
- `404 session_not_found` / `sweep_not_found`: сеанс или точный свип не найден;
  запись другого сеанса не раскрывается.
- `409 mask_incompatible`: несовместимый источник, выход за покрытие маски,
  превышение границ числа точек/частоты или неконечный производный результат.
- `413 request_too_large`: HTTP-тело больше 524 288 байт; соединение закрывается.

`features.spectral_mask_analysis` сообщает поддержку. Клиенты принимают только
HTTP 200, проверяют принадлежность результата зафиксированному источнику и
маске и не заменяют расчёт ядра локальной интерполяцией.

## Работа в трёх клиентах

1. Выберите сеанс и поток с архивным `dBm` свипом.
2. Откройте JSON-файл или создайте пример по крайним частотам текущего свипа.
   Для свипа с единственной частотой такой шаблон не строится: две разные
   частоты покрытия задаются вручную. Отредактируйте имя и вершины.
3. Нажмите анализ. До этого текст является непроверенным черновиком и
   никуда не отправляется. Результат фиксирует ID, UTC-интервал и маску.
4. При необходимости сохраните **проверенную маску из результата** отдельным
   JSON-файлом. Это не экспорт исходных измерений или производного графика.

Изменение текста отменяет ожидающий анализ и убирает прежний результат и
возможность его сохранить. Смена области или отключение тоже сбрасывает
результат; черновик может остаться в редакторе, но не применяется автоматически.
Новые polling/SSE снимки меняют лишь источник следующего явного действия.

Загрузка, выбор пути и сохранение могут быть отменены. Ошибка чтения/записи
показывается в панели. Нативные клиенты записывают выбранный файл атомарно;
сбой до замены не повреждает существующее содержимое. Браузер использует
обычную загрузку JSON-файла и свои правила сохранения. Секреты и локальные
пути не добавляются в артефакт.

Один анализ выполняется одновременно; ожидание ограничено 8 секундами в
WebUI/Windows и 6 секундами в macOS. Поздний ответ после отмены или смены
области игнорируется. Windows не может прервать уже работающий urllib-запрос,
поэтому новая попытка доступна после окончания прежнего транспорта.
Отмена POST не вызывает неопределённости записи: этот маршрут ничего не пишет.

Ответ ограничен 2 000 000 байт во всех клиентах. Большие метаданные или число
областей могут превысить предел даже при допустимом числе точек; тогда ответ
отклоняется целиком. WebUI/Windows показывают первые 200 областей с общим
числом, macOS использует ленивый список. Все точки принятого ответа остаются
на графике.

## Архив, совместимость и проверки

Ядро читает один точный ID, включая записи вне окна последних свипов.
Ни успех, ни отказ не пишут данные или события и не меняют курсор,
каталог и лимит архива. Анализ доступен при заполненном архиве. Схема остаётся
v3; требование резервной копии перед наследуемой миграцией 2 → 3 из PR #70
сохраняется, этот срез не добавляет миграций.

Срез покрывает одну табличную маску. [Три горизонтальные линии](three-sweep-thresholds.md)
реализованы отдельно. Одновременные три маски, нормативная библиотека,
серверный каталог, автоматическое применение и аттестованные измерения
остаются отдельной работой.

```bash
python -m unittest tests.test_spectral_mask
python -m unittest discover -s tests -t .
swift test --package-path macos/SpektrKomandy
swift test --package-path macos
xcodebuild -project macos/DvoynoyObzor.xcodeproj -scheme DvoynoyObzor \
  -configuration Debug -destination 'platform=macOS' \
  -derivedDataPath macos/DerivedData CODE_SIGNING_ALLOWED=NO build
```

Программные тесты используют только синтетические свипы и временные файлы.
Реальные пользовательские архивы и приборы для разработки не открываются.

Итоговый прогон 8 ноября 2026: 572 Python/Node-теста, 101 Swift API-тест
и 51 native-тест прошли; Xcode собрал приложение без подписи. Swift API
запускался с `ORI_MASK_SMOKE_BASE_URL` и `ORI_THRESHOLD_SMOKE_BASE_URL`,
указывающими только на временные синтетические серверы. Без этих переменных
два необязательных живых smoke-теста пропускаются.

Реальные локальные HTTP-проверки трёх клиентов подтвердили пример из файла
на 101 точке диапазона 100–104 МГц: области 30 и 69–71, четыре превышения,
пики +12 dB и +5 dB. WebUI-модуль и Windows/Tk прошли загрузку, анализ,
экспорт проверенной маски, повторную загрузку и анализ. Нативные файловые
помощники проверены на временных файлах, включая ошибку атомарной записи.
Полные логические dump обеих временных SQLite до и после проверок совпали
по SHA-256. Независимая сверка 300 случайных примеров с NumPy подтвердила
интерполяцию, области и выбор пика.

Визуальный осмотр браузера/SwiftUI и взаимодействие с системными файловыми
диалогами не проверены: Mac был заблокирован. Tk проверен на macOS,
не на Windows OS. Аппаратная и метрологическая валидация не выполнялись.

Независимое финальное ревью завершено без оставшихся замечаний.
