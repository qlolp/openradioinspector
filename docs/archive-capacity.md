# Ограничение роста архива

Срез этапа автономного узла: явный предел размера SQLite-архива, предупреждение
во всех трёх клиентах и отказ от новых измерений вместо удаления старых.

## Запуск

```bash
python3 -m radioinspector serve --host 127.0.0.1 --port 8770 \
  --session-database ./sessions.sqlite --archive-max-bytes 1073741824
```

Предел в примере — 1 GiB. `--archive-max-bytes` принимает только положительное
целое число байт и требует `--session-database`. Без ограничения сохраняется
прежнее поведение. Лимит задаётся при запуске ядра, не хранится в архиве и не
меняется через клиенты. При каждом запуске службы параметр нужно передавать
повторно, например в её конфигурации запуска.

## Что именно ограничивается

Размер — `PRAGMA page_count × PRAGMA page_size`: логический размер базы SQLite,
включая таблицы, индексы и свободные страницы. Это не размер файла на диске и не
жёсткая дисковая квота. WAL, SHM, временные файлы экспорта и резервные копии в
число не входят. Запись метаданных, событий управления и изменение состояния
сеансов остаются разрешены и могут увеличить базу сверх заданного предела.
Ограничение не гарантирует наличие свободного места на файловой системе.

Перед записью измерений ядро проверяет существующий размер. Если он уже достиг
предела, новые sweeps и observations отклоняются. Иначе запись измерений и их
событий выполняется в одной транзакции, и размер проверяется повторно перед
commit. Если новый размер превышает предел, откатывается весь пакет вместе с
событиями. Точный предел разрешён, следующая запись будет отклонена. Большой
пакет может не поместиться ещё до того, как состояние станет `full`.

Последовательность measurement-событий, последнее принятое измерение и
исходные уровни при отказе не меняются. Работающий worker может дополнительно
опубликовать отдельное служебное событие ошибки; оно не подтверждает приём
отклонённого измерения. Отсчёты S-метра не преобразуются в dBm. Все записи двух
приборных потоков проходят через одного писателя; ошибка записи видна в обычном
состоянии соответствующего worker. Автоматического удаления, ротации архива или
возобновления остановившегося worker нет.

Существующий архив, который уже больше ограничения, открывается для чтения.
Остаются доступны экспорт, просмотр и команды управления сеансом. Для
продолжения записи оператор может остановить ядро и запустить его с большим
явным пределом либо с новым архивом; старый архив не удаляется автоматически.

## API v1

`GET /api/v1/archive/capacity` — глобальный read-only маршрут, не требующий
выбранного сеанса. Ответ имеет обычную оболочку `contract`, `contract_version`,
`data`; в `data`:

| Поле | Значение |
|---|---|
| `storage_mode` | `sqlite` или `memory` |
| `database_bytes` | логический размер SQLite либо `null` |
| `max_database_bytes` | установленный предел либо `null` |
| `remaining_bytes` | неотрицательная разность предела и размера либо `null` |
| `state` | `unlimited`, `ok`, `warning`, `full` или `unavailable` |
| `warning_threshold` | `0.9` |
| `measurement_writes_blocked` | достигнут ли предел для новых измерений |
| `automatic_deletion` | всегда `false` |

При размере от 90% предела состояние — `warning`, от 100% — `full`.
Без предела — `unlimited`. Служба без SQLite-хранилища сообщает `memory` и
`unavailable`, не выдавая данные в памяти за дисковый архив. SQLite `:memory:`
по-прежнему считает свои логические страницы и сообщает `sqlite`.
Локальный путь файла в ответ не включается.

Отказ single/batch measurement POST возвращает HTTP **507** с
`error.code="archive_capacity_exceeded"`. Клиент не должен автоматически
повторять такой пакет. Поддержка объявлена как `archive_capacity_guard=true`,
автоматическое удаление — `archive_automatic_deletion=false`.

## Три клиента

Raspberry Pi WebUI, Windows GUI и macOS SwiftUI показывают глобальные размер,
предел и предупреждение независимо от выбранного сеанса. Они читают короткий
статус, не загружают для этого измерения и не изменяют лимит. Ошибка маршрута,
включая HTTP 404 старого сервера, показана отдельно и не скрывает остальные
данные. Поздние ответы предыдущего подключения не должны заменять актуальные.

## Проверка и границы

Автоматические тесты проверяют границы, совместную квоту sweeps/observations,
откат пакета и событий, конкурирующие записи, повторное открытие архива,
HTTP 507, режим без SQLite и клиентские состояния. Проверки выполняются на
синтетических данных без приборов. Аппаратная валидация и проверка нехватки
реального дискового пространства этим срезом не заявляются.

## Воспроизведение проверок

```bash
python3 -m unittest discover -s tests -t .
swift test --package-path macos/SpektrKomandy
swift test --package-path macos
xcodebuild -project macos/DvoynoyObzor.xcodeproj -scheme DvoynoyObzor \
  -configuration Debug -destination 'platform=macOS' CODE_SIGNING_ALLOWED=NO build
```

JavaScript behavior-тесты используют Node.js, если он доступен, и проверяют
таймаут при частом polling, поздний ответ, восстановление после ошибки и
независимость планировщика. Без Node соответствующие тесты явно пропускаются.
Native Swift/AppKit-проверки требуют macOS и Xcode. Подпись и установка приложения
пользователю не входят в проверку сборки.

Проверено 8 ноября 2026 на macOS arm64: API-пакет Swift — 60 XCTest,
native session/transport — 13 XCTest, полная Xcode-сборка без подписи. Живые
Safari и SwiftUI-клиент показали достигнутый предел 98 304 / 98 304 байта при
сохранённом отображении исходных dBm и s_meter_count. Tk-оболочка проверена
на Mac со всеми состояниями и HTTP 404; запуск на ОС Windows не выполнялся.

Нативная проверка также исправила прежние ошибки macOS: escaping-захват режима
перестройки, Darwin-ограничение fork в тесте, чтение httpBodyStream в URLProtocol
и NDJSON download (однократное завершение, сохранение временного файла до
возврата callback, завершающий перевод строки). Старый файл экспорта сохраняется
при некорректном, усечённом, чужом или неполном NDJSON. В WebUI восстановлен
пропущенный метод обновления TaskScheduler; тест launcher закрепляет фактический
Windows scheduler_app вместо устаревшего completion_app.

Python regression: 369 tests passed, including executable Node behavior checks.
