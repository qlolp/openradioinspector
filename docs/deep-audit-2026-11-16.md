## 4. Rust

### 4.1. Что это за слой

15 крейтов в `crates/` (310 файлов, 105 957 строк) — **кандидатная реализация,
а не замена ядра**. `Cargo.toml` помечает воркспейс явно:
`status = "candidate; Python remains the accepted default until parity and
physical gates pass"`. С Python ядром крейты **не связаны через FFI**: это
отдельные бинарники `ori-core` и `ori-supervisor`, которые упаковываются в
macOS personal RC (`tools/release/macos_rc_package.py`), и отдельные тесты
`crates/ori-core/tests`, поднимающие HTTP-поверхность кандидата.

|---|---|---|
| Строк | 51 129 | 54 828 (51,7 % тестов) |
| `#[test]` / `#[tokio::test]` | — | 746 |
| `unwrap()` | 152 | 6695 |

| I/O-вызовы под `unwrap()` | **0** | — |

Сильные стороны, измеренные, а не предположенные: в рабочем коде нет ни одного

Крейт `ori-contracts` (генерируемый) тестов не имеет — это нормально.

### 4.3. Гейты

`tools/modernization/checks.py` (шаг workflow «Run owned modernization release
checks») задаёт для всего воркспейса: `cargo fmt --check`,
`cargo clippy --workspace --all-features --all-targets -D warnings`,
`cargo test --workspace --all-features`, набор `crates/ori-core/tests`,
проверку версий `rustc`/`cargo` ровно 1.99.1 и сверку сгенерированных
контрактов. Отдельно `modern-clients.yml` гоняет `fmt`, `clippy` и `test` для
`clients/windows`. Фактический прогон на `9154cf5`: 24 job'а на
Linux x2 (x86-64 и arm64), macOS и Windows — все зелёные.

Не закрыто: порог покрытия, `cargo-deny` (аудит лицензий и advisory), fuzz для
сырого VFS, `miri` для `unsafe`-блоков.

### 4.4. Риск 1: отравление мьютекса

**90** мест `.lock().unwrap()` в рабочем коде: `ori-control` — 49
(`crates/ori-control/src/coordinator.rs`), `ori-tasks` — 14, `ori-automation` —
11, `ori-core` — 10, `ori-archive` — 6. `parking_lot` в зависимостях нет,
используется `std::sync::Mutex`.

По документации стандартной библиотеки, отравленный мьютекс означает, что
«all other threads are unable to access the data by default», а «most usage of
a mutex will simply `unwrap()` these results, **propagating panics among
threads**» ([std::sync::Mutex](https://doc.rust-lang.org/stable/std/sync/struct.Mutex.html)).
Практическое следствие: одна паника внутри критической секции `coordinator.rs`
превращает каждое последующее обращение к координатору в панику вместо
возвращаемой ошибки. Координатор управляет жизненным циклом приборов, то есть
именно там, где паника наиболее вероятна.

### 4.5. Риск 2: сырой SQLite VFS

`crates/ori-archive/src/checkpoint/vfs.rs` — собственный VFS поверх FFI SQLite:
регистрация `sqlite3_vfs_register`, разбор указателей
(`&*raw.cast::<Context>()`, `&mut *raw.cast::<File>()`), собственный метод
`open_file`. Код в боевом пути: `checkpoint/mod.rs:277` вызывает `vfs.connect(path)`
при каждой операции контрольной точки. Из 81 `unsafe` в рабочем коде **только
3** имеют комментарий `// SAFETY:` — это 78 без объяснения инварианта, хотя
lint `clippy::undocumented_unsafe_blocks` именно для этого и существует
([описание линта](https://rust-lang.github.io/rust-clippy/master/index.html#undocumented_unsafe_blocks),
группа `restriction`, по умолчанию выключен).

Покрытие при этом не нулевое: `vfs_tests.rs` содержит 4 целевых теста — короткое
чтение с обнулением остатка, отказ записи при отмене, сохранение WAL-блокировок
и неприкосновенность VFS по умолчанию. Но 4 теста на блок с сырыми указателями,
FFI и собственным файловым вводом-выводом — это мало для кода, который стоит на
пути записи архива.

### 4.6. Риск 3: гейты, которые никто не обязан выполнять

Защита ветки `main` **не применена**: `GET /branches/main/protection` отвечает
`404 Branch not protected` (токен имеет область `repo`, то есть читает
состояние защиты), наборов правил (`rulesets`) — ноль. При этом
`docs/release/main-protection.json` требует 13 обязательных контекстов, а CI
выдаёт 24 job'а. Расхождение двустороннее:

* в списке нет ни одного из четырёх job'ов `modern-*` и трёх job'ов
  `modern-clients` — то есть **весь контур Rust, Swift и браузерных клиентов**
  в список обязательных не входит;
* список требует `synthetic-*-py3.10/3.12/3.14`, а CI уже гоняет и 3.15;
* в списке нет job'а `macos-personal-rc`.

Даже если администратор применит конфигурацию как есть, Rust- и macOS-гейты
останутся рекомендательными: PR с красным `cargo test` можно будет слить.
