# Исследование возможностей RadioInspectorRT и сверка с проектом — 11 ноября 2026

Запись о разборе коммерческой программы RadioInspectorRT и сопоставлении её
возможностей с текущим состоянием OpenRadioInspector.

Состояние проекта, на котором выполнено сопоставление: ревизия `604b206`.
Состояние репозитория на момент записи: `15b700b`, `main` содержит 740 коммитов,
дерево — 622 файла, 7,7 МБ.

## 1. Вопрос исследования

Что коммерческая RadioInspectorRT умеет по документации и по первичным
артефактам, в чём наша программа на текущем состоянии уступает или превосходит
её, и что из этого определяет следующие работы.

## 3. Метод

Разбор выполнялся статически: без запуска коммерческих модулей, без обхода
защиты Guardant и без декомпиляции. Инструменты лежат в
[`tools/analysis/`](../tools/analysis/README.md): разбор дерева ресурсов PE и
бинарных форм Delphi, извлечение строк ASCII/UTF-8/UTF-16LE, выборка
идентификаторов из баз FireBird, чтение строкового пула установочного пакета
MSI, разбор справки WinHelp (B+-дерево каталога, распаковка блоков тем
HLP-LZ77, таблица фраз).

Сопоставление выполнено по 33 функциональным блокам, закрывающим обе
программы. Отдельно различались три состояния: реализовано полностью,
реализовано первым срезом (read-only, с очерченными границами), не реализовано.

## 4. Установленные факты по оригиналу

* RadioInspectorRT — специализированная версия RC для поиска источников
  излучений; собственные функции RT включают контроль средств радиоэлектронного
  подавления, в поставленных руководствах не раскрытый.
* RT управляет приборами самостоятельно, без I_MasterDevice, если не куплена
  опция удалённого управления; I_MasterDevice работает через COM, IEEE488, LAN
  и USB.
* Лицензионная модель: в поставку входит ПО, управляющее не более чем тремя
  заранее согласованными моделями средств измерений, и после поставки изменить
  модель нельзя.
* Опция DTest по состоянию на 2026 год: APCO-P25, DMR, TETRA, DECT,
  Bluetooth, 802.15.4 (ZigBee), 2G, 3G, 4G, аналоговое ТВ (PAL/SECAM/NTSC),
  DVB-T2; демодуляция речевого трафика — APCO-P25, TETRA, DMR, FM, AM.
* Аппаратная линейка «Кассандра»: ТМ9, ТМ30, С9, С30, WiFi; СО, СО6, К6, К21
  и М сняты с производства, по С6 и С30 поставки приостановлены.
* RT-Light — упрощённая версия RT, управляющая только сканирующими
  приёмниками AOR и ICOM.

## 6. Выводы

**Расхождение переместилось в глубину.** Бэклог, составленный по разбору
коммерческого пакета, закрыт десятью срезами: эталонная панорама, адаптивный
порог, табличная маска, усреднённый эталон, три горизонтальные порога, окно
N1/N2, результаты с явной методикой, встроенный частотомер, параметры DVB-T,
фонограмма с предысторией. Тринадцать блоков из 33 закрыты полностью, десять
существуют в виде первых срезов, пять не реализованы, четыре — частично.

**Мнимое расхождение — число приборов.** У вендора 36 разделов с особенностями
конкретных моделей, у нас обращение идёт через общие драйверы. Разрыв не в
совместимости, а в проверенности: quirks, требования к сети, особенности
Agilent IO Control и ограничения DTest по FSU, FSL, ETL, PR100, EM100.

**Реальные расхождения — четыре:** глубина реализации; метрология и quirks;
аппаратная приёмка (все срезы пока синтетические); закрытые цифровые
декодеры. Отдельно стоит контроль средств радиоэлектронного подавления —
заявленная RT-функция, не раскрытая в руководствах.

**Приоритеты:** довести срезы до глубины → аппаратная приёмка → реестр
особенностей подключения → методики и нормативные проверки → определение
класса аналоговых ТВ → сетевые сценарии → интерактивная карта с пеленгами.

## 7. Побочные находки в репозитории

1. **Двойная маркировка в `docs/limits.md`.** Раздел «Что не реализовано»
   перечислял десять пунктов, закрытых первыми срезами, как нереализованные,
   при том что ниже по тому же файлу они описаны как работающие. Исправлено:
   с каждого пункта стоит ссылка на документ среза.
2. **Решение по коммерческому диску выпало из дорожной карты** при её
   переписывании, хотя пункт 6 «Следующих этапов» опирается на его основания.
   Восстановлено отдельным документом.
3. **Коммерческий диск уже исключён из дерева `main`** (удаление в `8a40579`),
   но коммит `33cae7f` остаётся предком `origin/main`: файлы доступны в
   истории. Дерево уменьшилось с 169 МБ до 7,7 МБ, очистка истории — открытый
   шаг.
4. **Устаревшее утверждение в `docs/commercial-app-inventory.md`** о
   нераспакованной справке `.hlp` снято: тексты 24 файлов разобраны.

## 9. Что осталось неразрешённым

* Полная RadioInspectorRT в наличии не была: в поставке только RT-Light, часть
  сведений получена из документации 2008–2017 годов и с сайтов 2026 года.
* Публичные лицензионные условия RadioInspector не найдены — пробел, а не
  предположение; отраслевая модель условий приведена как контекст.
* Иллюстрации и перекрёстные ссылки внутри справки не извлечены: текст тем
  разобран, рисунки и контекстные идентификаторы остались за рамками.
* Таблицы MSI не декодированы, сценарий установщика не восстановлен.
* Точное число поддерживаемых моделей приборов у оригинала не подтверждено.
* Аппаратная приёмка не выполнена: 114 ошибок тестов в песочнице вызваны
  отсутствием `tkinter`, а не дефектом кода.

## 10. Воспроизведение

```bash
# формы и надписи коммерческого модуля
python3 tools/analysis/pe_resources.py --exe <InspectorRT.exe> --forms
python3 tools/analysis/strings_extract.py --exe <InspectorRT.exe> --cyrillic --grep эталон

# справка
python3 tools/analysis/hlp_reader.py <файл.hlp>

# модель данных
python3 tools/analysis/firebird_meta.py --db <TASKPLAN.ITASKDB>

# состояние проекта и сравнение
python3 -m unittest discover -s tests -t .
```

Сопоставление воспроизводится по документам `docs/rt-comparison.md` и
`docs/commercial-disk-decision.md`; числа проверяются на ревизии `604b206`.
