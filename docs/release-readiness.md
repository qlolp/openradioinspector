# Первый общий релиз: прогноз и критерии

Оценка на 8 ноября 2026 года. База — интеграционный стек PR #83; изменения
открытых PR не считаются включёнными в `main`. Цель первого релиза — один
проверенный двухприборный сценарий, а не весь функционал коммерческого аналога.

## Что должно пройти приёмку

На Raspberry Pi, Windows и macOS ядро открывает tinySA и AR-DV1, ведёт
независимые потоки, сохраняет исходные измерения и UTC в общем архиве.
Кандидат tinySA передаётся на AR-DV1 без остановки обзора. После перезапуска
архив доступен, прерванные операции отмечены явно. Windows и macOS могут
наблюдать тот же сеанс на Raspberry Pi; приборами владеет только ядро.

## Остаток до релиза

| Блок | Программная работа | Внешняя проверка / решение |
|---|---|---|
| Интеграция | Согласовать экспорт PR #79 и исправления SoapySDR PR #81 с общим стеком; повторить регрессии | Merge только по явному разрешению пользователя |
| Windows | COM transport, обработка ошибок, локальный запуск ядра, упаковка приложения и переносимые пути | Чистая Windows, реальные COM/USB, установка и удаление пакета |
| Raspberry Pi | Установка и автозапуск службы, контролируемое восстановление, диагностика диска/USB | Pi с питаемым USB-хабом, перезагрузка, длительная запись |
| macOS | Проверка UI, поставка приложения, сценарии локального и удалённого ядра | GUI-приёмка; подпись/notarization требуют учётных данных, если включены в формат поставки |
| Общая устойчивость | Полный CI на ОС, одновременные клиенты, явные ошибки и восстановление; проверка очереди и тайм-аутов | Двухприборный стенд, отключения USB, нехватка места, перезапуски и длительная запись |
| Выпуск | Воспроизводимые пакеты, руководство оператора, список подтверждённых устройств и ограничений | Решение о содержимом поставки и материалах сторонних правообладателей; публикация релиза отдельно |

Отдельный незакрытый риск — кодовые возможности не равны проверенному
профилю прибора. Аудио, цифровые режимы и IQ нельзя объявлять поддержанными
без подтверждения конкретного тракта. Первую приёмку следует ограничить
описанными FM/AM и спектральными сценариями; дополнительные возможности
принимаются отдельно.

## Прогноз

Ориентир — **4–8 инженерных недель** до первого общего релиза при доступных
трёх ОС и двухприборном стенде. Это оценка объёма работ, не обещание календарной
даты и не прогноз скорости агента. Уверенность низкая до первых аппаратных
испытаний: USB/прошивки и сборка Windows могут изменить объём существенно.

Примерное распределение: 1–2 недели на интеграцию и регрессии, 1–2 на
поставку/автозапуск, 2–4 на аппаратную приёмку и исправления. Работы частично
пересекаются; ожидание доступа, подписей и пользовательских решений сюда
не включено. Полная специализированная дорожная карта этапов 4–5 — отдельный
объём, для неё эта оценка неприменима.

Агент продолжает доступные программные срезы без организационных согласований.
Аппаратные проверки, недоступные credentials и разрешение merge/publish
не подменяются синтетическими тестами. На каждом срезе обновляются фактические
результаты в `roadmap-progress.md`, документация контракта и PR.
