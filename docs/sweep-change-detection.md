# Обнаружение изменений по усреднённому эталону

Ядро может выделить непрерывные области, где target архивного сравнения
превышает усреднённый эталон на заданную величину. Анализ использует
равновзвешенное среднее линейной мощности из
[усреднённого эталона](averaged-sweep-reference.md); вычисление и обнаружение
выполняются только ядром. WebUI, Windows Tk и macOS SwiftUI показывают
результат по явному действию оператора.

Это read-only поиск изменений, а не новый режим автоматического обнаружения
кандидатов. Он не создаёт кандидатов, исследования, события или измерения,
не меняет настройки политики, архив или каталог эталонов и не отправляет
команды приборам. Обнаруженный прирост не является классификацией сигнала,
точным измерением полосы, оценкой вероятности обнаружения или метрологическим
заключением.

## Правило областей

Для каждой точки используется уже рассчитанная разность
`target_dbm − mean_reference_dbm`. Область включает максимальную
непрерывную последовательность соседних по индексу точек, для которых
`delta_db >= minimum_increase_db`. Равенство порогу включается. Затем области
короче `minimum_bins` удаляются.

Соседство определяется порядком bins в исходном свипе, а не равномерностью
частотного шага. Повторяющиеся частоты остаются отдельными точками. Для каждой
области возвращаются включительные индексы и частоты начала/конца, индекс и
частота пика, пиковый прирост и число bins. При равных пиках выбирается первый
bin. Падения ниже эталона не выделяются этим режимом.

Параметры:

- `minimum_increase_db`: конечное число от 0 до 120 dB включительно;
- `minimum_bins`: целое число от 1 до 16 384 включительно.

Порог 0 dB намеренно включает нулевые и положительные изменения. Значение по
умолчанию интерфейсов — 6 dB, ширина — 2 точки; это пользовательские
настройки, не нормативные пороги.

## API

```text
POST /api/v1/sessions/{session_id}/sweep-average-change-detection
```

Тело содержит ровно четыре поля:

```json
{
  "reference_ids": ["reference-1", "reference-2"],
  "target_id": "target-3",
  "minimum_increase_db": 6,
  "minimum_bins": 2
}
```

Идентификаторы и совместимость источников подчиняются контракту усреднённого
эталона. Запрос ограничен 8192 байтами; query string не допускается. Ответ
содержит `data.comparison` с обычным сравнением и `data.detection`:

```json
{
  "minimum_increase_db": 6.0,
  "minimum_bins": 2,
  "regions": [
    {
      "start_index": 12,
      "end_index": 14,
      "start_frequency_hz": 101200000,
      "end_frequency_hz": 101400000,
      "peak_index": 13,
      "peak_frequency_hz": 101300000,
      "peak_increase_db": 9.5,
      "bin_count": 3
    }
  ],
  "count": 1
}
```

Ошибки: `400 invalid_request` для параметров/framing, `404` для отсутствующего
сеанса или свипа, `409 average_reference_incompatible` для несовместимых
источников. Возможность объявляется как
`features.averaged_sweep_change_detection`. Ответные клиенты ограничивают
размер JSON тем же пределом 2 000 000 байт, что и сравнение.

## Клиенты и жизненный цикл

Клиент локально закрепляет те же 2–16 исходных свипов и отдельную цель, что и
при сравнении. Оператор задаёт минимальный прирост и число точек; запрос
отправляется по кнопке. В ответе сохраняется полный результат сравнения,
а области показываются списком и выделяются на графике разности. Изменение
параметров инвалидирует ожидающий запрос и прежний результат, но не
перезаписывает исходные свипы. Смена сервера, сеанса или потока снимает
закрепление. Обновления polling/SSE не запускают повторный анализ.

## Воспроизводимая проверка

```bash
python -m unittest tests.test_sweep_average_detection tests.test_windows_sweep_average
python -m unittest tests.test_webui_sweep_average
swift test --package-path macos/SpektrKomandy
swift test --package-path macos
```

Тестовые данные синтетические; проверка не требует доступа к пользовательским
архивам и физическим приборам.
