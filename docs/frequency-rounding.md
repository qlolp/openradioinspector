# Таблица округления частот кандидатов

Read-only расчёт общего ядра по переносимому профилю. Исходная частота кандидата
сохраняется, производная показывается отдельно в трёх клиентах. Нет записи
в архив, изменения кандидата, настройки receiver, автоматического применения
к handoff, калибровки частотомера или проверки законности использования частоты.
Это срез пункта 5 функционального бэклога. Поиск изменений PR #75 не дублируется.

## Профиль

Строгий JSON UTF-8, максимум 65 536 байт. Точные поля:

```json
{"format":"openradioinspector-frequency-rounding","format_version":1,
 "name":"Пример, не норматив","frequency_unit":"Hz","method":"nearest_grid",
 "tie_break":"lower","rules":[{"start_frequency_hz":100000000,
 "end_frequency_hz":110000000,"step_hz":100000,"origin_frequency_hz":0,
 "max_offset_hz":30000}]}
```

От 1 до 128 правил в порядке диапазонов. Все пять значений каждого правила
являются целыми JSON числами 0…9 007 199 254 740 991, step_hz не меньше 1,
start не больше end. Строки, boolean, дроби, повторные поля и неизвестные поля
отклоняются. Имя нормализуется NFC и обрезается по краям; Unicode C* запрещены
до обрезки, длина нормализованного имени 1…80 code points.

Диапазоны включают обе границы, не пересекаются; следующий start строго больше
предыдущего end. Каждое правило должно содержать хотя бы одну частоту сетки
origin + k × step, где k любое целое, в том числе отрицательное. Origin может
лежать за пределами диапазона. Профиль не является таблицей разрешённых частот.

## Метод

Для исходной частоты выбирается единственное правило, чей диапазон включает её.
Внутри этого диапазона ищется ближайшая частота сетки. При равных расстояниях
выбирается меньшая. У края диапазона берётся ближайшая допустимая точка, даже
если точка продолженной сетки за диапазоном была бы ближе. Всё считается целыми
числами, без floating-point округления, интерполяции или накопления поправок.

Offset = nearest − original в целых Hz. Если |offset| больше max_offset_hz,
ближайшая точка показывается, но результат округления не принимается. Равенство
допуску разрешено. Исходное совпадение с сеткой имеет offset 0. Вне всех
диапазонов нет экстраполяции или выбора соседнего правила.

Единицы исходного уровня не участвуют в расчёте: dBm и s_meter_count остаются
исходными и не смешиваются. Уровни в ответ не включаются. Результат не меняет
частоту кандидата и не становится заданием на перенастройку прибора.

## API

POST /api/v1/sessions/{session_id}/candidate-frequency-rounding

Точное тело: {candidate_id, profile_json}, где profile_json строка сырого JSON.
ID непустой, точный UTF-8, до 128 Unicode code points; без нормализации. Нового
ограничения длины session/stream ID нет. Проверка пустоты ID и единиц совпадает
с Python str.strip: U+FEFF и U+200B не считаются пробелами и сохраняются точно.
Для имени профиля они по-прежнему запрещены как Unicode C*. URL-параметры, в том числе пустой ?,
запрещены. Строгий Content-Length без Transfer-Encoding, предел тела
524 288 байт до чтения. Повторные ключи и некорректный UTF-8 отклоняются.

Обычная оболочка contract / contract_version / data, поля data:

- session_id;
- candidate: id, source_stream_id, interval (started_at/ended_at UTC),
  center_frequency_hz, level_unit;
- profile: проверенный канонический профиль;
- frequency_unit: Hz, method: nearest_grid, tie_break: lower;
- result: status, rule_index, nearest_frequency_hz, offset_hz,
  rounded_frequency_hz.

rule_index нулевой. Статусы:

- rounded: nearest и rounded совпадают, offset ненулевой и в допуске;
- unchanged: nearest и rounded равны исходной частоте, offset 0;
- outside_tolerance: rule_index/nearest/offset заполнены, rounded null;
- outside_ranges: все четыре числовых поля null.

Снимок candidate намеренно содержит только неизменяемые поля происхождения
частоты. Mutable state, score, наблюдения и уровень не участвуют; смена состояния
кандидата во время запроса не меняет частотный расчёт. Исходная частота 1…MAX_SAFE
Hz. Область и полное происхождение этого подмножества фиксируются клиентом.

400 invalid_request: профиль, тело, ID или framing; 404 session_not_found /
candidate_not_found: отсутствующий точный источник (чужая запись не раскрывается);
409 frequency_rounding_incompatible: неподходящий источник; 413 request_too_large:
предел HTTP-тела. Capability features.candidate_frequency_rounding.

Ни одной миграции, события или записи нет. Schema остаётся v3, чтение работает
при заполненном архиве. Конкурентные изменения состояния не подменяют источник.

## Клиенты

Панель выбирает кандидата из текущего сеанса, независимо от выбранного
спектрального потока. Профиль редактируется как сырой текст, импортируется из
UTF-8 файла и явно отправляется ядру. Начальный пример из
[frequency-rounding-profile.json](examples/frequency-rounding-profile.json)
не является нормативом или рекомендованной сеткой для какого-либо прибора.

Полный выбранный источник сохраняется через polling, даже вне текущей страницы;
запрос фиксирует его частотное происхождение и текст профиля. Отдельно показаны
исходная частота, ближайшая точка, подписанное отклонение, допуск и статус.
Экспортируется только канонический профиль последнего успешно проверенного
ответа, не сырой черновик и не кандидат. Изменение текста, выбор источника,
очистка, смена области, разрыв связи или закрытие отменяют ожидающие операции
и лишают старый результат права на экспорт. Нет автоматических запросов.

Ответы всех статусов ограничены 2 000 000 байтами до декодирования, принимается
только 200. Тайм-аут WebUI/Windows 8 секунд, macOS 6 секунд. Повторные клики
не создают очереди. Импорт, анализ и сохранение защищены от поздних результатов.
Windows urllib не прерывается мгновенно; устаревший ответ игнорируется.

Визуальная проверка и системные файловые диалоги, Windows OS и оборудование
не проверяются автоматически. Синтетические тесты не заменяют их.

## Воспроизводимая синтетическая проверка

```sh
python -m tests.frequency_rounding_smoke_server --port 56040
```

Сервер создаёт только собственную временную SQLite, путь к пользовательскому
архиву не принимает. Он заранее создаёт два сеанса, исходные sweeps, S-meter
наблюдения, именованный эталон и кандидатов. Затем API используется только для
чтения. Полный логический dump до/после проверяется при остановке Ctrl-C.

Сеанс rounding-one и профиль из docs/examples/frequency-rounding-profile.json:

| ID | Исходная Hz | Ближайшая Hz | Offset Hz | Статус |
|---|---:|---:|---:|---|
| one-rounded | 103025123 | 103000000 | -25123 | rounded |
| one-unchanged | 103000000 | 103000000 | 0 | unchanged |
| one-tolerance | 103050000 | 103000000 | -50000 | outside_tolerance |
| one-outside | 120000000 | null | null | outside_ranges |
| one-receiver | 145506250 | 145500000 | -6250 | rounded |
| one-upper | 103075000 | 103100000 | 25000 | rounded |

Для outside_tolerance rounded_frequency_hz = null, хотя ближайшая частота
известна. Вторая строка профиля показывает выбор меньшей точки при равенстве
расстояний и равенство отклонения допуску. Receiver сохраняет s_meter_count;
его уровень 37 не участвует в частотном расчёте. У всех кандидатов UTC
2026-11-08T12:00:00.000001Z…12:00:01.000002Z. Отдельный rounding-two
проверяет изоляцию области сеанса.

Включение живой проверки: ORI_ROUNDING_SMOKE_BASE_URL=http://127.0.0.1:56040.
Node нужен в PATH для исполняемых WebUI-тестов. Дополнительно
ORI_ROUNDING_TK_SMOKE=1 включает тест собственного скрытого Tk-окна.
Windows GUI проверяется на этом окне и синтетическом HTTP, а не на Windows OS.
Полные регрессии: `python -m unittest discover -s tests -t .`,
`swift test --package-path macos/SpektrKomandy`, `swift test --package-path macos`.
HTTP-тесты прежних срезов требуют их собственных synthetic fixtures и env.
