# Воспроизводимая проверка релиза без приборов

Runner объединяет проверку общего ядра, Raspberry Pi WebUI, Windows Tk и
macOS SwiftUI в одном изолированном запуске. Он не запускает рабочий сеанс,
не ищет подключённые приборы и не принимает путь к пользовательскому архиву.

## Подготовка

Из корня checkout установите Python 3.12, зависимости проекта и Node 24.
Для Tk нужен доступный desktop; Linux CI использует Xvfb.

```sh
python -m pip install '.[serial]'
python -m tests.run_release_checks
```

На macOS с Xcode:

```sh
python -m tests.run_release_checks --swift
```

С `--swift` дополнительно выполняются оба Swift package test suites и
unsigned Xcode build. Приложение не запускается. Runner рассчитан на исходный
checkout, а не на установленный wheel без каталога tests.

Отсутствующие Node, NumPy, pySerial или Tk являются ошибкой подготовки,
а не основанием для зелёного прогона с пропусками. Это не установка драйверов,
службы, GUI-пакета или аппаратная приёмка.

## Собственные fixtures и жизненный цикл

Runner поднимает семь HTTP fixtures: адаптивный порог, маску, усреднение,
обнаружение изменений, три порога, архивное окно и округление частоты.
Каждый использует отдельный временный SQLite и свободный порт loopback.
Дочерние Python/Tk процессы получают собственные TMPDIR/TMP/TEMP и пустой
HOME, чтобы не загружать пользовательские Tk-профили или старые временные
TaskBook. В окружение тестов передаются фактически выделенные URL, поэтому
вручную запускать серверы или назначать фиксированные порты не требуется.

Каждый fixture печатает SHA-256 полного логического dump до чтения и после
закрытия всех сервисов. Успех требует реального совпадения, успешного
завершения процессов и очистки собственных ресурсов. Проверка не ограничена
числом строк или размером файла.

Остановка передаётся только через закрытие приватного stdin pipe дочернего
процесса. Публичного HTTP shutdown endpoint нет. Runner следит только за
созданными им процессами, не ищет и не завершает чужие серверы. При ошибке,
тайм-ауте или прерывании он выполняет cleanup; принудительное завершение
собственного зависшего процесса не считается доказательством неизменности
архива. Контроль охватывает собственные группы процессов/Windows jobs и
явно зарегистрированные вложенные Python helpers. HTTP-fixture Swift имеет
отдельную stdin lifeline. Это не общий надзор за любыми detached-процессами
или системными build services Xcode; чужие службы не завершаются.

Отдельные fixture-модули сохраняют ручной запуск и Ctrl-C. Параметры
`--port 0 --shutdown-stdin` предназначены для автоматического владельца
процесса. stdin EOF не заменяет подтверждение результата в финальном JSON.

## Пропуски и CI

Workflow в `.github/workflows/windows-core.yml` проверяет точный head PR,
а не неявный результат объединения веток. Он использует закреплённые SHA
официальных actions, read-only repository permissions и не сохраняет Git
credentials. Матрица включает Linux, Windows и macOS.

На POSIX ожидается полный Python/Node/Tk набор без пропусков. На Windows
допустимы только явно перечисленные тесты POSIX PTY и permission bits.
Пропущенный live HTTP/Tk сценарий или отсутствующая зависимость приводят к
ошибке проверки. На macOS также проверяется отсутствие пропусков Swift.

Полный успешный CI подтверждает синтетические программные сценарии конкретного
коммита. Он не доказывает работу native COM/USB, реального tinySA/AR-DV1,
отключения питания, калибровки, метрологическую точность или пригодность к
длительной автономной записи. Внешний вид и системные диалоги требуют отдельной
ручной проверки. macOS CI не означает проверку на Raspberry Pi ARM.

## Проверенная база

PR #87, `2afba069263785e7dbdc79f8d26c8b99a7532bc6`, уже прошёл
[Windows CI](https://github.com/qlolp/openradioinspector/actions/runs/42479617643):
981 тест, 952 прошли и 29 пропущены. Из них 21 относятся к POSIX,
8 к opt-in HTTP/Tk fixtures. Новый runner предназначен для устранения этих
восьми пропусков и воспроизводимости полного клиентского прогона.
Результаты нового workflow фиксируются отдельно после выполнения.


## Локальная проверка нового runner

Единая команда `python -m tests.run_release_checks --swift` прошла на Mac:
1026 Python/Node/Tk, 164 Swift SDK и 108 native тестов без пропусков;
unsigned Xcode BUILD SUCCEEDED. Локальный Node — 22.22.3, CI использует 24.
Семь полных логических SHA-256 совпали, все собственные серверы остановлены
и корневой временный каталог удалён. Независимый review не оставил блокеров
изоляции/жизненного цикла; реальные Linux/Windows/macOS CI проверяются после
публикации точного коммита.

В полном прогоне воспроизвелись 39 известных Tcl teardown сообщений
`invalid command name ..._drain_messages`. Они не скрыты и не объявлены
исправленными: владение таймерами WindowsApp — следующий отдельный дефект.
Зелёные unittest assertions не означают отсутствие этих предупреждений
или готовность всего продукта к релизу.
