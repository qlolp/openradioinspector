# Воспроизводимая проверка релиза без приборов

Runner объединяет проверку общего ядра, Raspberry Pi WebUI, Windows Tk и
macOS SwiftUI в одном изолированном запуске. Он не запускает рабочий сеанс,
не ищет подключённые приборы и не принимает путь к пользовательскому архиву.

## Подготовка

Из корня checkout установите Python 3.12, зависимости проекта и Node 24.
Для Tk нужен доступный desktop; Linux CI использует Xvfb.

```sh
python -m pip install '.[serial]'
python -m tests.run_release_checks
```

На macOS с Xcode:

```sh
python -m tests.run_release_checks --swift
```

С `--swift` дополнительно выполняются оба Swift package test suites и
unsigned Xcode build. Приложение не запускается. Runner рассчитан на исходный
checkout, а не на установленный wheel без каталога tests.

Отсутствующие Node, NumPy, pySerial или Tk являются ошибкой подготовки,
а не основанием для зелёного прогона с пропусками. Это не установка драйверов,
службы, GUI-пакета или аппаратная приёмка.

## Собственные fixtures и жизненный цикл

Runner поднимает семь HTTP fixtures: адаптивный порог, маску, усреднение,
обнаружение изменений, три порога, архивное окно и округление частоты.
Каждый использует отдельный временный SQLite и свободный порт loopback.
Дочерние Python/Tk процессы получают собственные TMPDIR/TMP/TEMP и пустой
HOME, чтобы не загружать пользовательские Tk-профили или старые временные
TaskBook. В окружение тестов передаются фактически выделенные URL, поэтому
вручную запускать серверы или назначать фиксированные порты не требуется.

Каждый fixture печатает SHA-256 полного логического dump до чтения и после
закрытия всех сервисов. Успех требует реального совпадения, успешного
завершения процессов и очистки собственных ресурсов. Проверка не ограничена
числом строк или размером файла.

Остановка передаётся только через закрытие приватного stdin pipe дочернего
процесса. Публичного HTTP shutdown endpoint нет. Runner следит только за
созданными им процессами, не ищет и не завершает чужие серверы. При ошибке,
тайм-ауте или прерывании он выполняет cleanup; принудительное завершение
собственного зависшего процесса не считается доказательством неизменности
архива. Контроль охватывает собственные группы процессов/Windows jobs и
явно зарегистрированные вложенные Python helpers. HTTP-fixture Swift имеет
отдельную stdin lifeline. Это не общий надзор за любыми detached-процессами
или системными build services Xcode; чужие службы не завершаются.

Отдельные fixture-модули сохраняют ручной запуск и Ctrl-C. Параметры
`--port 0 --shutdown-stdin` предназначены для автоматического владельца
процесса. stdin EOF не заменяет подтверждение результата в финальном JSON.

## Пропуски и CI

Workflow в `.github/workflows/windows-core.yml` проверяет точный head PR,
а не неявный результат объединения веток. Он использует закреплённые SHA
официальных actions, read-only repository permissions и не сохраняет Git
credentials. Матрица включает Linux, Windows и macOS.

На POSIX ожидается полный Python/Node/Tk набор без пропусков. На Windows
допустимы только явно перечисленные тесты POSIX PTY и permission bits.
Пропущенный live HTTP/Tk сценарий или отсутствующая зависимость приводят к
ошибке проверки. На macOS также проверяется отсутствие пропусков Swift.

Полный успешный CI подтверждает синтетические программные сценарии конкретного
коммита. Он не доказывает работу native COM/USB, реального tinySA/AR-DV1,
отключения питания, калибровки, метрологическую точность или пригодность к
длительной автономной записи. Внешний вид и системные диалоги требуют отдельной
ручной проверки. macOS CI не означает проверку на Raspberry Pi ARM.

## Hosted macOS: обратный DNS loopback

Первый CI 42482443812 прошёл на Linux (1026/0 skips) и Windows
(1026, 21 POSIX skips), но hosted macOS не дождался первого fixture.
Стандартный HTTPServer вызывает getfqdn перед ready. Известная
[проблема hosted macOS 15/26](https://github.com/actions/setup-python/issues/1223)
может задерживать этот обратный lookup более чем на 30 секунд.

Синтетические fixtures и отдельный процесс unittest теперь используют
scoped helper только для точных numeric loopback `127.0.0.1` и `::1`.
Остальные имена, включая `localhost`, передаются исходному resolver вместе
с его ошибками. Вложенные контексты и исключения восстанавливают resolver.
Собственный Swift HTTP fixture задаёт информационное имя после numeric bind
без обратного DNS. Производственные DNS/bind, deadlines и assertions
не изменены. Успех новой hosted macOS проверки должен подтверждаться CI,
а не выводиться только из совпадения с внешним issue.


## Повторный CI и диагностика зависаний

[CI 42483687163](https://github.com/qlolp/openradioinspector/actions/runs/42483687163)
на `1107381` прошёл Linux (1031 тест, без пропусков) и Windows
(1031 тест: 1010 прошли, 21 допустимый POSIX skip). Hosted macOS успешно
поднял все семь fixtures, затем достиг 600-секундного ограничения Python
набора. Последним начатым был
`AverageActualTkHTTPTests.test_hidden_live_detection_regions_and_parameter_traces`.
Все семь серверов штатно остановились, полные логические SHA-256 совпали.

Лог содержал 39 сообщений `_drain_messages` и 23 `_poll` после уничтожения
Tk-окон. Это подтверждённый отдельный дефект владения таймерами; его
причинная связь с зависанием ещё не установлена. Буферизованный лог без
стека не позволяет отличить заблокированный `root.update()` от другой
операции или накопленной задержки. Следующая проверка добавляет диагностику
точного теста, времени выполнения, версий Python/Tcl/Tk и стеков потоков.
Периодический faulthandler dump — только диагностический снимок, не отдельный
провал теста; окончательный результат по-прежнему определяется assertions,
кодом выхода, проверкой пропусков и общим deadline.
Тайм-ауты, assertions и правила пропусков не ослабляются, фоновые Tcl-ошибки
не подавляются. До успешного полного hosted macOS прогона CI остаётся
незавершённой проверкой, а не зелёным релизным критерием.


## Изоляция actual-Tk случаев на macOS

В hosted прогонах PR #99, #100 и #101 (Python 3.12.10, Tk 8.6.16,
Aqua) стек фиксирует зависание `tkinter.update` в
`AverageActualTkHTTPTests.test_hidden_live_detection_regions_and_parameter_traces`
до общего deadline 600 секунд. Сообщений stale Tcl/Tcl_AsyncDelete в этих
прогонах нет. Это не доказывает причину зависания; успешный локальный Tk 9
не заменяет проверку hosted Tk 8.6.

Узкая идея изоляции перенесена из
[PR #96, точный источник 1b8b810](https://github.com/qlolp/openradioinspector/blob/1b8b810a6141322d1e89a1d6c881f4ce7477961c/tests/run_release_checks.py#L142-L198),
с усиленной проверкой отчётов и диагностикой. Остальной PR #96 не интегрирован.
На macOS пять перечисленных в `MACOS_TK_CLASSES` классов выполняются по одному
исходному случаю в свежем Python, с deadline 90 секунд. На других платформах
это можно проверить через `ORI_RELEASE_ISOLATE_TK=1`. Остальные тесты, включая
специальную последовательность lifecycle → worker GC → HTTP и несколько Tk
roots внутри одного случая, остаются без изменений. Это инфраструктура тестов,
а не замена производственного исправления lifecycle.

Дочерний процесс наследует приватные HOME/temp и URL собственных fixtures,
остаётся в группе/job внешнего runner и не запускает повторный discovery.
Сохраняются исходные ID и количество случаев. Успех требует ровно одного
запрошенного случая, корректного отчёта и нулевого exit status. Ошибка,
тайм-аут, отсутствующий/повреждённый отчёт или nonzero exit не превращаются
в pass/skip. Правила допустимых skips не расширены. Каждый дочерний процесс
пишет границы теста и периодический faulthandler stack; его stdout/stderr сразу направлены в общий file-backed журнал внешнего runner,
поэтому сохраняются и при внешнем timeout без ожидания дочернего finally.
Общий deadline 600 секунд и assertions не изменены. Подтверждение исправления
hosted macOS требует полного CI точного нового commit.

Локальная узкая проверка: `python -m unittest tests.test_release_checks -v`
прошла (45 тестов, без пропусков). Три случая `AverageActualTkHTTPTests`
дополнительно прошли каждый в отдельном Python с двумя собственными HTTP
fixtures (Python 3.12.15 / Tk 9.0.4); оба полных SHA-256 совпали после остановки,
приватный корневой каталог удалён. Это не полный release/Swift прогон и не
проверка hosted Tk 8.6.16 или оборудования.


Локальная полная проверка этого среза: **1087 Python/Node/Tk**, включая
29 изолированных actual-Tk случаев, **170 Swift SDK** и **113 native Swift**,
без пропусков; unsigned Xcode **BUILD SUCCEEDED**. Python 3.12.15,
Tcl/Tk 9.0.4. Семь временных архивов сохранили полные логические хеши,
собственные серверы остановлены, временный корень удалён. Stale Tcl и
Tcl_AsyncDelete сообщений нет; два нефатальных loopback ConnectionResetError
и прежние build warnings остаются в журнале. Отдельно прошли 45 harness
тестов и три focused actual-Tk случая. Независимое ревью не оставило
подтверждённых замечаний. Hosted Tk 8.6.16 пока не объявляется проверенным
на новом коммите.


## Hosted Swift SDK: явный deployment target

[CI 42499338572](https://github.com/qlolp/openradioinspector/actions/runs/42499338572)
на `9595b6c` прошёл Python/Node/Tk gate на всех трёх ОС (1087 случаев на
каждой), включая прежний зависавший actual-Tk случай на hosted macOS
с Tk 8.6.16. Затем компиляция Swift SDK остановилась на availability errors
для `Task`, `checkCancellation` и `JSONEncoder.OutputFormatting.withoutEscapingSlashes`.
Swift SDK tests, native Swift tests и Xcode build в этом hosted прогоне
не выполнялись.

SDK теперь явно задаёт `platforms: [.macOS(.v14)]`, как существующий native
пакет `macos/Package.swift` и все четыре `MACOSX_DEPLOYMENT_TARGET = 14.0`
в Xcode-проекте. Перенесена только эта строка из
[PR #96, точный источник 78130ac](https://github.com/qlolp/openradioinspector/blob/78130acb67b593b031ba81cf96d27c13b4e2b1e5/macos/SpektrKomandy/Package.swift).
Это согласование поддерживаемого минимума macOS 14, а не заявление поддержки
macOS 10.15. Декларация macOS minimum не исключает сборку SDK на Linux.
Ранее явный target SDK отсутствовал; успешная локальная сборка не подтверждала
переносимость неявного deployment target на hosted toolchain. Причина различия
локального и hosted поведения отдельно не установлена. Исправление target
ещё требует нового полного hosted прогона; предыдущий локальный успех
не является его проверкой.


После добавления явного target повторно прошёл полный локальный gate:
1087 Python/Node/Tk, 170 Swift SDK, 113 native Swift, без skips, unsigned
Xcode BUILD SUCCEEDED. Все семь fixture-хешей совпали, собственные серверы
остановлены и временный корень удалён. Stale Tcl/Tcl_AsyncDelete нет,
два нефатальных loopback ConnectionResetError сохранены в журнале.
`swift package dump-package` подтвердил platform macos 14.0. Новый hosted
результат должен подтверждаться отдельно на опубликованном коммите.
