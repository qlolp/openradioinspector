## Проверка #116

Проверенный код: `0b19e641cdcfe53119c1aafa8e9ce08fc54c400d`, поверх
обновлённого #115. Полный локальный Linux/Python 3.12 release runner —
**1438 тестов, 0 skips**; все семь архивов неизменны, серверы остановлены.
Независимое ревью проверило lifecycle и экспорт, Python/Node тесты, контракт
реального HTTP и регистрацию Swift sources. Нативная сборка остаётся воротами CI.

Сохраняется точный JSON объекта данных, включая вложенные ключи и большое
целое 9007199254740993, без повторного кодирования через модель UI. Смена
контекста и порога отбрасывает поздние ответы и ожидающее сохранение;
отмена диалога не создаёт файл. Общая синтетическая фикстура сохранена в
`tests/fixtures/sweep-occupancy-v1.json` и проверяется тремя клиентами.
Из инструкции этого среза также удалена команда bare native Swift test,
которая могла автоматически запустить физический tinySA smoke.

Порядок слияний — #115 → #116. Их проверки можно выполнять параллельно на
согласованной истории, но перед каждым merge заново сверяются актуальный
`main`, голова PR, обсуждения и совпадение результата с проверенным деревом.
В этом срезе CSV, импорт артефакта в UI и аппаратная/визуальная приёмка не заявляются.

В Windows/Python 3.12 job `128976392029` на голове `49750b18` старый тест
`AverageChangeDetectionHTTPTests.test_http_result_is_read_only_and_advertised`
получил WinError 10053 при GET capabilities. Его helper неявно отправлял тело
POST-анализа вместе с GET; сервер не читает это тело и закрывает HTTP/1.0
соединение. Такое закрытие может приводить к TCP reset на Windows.
Helper исправлен: обычный GET не имеет тела, явные payload/raw и прежний POST
сохранены. Assertions, тайм-ауты и production HTTP-код не менялись; повторная
проверка Windows требуется на новой голове. Это не объявляется доказательством
устранения всех возможных транспортных сбоев.

## Проверка #117

Начальная голова — `dc20e88020ec7266d92afa1d4cb65051325ca52d`, два новых
коммита поверх #116. Добавлено обычное слияние исправления GET из `dfd1a1a6`;
чужая история сохранена. Независимое ревью и восемь новых тестов не выявили
блокирующих ошибок. Экспорт заново вычисляет контекст и статистику общим
ядром, сохраняет повторяющиеся bins и SHA-256 исходного JSON, ограничивает
размеры входа и CSV и атомарно отказывает в замене существующего файла.
Идентификаторы кодируются JSON внутри CSV-ячеек.

Полный Linux/Python 3.12 runner на объединённом коде `6fa4f659` выполнил
**1446 тестов, 0 skips**; семь временных архивов неизменны, серверы остановлены.
Этот запуск включает исправление HTTP-фикстуры #116, восемь тестов CSV,
реальные HTTP-обработчики, Node и Tk. Hosted-проверки требуются на новой голове.

Аппаратный сценарий требует явного запуска и `--port`, не входит в discovery
и использует штатный receive-only worker. Он не запускался в этом Linux-аудите.
Сообщённая в исходном PR попытка на macOS остановилась на открытии USB-порта;
новых аппаратных измерений и PASS нет. Следующий шаг на стенде — запуск
документированной команды из среды с доступом к USB, сохранение SQLite,
точного JSON и CSV, затем отдельная калибровочная и восьмичасовая приёмка.

## Продолжение после уборки

Сохраняется порядок [основной ревизии](repository-audit.md): сначала завершение
runner и воспроизводимость lifecycle, затем масштаб архивов, длительный прогон,
чистые установки и аппаратная приёмка. Для startup-теста выше следующий шаг —
воспроизвести задержанный старт и отделить готовность фикстуры от измеряемого
тайм-аута очистки; проверки остановки потомков и сохранности соседнего процесса
не ослаблять. CLI CSV из #117 остаётся офлайн-сводкой; импорт и CSV-кнопки
в клиентах, маркеры и другие расширения идут после этих проверок.

Приватный bundle создан вне репозитория и проверен восстановлением, `fsck`
и SHA-256. Перед удалением каждой серверной ветки повторно проверяются её голова,
включение в `main` и отсутствие зависимости открытого PR.
