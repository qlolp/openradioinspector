## 3. Проверки

Свежий прогон полного набора на `9154cf5` в песочнице:

```
Ran 2303 tests in 170.154s
FAILED (failures=1, errors=124, skipped=34)
```

Причины падений разобраны по отдельности:

* **124 ошибки** — `ModuleNotFoundError: No module named 'tkinter'` и
  производные от него (`ImportError`, `ReleaseCheckError` в подпроцессе
  владения интерпретатором). В песочнице нет `tkinter`; на машине с
  графической сессией эти тесты проходят.
* **1 падение** — `tests/test_ci_headless_bootstrap.py`:
  `AssertionError: 'python3-tk' unexpectedly found in ('python3-tk', 'xauth',
  'xvfb')`. Проверка `tools/ci/headless_bootstrap.py::probe_headless`
  запускает `import tkinter` и ищет `xvfb-run`, `Xvfb`, `xauth`; отсутствие
  любого из них она честно сообщает как проблему. Тест ожидает, что
  headless-зависимости уже установлены (в CI их ставит bootstrap), а в образе
  песочницы нет ни модуля `tkinter`, ни `xvfb`, ни `xauth`. Тест рассчитан на
  образ с headless-окружением; это свойство образа, а не дефект кода.

Регрессий в коде прогон не выявил; все падения объяснены окружением.

Статический анализ (`tools/audit/code_checks.py`, 12 правил) на `9154cf5`:
**109 находок** — 68 `COMPLEXITY`, 24 `SWALLOW-EXC`, 8 `LONG-FUNC`,
5 `DYNAMIC-CODE` (ложные срабатывания на `re.compile`), 4 `ASSERT-IN-PROD`.
Число находок выросло со 91 на `bb223cb`: код стал больше. Из четырёх
`ASSERT-IN-PROD` три исправлены в PR #172, одно (`archive_stream.py:271`)
осталось открытым до разрешения конфликта.

## 5. CI и покрытие сборок

Четыре workflow: `desktop-packages.yml`, `modern-clients.yml`,
`modern-core.yml`, `windows-core.yml`.

**Крейты Rust собираются и тестируются в CI — через индирекцию, а не напрямую.**
`cargo fmt`, `cargo clippy` и `cargo test` вызываются только с `--manifest-path
clients/windows/Cargo.toml` — это отдельный воркспейс, исключённый из
корневого (`exclude = ["clients/windows"]`). Для корневого воркспейса `crates/*`
в файлах workflow прямых вызовов `cargo` нет, и по grep по YAML это выглядит
как отсутствие гейтов. Гейты есть, но спрятаны за шагом workflow
«Run owned modernization release checks»: он вызывает
`tests/run_release_checks --modern`, а тот — `tools/modernization/checks.py`,
где заданы:

* `cargo fmt --all -- --check`;
* `cargo clippy --workspace --all-features --all-targets --locked --offline -D warnings`;
* `cargo test --workspace --all-features --locked --offline`;
* набор `crates/ori-core/tests` (HTTP-поверхность кандидата);
* проверки версий `rustc`/`cargo` ровно 1.99.1.

Шаг отработал успешно в прогоне «Modern core and shared clients» на `9154cf5`
(Linux x2, macOS, Windows), поэтому 15 крейтов и 111 447 строк Rust под
`fmt`, `clippy -D warnings` и тестами. Локально в песочнице это не
воспроизвести — `cargo` и `rustc` недоступны, и логи job'ов GitHub для этого
токена недоступны (HTTP 401), поэтому состав и число выполненных Rust-тестов
подтверждены кодом гейта и фактом успешного прогона, но не самим логом.

> **Коррекция от 16 ноября.** В первой редакции этого отчёта утверждалось, что
> крейты Rust в CI не собираются и не тестируются. Утверждение неверное: оно
> получено поиском по строкам в файлах workflow без прохода по индирекции
> `workflow → run_release_checks --modern → tools/modernization/checks.py`.
> Исправлено в этом же документе.

**Гейтов линтинга, проверки типов и порога покрытия нет** — это осталось от
аудита 13 ноября. `tools/audit/code_checks.py` написан, но не подключён ни к
одному workflow.

**Python-набор в CI запускается** через `tests/run_release_checks.py` с
раздельными окружениями и зафиксированными зависимостями
(`requirements/core.lock` с хешами).

## 7a. Что в репозитории сделано правильно

Аудит фиксирует не только пробелы. За два дня в проекте появились
механизмы, которые ловят именно те ошибки, что обычно остаются незамеченными:

* **Предохранитель публичного паритета.** `contracts/fixtures/api-parity-inventory-v1.json`
  хранит рецензированный снимок SHA-256 семи исходных файлов и ревизии; при
  изменении любого из них проверка отказывается считать покрытие маршрутов
  подтверждённым («Authority inventory changed; regenerate and review»).
  Перебазирование PR #172 на новый `main` сработало именно на этом
  предохранителе — он спас от молчаливого расхождения контракта.
* **Пинование зависимостей по хешам** (`requirements/core.lock`) и отдельное
  изолированное окружение для исследовательского пакета.
* **Атомарная публикация и проверка целостности архива:** SigMF пишется через
  временные файлы с `fsync`, копия архива проверяется `integrity_check` и
  `foreign_key_check`.
* **Аддитивные миграции схемы** с явной версией `SCHEMA_VERSION` и проверкой
  отказа при более новой версии.
* **Разделение записи в архив и выдачи**: одна точка записи, постраничная
  выдача результатов измерений, ограничения ответа на стороне сервера.
* **Проверка соответствия источникам** во внешних сравнительных отчётах:
  утверждения о возможностях RT снабжены ссылками на первичные источники и
  помечены датой.

```bash
# целостность ссылок документации
python3 - <<'PY'
import re, pathlib
from urllib.parse import unquote
link = re.compile(r"\[[^\]]*\]\(([^)\s]+)")
missing = []
for md in pathlib.Path(".").rglob("*.md"):
    for target in link.findall(md.read_text(encoding="utf-8", errors="replace")):
        if target.startswith(("http", "mailto:", "#")): continue
        clean = unquote(target.split("#")[0].strip())
        if clean and not (md.parent / clean).exists(): missing.append(f"{md}: {clean}")
print("\n".join(missing) or "битых ссылок нет")
PY
```

Проверка Rust-крейтов требует `cargo` и выполняется отдельно; в песочнице
инструмент недоступен.
