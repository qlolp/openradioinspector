# Ограничения и отличия от оригинала

Документ фиксирует границы реализации. Он составлен так, чтобы читатель не
принял OpenRadioInspector за средство, пригодное для нормативных измерений
без дополнительной метрологической оценки.

## 1. Метрологический статус

**OpenRadioInspector не является аттестованным средством измерений.**
Расчётные процедуры реализованы по опубликованной методике, но:

* не проводится аттестация ПО;
* погрешность тракта (антенна, кабель, прибор) задаётся пользователем и не
  проверяется;
* калибровочные коэффициенты приборов не загружаются автоматически;
* каждый результат измерения сопровождается дисклеймером, но не заменяет
  его.

Для задач, требующих нормативного подтверждения, применяйте аттестованное
оборудование и сертифицированное ПО.

## 2. Расхождения в методике расчёта

### 2.1. Ширина занимаемых частот β/2

OpenRadioInspector использует **модель плотности мощности**: каждая точка
трассы трактуется как прямоугольник шириной, равной шагу перестройки, а
накопленная мощность обращается кусочно-линейно. Это соответствует
ITU-R SM.328-10 §3.4.1.

В оригинале накопленная мощность суммируется дискретно по строкам
таблицы. Расхождение между подходами не превышает **половины шага
перестройки**, то есть для шага 125 кГц — не более 62,5 кГц.

### 2.2. Полоса по уровню −N дБ

Уровень отсчитывается от пикового значения сигнала в пределах
выбранного поддиапазона. При наличии нескольких пиков отсчёт ведётся от
наибольшего; остальные сигналы в поддиапазоне могут исказить результат.
Рекомендуется выбирать поддиапазон, содержащий один сигнал.

Границы полосы находятся по алгоритму §11.2 руководства оригинала: от
точки максимума в обе стороны отыскивается ближайшая точка вне полосы
сигнала, а частота границы уточняется кусочно-линейной интерполяцией в
линейных величинах. Уточнение ведётся внутри интервала между соседними
отсчётами, поэтому погрешность определения **каждой границы** не превышает
шага перестройки; для гладкого спектра фактическая погрешность существенно
меньше.

### 2.3. Контрольная ширина полосы частот

Контрольная ширина полосы измеряется на уровне **минус 30 дБ** — так
определяет п. 2.6 Норм 19-21. Сверка с нормой выполняется с допуском
**10 %**: измеренное значение признаётся соответствующим норме, если
| B_изм − B_норма | ≤ 0,1 · B_норма.

Допуск 10 % — правило самого изделия (оно же зафиксировано в ключевом
слове `#M1902T_Res#` и в описании нормы на уровень +10 %), а не
требование Норм ГКРЧ: Нормы задают величину B_к, а не допуск к ней.

Условие п. 5.2.5 Норм 19-21 (уровень шумов должен быть меньше заданного
уровня на величину (X + 10) дБ) реализовано как предупреждение при
отношении сигнал/шум менее 10 дБ — расчёт не блокируется.

Пересчёт ширины полосы к уровню B_к по таблице 1 (п. 5.1.7 Норм) **не
реализован**: таблица содержится в приложении к Нормам и в открытой
реализации не воспроизведена.

### 2.4. Напряжённость поля

Расчёт нормированного значения напряжённости поля выполняется по мощности
с учётом сопротивления антенны и потерь антенного тракта. Значение
сигнала/помехи (ОСПШ) определяется по уровню шумовой дорожки, оценённой
методом автокорреляции; при недостаточном числе точек оценка помечается
предупреждением.

### 2.5. Центр тяжести

Метод применим при симметричном спектре, отношении сигнал/шум не ниже
30 дБ, расположении сигнала в центре полосы обзора и не менее 200 точках
в полосе. При несоблюдении условий выдаётся предупреждение, а не ошибка.

### 2.6. Единицы измерения и порог

Порог задаётся в **ваттах** (по умолчанию 1 пВт). В оригинале порог
задаётся в единицах мощности передатчика. Превышение порога рассчитывается
как разность между мощностью сигнала и мощностью, соответствующей порогу
на частоте сигнала.

### 2.7. Эффективность использования диапазона

Величина реализована как **доля моментов наблюдения, в которые уровень в
диапазоне превышал порог** (n/N по времени), что соответствует
ITU-R SM.1880 п. 3.6.2 (процент времени выше порога).

Это **не** загрузка диапазона по каналам: загрузка по каналам
(доля занятых каналов) и эффективность по времени — разные характеристики,
и в интерфейсе они вычисляются раздельно.

Число измерений N определяется по фактическому числу панорам в базе;
интервалы между измерениями вычисляются по времени записи. При
нерегулярном интервале (паузы в сканировании) статистика по интервалам
показывает это явно.

### 2.8. Профиль контроля фиксированных частот

Рекомендации оригинала (7–11 точек на частоту, пороги 6/20/30 дБ,
полоса пропускания ≤ 1/10 полосы сигнала, полоса обзора 1,5–3 полосы
сигнала, размах сигнала не менее половины экрана) реализованы как
**проверка профиля с формированием замечаний**, а не как автоматическая
настройка прибора: фактические параметры устанавливаются драйвером
устройства.

### 2.9. Ключевые слова протоколов

Словарь из 317 ключевых слов воспроизводит **названия и назначение**
полей подстановки, но не их форматы и единицы измерения, а также не
формат файлов шаблонов `.doc`, которые использовал оригинал.

## 3. Отличия в организации данных

| Аспект | Оригинал | OpenRadioInspector |
|---|---|---|
| Формат базы | FireBird 2.1, пять отдельных баз | SQLite, одна база панорам + база присвоений |
| Доступ к данным | через драйвер БД | открытый файл, читается любым сторонним средством |
| Имя файла базы | схема с `Dev`/`Ant`/`Tract`/`From`/`To` | та же схема |
| Продолжение записи | по набору параметров | по набору параметров (тот же принцип) |
| Связи между базами | по уникальным полям частоты | по частоте и времени, в общей схеме |

Переход на SQLite сохраняет принцип оригинала — «обработка результатов
измерений силами сторонних разработчиков» — и снимает зависимость от
проприетарного сервера БД.

## 4. Что не реализовано

* **Формирование отчётов в формате DOCX.** Протокол формируется в
  Markdown/HTML; конвертация выполняется внешними средствами
  (`pandoc`, LibreOffice).
* **Собственный драйвер GPIB.** Используется SCPI по TCP/IP или через
  адаптер; прямое управление через GPIB-контроллер не реализовано.
* **Полные сервисные подменю приборов** (калибровка по меню прибора,
  загрузка таблиц коррекции, переключение траекторий и т. п.).
* **Задачи пользовательского интерфейса оригинала** — многокомпонентная
  MDI-система заменена веб-интерфейсом и командной строкой.
* **Автоматическое распознавание типа прибора** по SCPI `*IDN?` с выбором
  профиля.
* **Режимы обработки IQ-данных оригинала** (IQ_ProcessPRO) реализованы
  частично: есть демодуляция и звуковой контроль, нет полного набора
  обработчиков.
* **Планировщик заданий с таймером.** Модель задания, статусы и профиль
  контроля фиксированных частот реализованы, но фоновый планировщик,
  автоматически запускающий задания в назначенный момент, не реализован:
  переход статусов выполняется вызовом из кода или вручную.
* **Сетевой протокол I_RemoteCheck.** Порт 47383, интервал опроса 20–30 с и
  цветовая индикация состояния операторов относятся к закрытому протоколу;
  в проекте реализован родственный механизм — веб-интерфейс с SSE,
  несовместимый с оригиналом на уровне протокола.
* **Аппаратная часть RInspectorWiFi** — модуль перехвата 2,4/5 ГГц,
  архив `*.IWArch`, заводской адрес 192.168.200.201 — не воспроизводится;
  реализован только разбор кадров 802.11.
* **Загрузка данных ФАИС и ЕТС.** Исходные конверторы оригинала
  (программа «Конвертор БД», конвертер ЕТС из Access в FireBird) не
  реализованы; загрузка выполняется из CSV.
* **Эталонная панорама и разность панорам.** Один из трёх методов поиска
  незаконно действующих передатчиков оригинала; в проекте не реализован.
* **Адаптивная линия порога** — огибающая по минимуму превышения графика
  максимумов (Книга 7, §1.1).
* **Спектрограмма 3D.** Реализовано только 2D-представление.
* **Запись фонограммы с 5-секундным отрезком**, предшествующим началу
  записи, и автоматическая запись по превышению порога.
* **Аудиоконтроль вторым сканирующим приёмником** без остановки сканирования
  (опция `Light-SoundScaner`).
* **Определение принадлежности излучения к классу аналоговых
  телевизионных сигналов** и поиск передатчиков со сложными алгоритмами
  скрытия работы.
* **Измерение параметров DVB-T(H)** (MER, BER до и после декодера Витерби и
  кода Рида — Соломона, защитный интервал, скорость кодирования H/L).
* **Автоматическая коррекция (округление) частот** по таблицам коррекции.
* **Геоинформационная система** на картах OpenStreetMap с режимами Online и
  Offline; расчёты радиовидимости и антенного компаса реализованы, карта с
  точками измерений — нет.
* **Управление приборами по сети** (опция `RemoteMD`, программа
  `MasterDevice-Light`): OpenRadioInspector обращается к прибору по сети, но
  не принимает управления от удалённой рабочей станции.
* **Импорт списка сигналов формата Радиосканера** (файл `RadioScanner.fcsvs`)
  и база частотных запросов (`1 RECORD.IFRQDB`).
* **Декодеры цифровых стандартов** DECT, GSM, TETRA, APCO25, DMR: закрытое
  ПО оригинала; реализован только расчёт требований к IQ-данным
  (`iq.py`).

### 4.1. Что воспроизведено по итогам разбора RadioInspector Light 32314

* Задание на контроль фиксированных частот с условием действия при
  обнаружении (`tasks.py`, `FixedFrequencyList`, команда `freqs`) — второй
  уровень трёхуровневой модели измерений.
* Модель планового задания по составу записи `TASKPLAN`: справочные
  величины вида задания, цели, предприятия, отдела, группы, основания и
  носителя; служебные даты создания, подготовки, фактического запуска и
  остановки; прерывания; состав оборудования и исполнителей; результат;
  позиция обработки; мобильность; вложения.
* Диагностика изрезанности спектра: число обнаружений больше числа циклов
  сканирования.
* Расчёт требований к IQ-данным (`iq.py`, команда `iq`): `Fd`, `L`,
  `M = Fd · L`, `L1 = M_доступное / Fd`.


## 5. Производительность

* Расчёт агрегатов по всей базе выполняется в памяти (`numpy`): при базе
  из 10 000 панорам по 801 точке это ≈ 64 МБ и единовременная загрузка
  всей базы. Для очень больших баз рекомендуется ограничивать выборку
  (`panorama.select`).
* Веб-интерфейс обновляет снимок состояния по таймеру и по событиям SSE;
  спектрограмма обновляется раз в 15 секунд, чтобы не пересылать
  многомегабайтные массивы.
* Запись в SQLite выполняется в режиме WAL, синхронизация — на каждую
  панораму; для длительных измерений на сетевых дисках возможны задержки.

## 6. Совместимость

* Python 3.10 и новее.
* Обязательная зависимость — только `numpy`. `matplotlib`, `SoapySDR`,
  `pyrtlsdr`, `scapy` устанавливаются как необязательные extras.
* Веб-интерфейс использует только стандартную библиотеку
  (`http.server`) и не требует ASGI-сервера.
