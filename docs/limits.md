# Границы и ограничения

Этот документ отделяет реализованный программный контур от возможностей оригинального RadioInspector и от будущих аппаратных функций.

## Происхождение

- Это независимая открытая разработка по публичной документации.
- Исходный код RadioInspector, закрытые протоколы и лицензионная совместимость не заявляются.
- Чужие PDF не копируются в репозиторий. Сохраняются только ссылки на публичные источники и собственные выводы.
- Отчёты о 28 руководствах являются исследованием требований, а не списком уже реализованных функций.

## Приборы

- В текущем серверном контуре доступны только `tinysa-sim` и `ardv1-sim`.
- Физические последовательные/USB-соединения tinySA Ultra и AR-DV1 этими адаптерами не открываются.
- Реальная чувствительность, RBW, скорость sweep, уровни S-метра, режимы демодуляции и одновременная работа должны проверяться на стенде.
- Наличие поля `capabilities` у модели не означает аппаратную поддержку.
- `audio_available` является данным наблюдения, а не доказательством потокового аудио через сервер.
- Генератор tinySA не включён в общий приёмный сеанс. Передача, излучение и генерация сигнала не предлагаются как готовые функции.

## Единицы и время

- Частоты строго целые Гц. Дробные значения, включая `100000000.5`, отклоняются, а не округляются молча.
- `Sweep.levels_dbm` допускается только для потока `dBm`.
- `ReceiverObservation.s_meter_count` — положительный целый отсчёт для потока `s_meter_count`.
- `rssi_dbm` отдельное необязательное поле; автоматического преобразования между `dBm` и `s_meter_count` нет.
- Для каждого измерения обязательны timezone-aware `started_at` и `ended_at`; JSON использует UTC `Z`.
- Выборки сортируются по времени начала с микросекундами и ID до применения `limit`.

## Сеансы и отказоустойчивость

- В одном процессе может работать несколько независимых `DeviceWorker`, но только один владелец каждого worker.
- Перестройка, остановка или сбой одного worker не останавливает другой. Общий lock не удерживается во время команды прибору.
- Несколько UI могут подключаться к одному серверу. Они не должны открывать общий физический порт напрямую.
- После перезапуска SQLite восстанавливает архив, но не runtime threads. Потоки получают `disconnected`, workers нужно запустить заново.
- Live SSE не гарантирует доставку при переполнении очереди медленного клиента. Восстановление выполняется через сохранённые события и `after`/`Last-Event-ID`.
- Отсутствует распределённый кластер, репликация SQLite и координация нескольких независимых серверных процессов над одной базой.

## Кандидаты и исследования

- Кандидаты создаются вручную через API/WebUI. Автоматического обнаружения сигналов пока нет.
- Ручной handoff перестраивает выбранный receiver и переводит исследование в `listening` только после успешной команды.
- Полуавтоматический handoff выбирает следующее `queued` по приоритету, но `next` ничего не запускает. Для `start-next` обязательны актуальный `investigation_id` и `confirm=true`; устаревшая рекомендация отклоняется до перестройки.
- Автономного scheduler/dispatcher нет: `automatic_handoff=false`. Исследования не запускаются по таймеру, SSE или изменению очереди без отдельного подтверждения оператора.
- На одном receiver одновременно допускается только одно исследование в `tuning`, `listening` или `decoding`. Другие receiver и scanner не блокируются.
- Нет автоматического восстановления прежней частоты receiver после завершения или отмены.
- Нет публичного перехода в `decoding`, автоматического распознавания режима и аппаратной цифровой демодуляции.
- Успешное `complete` требует подходящее наблюдение того же receiver, с целевой частотой и, если задан, режимом.
- После перезапуска активные исследования получают `failed`, кандидаты возвращаются в `queued`; ожидающие остаются `queued`.
- Кандидаты и исследования являются архивными записями с foreign keys. Удаление связанных потоков и архивных результатов намеренно ограничено.

## WebUI и сеть

- `/platform` — рабочий многоприборный интерфейс, а `/` — сохранённый legacy-прототип панорам.
- WebUI не содержит браузерного симулятора измерений. Он показывает только серверные ответы и не управляет портами напрямую.
- Спектр/водопад ограничены 40 свипами и 1000 точками на свип. Это защита браузера, а не предел архива SQLite.
- Проверены программный HTTP/SSE-стенд и отображение на 320 px. Аппаратный Raspberry Pi, реальные приборы, длительная нагрузка и все браузеры не сертифицированы.
- HTTP не имеет встроенных TLS, пользователей, ролей и аутентификации. По умолчанию сервер слушает loopback.
- `0.0.0.0` следует использовать только в доверенной сети или за внешним защищённым reverse proxy.

## Клиенты и производительность

- Windows GUI ещё не реализован.
- Существующий macOS SwiftUI-клиент не подключён автоматически к новому серверному `/api/v1`; его локальные симуляторы не являются общим серверным архивом.
- Измерения записываются по одному в текущей транзакционной реализации. Пакетная оптимизация ещё не выполнена.
- Нет потокового аудио, записи IQ, цифровых протоколов, классификации сигналов и полноценной системы отчётов в общем контуре.
- Нет гарантии повторения всех 28 руководств или полного функционального паритета с RadioInspector.
