# Проверка крайних отсчётов архивного спектра

## Что делает срез

Общее ядро вычисляет **производный отчёт по одному сохранённому dBm sweep**.
WebUI/Pi, Windows Tk и macOS SwiftUI запрашивают тот же API, а не реализуют
собственные измерения или команды tinySA. Два явно заданных порога помогают
отметить данные, которые стоит проверить перед длительным мониторингом:

- `edge_margin_db`: положительный скачок первой/последней точки относительно
  её непосредственного соседа; допустимо `0 < value <= 200` dB;
- `high_level_dbm`: уровень для подсчёта отсчётов `level >= threshold`;
  допустимо `-200 <= value <= 100` dBm.

Значения формы по умолчанию: 20 dB и 0 dBm. **Это пользовательские пороги
просмотра, не предел безопасного RF-входа и не характеристика прибора.**
Настоящий узкополосный сигнал на краю диапазона тоже может дать флаг.
Отсутствие флагов не доказывает исправность прибора или отсутствие помех.

Метод не ставит диагноз «перегрузка», «неверная калибровка» или «внутренний
отклик». Он не исправляет/удаляет отсчёты, не меняет настройки/прошивку,
не переключает генератор/LNA/Ultra и не запускает либо останавливает
работающий поток. Решение о физической проверке остаётся отдельным действием.

## Методика `archived_edge_level_review_v1`

1. Требуется 2–16384 точки со строго возрастающей сеткой целых Hz в диапазоне
   0…9007199254740991 и конечными исходными dBm. Повторяющиеся частоты,
   несовпадающие размеры, неверные единицы/интервал и непредставимые разности
   отклоняются, а не исправляются.
2. Для начала: `delta_db = levels[0] - levels[1]`; для конца:
   `delta_db = levels[-1] - levels[-2]`. Разность **знаковая**, не модуль.
   Равенство порогу считается срабатыванием.
3. `high_level_count` — число всех точек, достигших порога уровня. Это не
   длительность и не частотная занятость. Точки не исключаются из архива или
   последующей аналитики.
4. `peak_index` — индекс первого максимума при равных уровнях. Частота и
   уровень пика берутся непосредственно из исходной сетки, без интерполяции.
5. Флаги возвращаются в порядке `first_edge_jump`, `last_edge_jump`,
   `level_threshold`. `assessment=review`, если есть флаг, иначе `no_flags`.
   Всегда `hardware_diagnosis=false`, `raw_modified=false`.

При двух точках начало и конец используют друг друга как соседа.
Неравномерная, но строго возрастающая сетка разрешена: отчёт сравнивает
соседние отсчёты, не спектральную плотность и не производную на Hz.

## API v1

`POST /api/v1/sessions/{session_id}/sweep-quality` — read-only анализ,
без событий записи и без изменения состояния сеанса/прибора.

Тело содержит **ровно**:

```json
{"sweep_id":"example-sweep","edge_margin_db":20,"high_level_dbm":0}
```

ID — непустая UTF-8 строка до 128 символов. Числа должны быть конечными;
строки, boolean, NaN/Infinity и неизвестные поля не принимаются. Тело
ограничено 8192 байтами; duplicate JSON keys, query-параметры, неправильный
Content-Type и чужой Origin отклоняются общим bounded-analysis обработчиком.

Ответ в существующей оболочке `openradioinspector-platform`, version 1:

- `session_id`, `stream_id`, `sweep.id/interval/level_unit/settings` — копия
  происхождения выбранного источника; исходные UTC и настройки не выдумываются;
- `parameters.edge_margin_db/high_level_dbm`, `points`;
- `peak_index`, `peak_frequency_hz`, `peak_level_dbm`, `high_level_count`;
- `edge_assessments`: ровно начало и конец, каждое содержит `edge`, `index`,
  `frequency_hz`, `level_dbm`, `neighbor_index`, `neighbor_level_dbm`,
  `delta_db`, `flagged`;
- `flags`, `assessment`, `method`, `hardware_diagnosis`, `raw_modified`.

Ответ не содержит полного массива исходных уровней: его по-прежнему можно
получить через существующий архивный API/NDJSON. Метаданные источника
ограничены 64 KiB сериализованного UTF-8 JSON; неподдерживаемые типы,
некорректный UTF-8 и числа, не представимые конечным float, отклоняются без
нормализации исходных настроек. Отчёт не сохраняется в архив.

Ошибки: 400 `invalid_request`, 404 `session_not_found`/`sweep_not_found`,
409 `quality_incompatible`, 413 `request_too_large`; общие 403/415 для
Origin/Content-Type. `capabilities.features.sweep_quality=true` объявляет
наличие этого read-only API, не аппаратную поддержку.

## Архивы и клиенты

Работа возможна без подключённого прибора и без PR ограниченного tinySA
профиля. Старые и новые архивы принимаются независимо от наличия identity
или readback. `null` в исходных JSON settings сохраняется как неизвестное
значение и не превращается в подтверждённую настройку. Общий gate сравнения
нескольких sweep не изменён и не ослаблен: этот отчёт читает один источник.

Клиенты показывают отчёт только для выбранного источника и порогов, проверяют
идентичность ответа и отбрасывают устаревший результат после смены выбора.
Неверный ответ не отображается как отсутствие флагов. Пределы и единицы
доступны в формах; после редактирования параметров требуется новый запрос.

## Проверка и ограничения

Синтетические тесты покрывают оба края, знаковые разности, равенство порогу,
две точки, равные максимумы, внутренний пик, границы размеров, неверные JSON,
переполнение разности, HTTP-коды и неизменность logical SQLite dump после
анализа и перезапуска. Тесты клиентов проверяют ответы, происхождение и
устаревшие асинхронные результаты. Это не новая аппаратная валидация.

Общий gate: `python -m tests.run_release_checks --swift` на macOS с Tk,
Node, pySerial, Swift и Xcode. На headless Linux нужен Tk display (Xvfb);
`python -m unittest discover -s tests -t .` с пропусками не заменяет полный gate.
Физические порты, прошивка, калибровка и пользовательские архивы не нужны.
