# Закреплённый вид спектра, версия 1

Первый срез обновления GUI меняет только отображение данных общего API.
Новых методик измерения, API-маршрутов, записей в архив, команд приборам,
калибровки или постоянных настроек нет. M1/M2, выделение диапазона и водопад
с настоящей временной осью остаются следующими срезами. Прежние локальные
macOS-панели прямого управления приборами сохраняют поведение.

## Управление

В WebUI и Windows откройте спектр выбранного потока, в macOS — панель
tinySA через общее ядро. Первая корректная выборка закрепляет одну шкалу
уровня для спектра и палитры водопада. Обновление данных и изменение размера
окна её не меняют.

- **Fit** подгоняет шкалу по текущему видимому снимку.
- Два поля границ и **Apply** задают её вручную: минимум строго меньше
  максимума, оба значения конечны. Используется десятичная точка, разрешён
  показатель степени e. Ошибка не меняет предыдущую правильную шкалу.
- **Pause view** замораживает только видимый снимок, его исходные ID,
  интервалы UTC и показания. **Live** сразу показывает последнюю доступную
  выборку, без проигрывания пропущенных обновлений.
- Опрос, команды сбора и состояние записи не меняются от этих кнопок.
  Просмотр остановленного архива не запускает приборы. Панели анализа
  независимы от паузы графиков.
- Fit и ручная шкала работают и с замороженным снимком. Счётчик сообщает,
  сколько исходных значений находится за шкалой: ограничиваются только
  координаты и цвет, а не записанные значения.
- Действия по пику видимого спектра заблокированы во время паузы, чтобы
  незаметно не использовать более новый живой свип.

Границы в полях — редактируемый черновик. Обычное обновление данных его не
перезаписывает; фактически применённая шкала показана отдельно.

## Общие правила трёх клиентов

Область просмотра включает точный адрес сервера, ID сеанса и потока,
исходную единицу и всю частотную сетку. Строковые ID сравниваются без
нормализации Unicode и без удаления пробелов; допустимы непустые строки.

Этот вид принимает исходные dBm спектрального потока. Наблюдения приёмника
s_meter_count остаются отдельными и не переводятся в dBm. Частоты должны
не убывать; повторяющиеся целые Гц сохраняются. Для точного общего
отображения допустимы 0…9 007 199 254 740 991 Гц. Это ограничение нового
вида, а не изменение контракта или содержимого архива.

Проверяется вся полученная выборка. Вид хранит максимум 40 свипов:
непрерывный хвост с точной сеткой последнего свипа. Разные сетки не
склеиваются в один водопад. Смена сервера, сеанса, потока, единицы или
сетки сбрасывает шкалу и снимает паузу. Пустые, некорректные или чужие
данные очищают вид. Потеря соединения не оставляет старый график под
видом живых данных.

Интервалы должны быть полными корректными датами UTC григорианского
календаря, годы 0001…9999: YYYY-MM-DDTHH:MM:SS, необязательные 1…6 цифр
дробной секунды и Z либо +00:00. Начало не позже окончания, сравнение
точно до микросекунды. Исходные строки сохраняются. Несуществующие даты,
24:00, секунды 60, локальное время и обратные интервалы отклоняются.

При ручном вводе удаляются только крайние ASCII-пробелы: обычный пробел,
табуляция, CR/LF, FF, VT. Затем принимается десятичное число с необязательным
знаком и показателем степени. Пустые строки, шестнадцатеричная запись,
NaN/Infinity, Unicode-пробелы и FEFF не принимаются.

## Численная устойчивость

Автошкала использует минимум и максимум всех видимых уровней с запасом
max(8% размаха, 1). Размах вычисляется в нормированных координатах без
переполнения, границы ограничены конечными значениями Double. Если для
огромного постоянного уровня округление сводит границы к одному числу,
используется запас max(8% абсолютного уровня, 1). Координаты и палитра
ограничены [0, 1]. Исходные уровни, единицы и частоты не изменяются.

В macOS ответы обновления дополнительно защищены порядковым номером
запроса: запоздалый старый успех или ошибка не заменяет более свежий
снимок в той же области.

## Ограничения водопада

Строки пока означают порядок свипов, а не равные интервалы времени;
WebUI использует общую шкалу частоты в Гц с release resampling;
остальные рендереры сохраняют прежнюю геометрию. Это не временная ось.
Исходные начало и окончание последнего видимого свипа показаны в UTC.
Паузы между свипами не выводятся из частоты опроса и не выдаются за
измеренную временную шкалу. Настоящая временная ось и согласование
частотной геометрии native-клиентов остаются отдельными срезами. Ориентация прежних клиентов сохранена.

## Воспроизводимые проверки

Общие синтетические данные:
`tests/fixtures/spectrum-presentation-v1.json`. Их читают Python,
JavaScript и Swift: обычные, постоянные и предельные конечные уровни,
одна точка, неравномерная сетка, разрыв UTC, некорректные интервалы,
границы Гц и ручной ввод. Отдельные проверки выполняют реальные
обработчики WebUI, скрытые Tk-кнопки и RemoteDualModel через URLProtocol.
Они проверяют заморозку и возобновление, смену области, исходные значения,
отсутствие команд от локальных кнопок и закрытие окон.

Полный набор: `python -m tests.run_release_checks --swift`;
описание изоляции — [release-validation.md](release-validation.md).

Следующие результаты относятся к исходному PR101, коммит
`bb9f629f788db3cf9bbfc17b23b46dd77f2712b5`, а не к текущей release-интеграции.
Финальный полный локальный прогон этого исходного дерева на Mac Air: **1079 Python/Node/Tk**,
**170 Swift SDK**, **113 native Swift**, без пропусков; unsigned Xcode
**BUILD SUCCEEDED**. Все семь временных архивов сохранили логические хеши,
собственные серверы остановлены, временный каталог удалён. Python 3.12.15,
Tcl/Tk 9.0.4. Stale Tcl/native lifetime ошибок нет; в журнале есть два
нефатальных loopback ConnectionResetError и прежние предупреждения сборки.

Независимое ревью не оставило подтверждённых блокеров. Дополнительные чистые
численные проверки дали 20 005 Python и 100 000 JavaScript случаев без
некорректных границ/координат. Полный прогон также проверил прежние HTTP
сценарии анализа: одинаковые данные больше не создают лишнюю ревизию
водопада, а ID/UTC обновляются независимо.

Ручная визуальная приёмка, native Windows, hosted CI этого среза,
физические приборы и реальные архивы не проверялись. Локальный успех
не подтверждает устранение прежнего hosted macOS/Tk 8.6.16 зависания:
матрица должна быть запущена на точном опубликованном коммите отдельно.

## Проверка release-интеграции

База release-интеграции — PR103,
`9143324191758e25cd492a928ad49e46a522b363`. Полный локальный набор после
согласования с этой базой: **1182 Python/Node/Tk**, **174 Swift SDK**,
**113 native Swift**, 0 пропусков и unsigned Xcode **BUILD SUCCEEDED**.
Семь временных архивов неизменны, серверы остановлены, временный каталог
удалён. Stale Tcl/native lifetime diagnostics отсутствуют. Два нефатальных
loopback ConnectionResetError и прежние предупреждения сборки не скрываются.

Для воспроизводимой визуальной проверки без приборов можно запустить
`python -m tests.spectrum_view_smoke_server`. Фикстура печатает URL
свободного loopback-порта, создаёт два потока только в памяти и не открывает
архив. Команда `advance` в её stdin добавляет синтетический свип в каждый
поток (не более 32 команд), `quit` или EOF останавливает сервер; время жизни
ограничено 600 секундами. Изменяющие HTTP-запросы, SSE и legacy API запрещены.
Браузерное обновление использует polling и ограниченный history GET.
Фикстура предназначена для общего API, не для локальных macOS-панелей приборов.

Ручная визуальная приёмка трёх клиентов не завершена. Полный автоматический
прогон, проверки HTTP и модели не заменяют визуальную или аппаратную приёмку.
Hosted source/package gates этого дерева проверяются отдельно. Локально
не устанавливались зависимости и не собирался настоящий Python sdist;
workflow проверяет общий fixture и тесты отображения из распакованного sdist.
