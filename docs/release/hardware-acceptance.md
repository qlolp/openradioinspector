# Аппаратная приёмка v0.4.0

Только реальные приборы подтверждают эти критерии. Симуляторы и зелёный CI
не меняют BLOCKED на PASS. Выполняет владелец оборудования на точном SHA.

Заполнить: дата UTC, SHA/версия, хэш установщика, ОС/архитектура, модели,
серийные номера (приватно), прошивки tinySA/AR-DV1, драйверы USB, порты,
параметры обзора и сети. Измерения и журналы с частными данными не публиковать.

| № | Действие | Ожидаемый результат | Статус | Журнал/наблюдение |
|---|---|---|---|---|
| 1 | Запустить tinySA и AR-DV1, затем остановить по одному | Второй поток продолжает запись; порт освобождается после остановки владельца | BLOCKED | |
| 2 | Обнаружить кандидат tinySA и передать AR-DV1 | AR-DV1 настроен на целевую частоту, исходный обзор не прерывается; S-метр не выдаётся за dBm | BLOCKED | |
| 3 | Отключить/вернуть USB; задержать ответ до timeout | Явная ошибка только нужного потока, отменённый транспорт не используется повторно; восстановление управляемое | BLOCKED | |
| 4 | Перезапустить ядро, открыть архив | Измерения и последовательности событий целы, незавершённые действия отмечены, приборы не активируются скрытно | BLOCKED | |
| 5 | Windows и macOS подключить к одному сеансу Pi | Оба видят согласованные данные и переподключаются; USB принадлежит только ядру Pi | BLOCKED | |
| 6 | Запустить реальное задание, отменить, перезапустить | Нет повторных аппаратных действий; отмена сохраняется, тайм-аут/ошибка видимы | BLOCKED | |
| 7 | Перенести сеанс на другую ОС, аналитика и DOCX | Контрольные суммы и исходные единицы сохранены; отчёт открывается; ошибка записи не уничтожает предыдущий документ | BLOCKED | |
| 8 | Совместный прогон 8 часов | Учтены пропуски/дубликаты; нет необъяснённой потери данных или неограниченного роста памяти | BLOCKED | |
| 9 | Чистая установка/обновление/удаление на трёх ОС | Запуск без checkout и ручного Python на Windows; архив не удаляется деинсталляцией; откат проверен | BLOCKED | |

Для каждого FAIL записать шаги, ожидаемое/фактическое поведение, время и ссылку
на issue. Для восьмичасового прогона: количество измерений по потокам,
ожидаемая частота/интервалы, пропуски и дубликаты, RSS раз в минуту,
начальный/конечный размер архива, события USB и переподключений клиентов.
Только документированный PASS всех обязательных сценариев разрешает RC→релиз.
