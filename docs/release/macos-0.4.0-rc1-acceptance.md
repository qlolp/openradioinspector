# Приёмка личного macOS RC1

Статус: **протокол, фактическая macOS 27.3 и приборы пока не проверены**.
Версия `0.4.0-macos.rc.1` — личный кандидат, не стабильный публичный релиз.
Rust не становится принятым основным ядром по результату сборки пакета.
Аудиозахват и Python/DuckDB в RC1 исключены. Pi и Windows выпускаются позже;
их общие автоматические проверки сохраняются.

## Установка и происхождение

На MacBook Air Apple Silicon с 16+ ГиБ сохранить вне Git: SHA исходников,
внешний манифест и SHA256SUMS, реальную версию `sw_vers`, модель/память Mac,
прошивки обоих приборов, параметры USB-хаба, антенн и тракта. Установить macOS
27.3 перед приёмкой. CI на другой версии ОС не закрывает эту строку.

Скопировать проверенный `.app` из DMG в «Программы», извлечь DMG, выполнить
штатное разрешение запуска ad-hoc приложения. Проверить офлайн, вне checkout,
без Python/Homebrew/Xcode у пользователя. `--self-check` проверяет подпись и
состав без запуска службы. Изменённый helper/манифест должен дать отказ.
Включить службу явно, при необходимости подтвердить фоновое приложение в
настройках macOS. До подготовки не должны открываться USB или включаться
охрана. Ошибка службы не запускает Python или симулятор.

Проверить другой запущенный экземпляр, занятый порт и ошибку запуска. Второй
владелец не получает архив/порты. Повторный UI подключается к тому же instance
ID. Команды управления службой не доступны через HTTP. Остановить службу
штатной кнопкой, дождаться подтверждения и только затем заменить пакет.
Откат сохраняет новые измерения; старую копию поверх них не восстанавливать.

## Программная нагрузка без аудио

У инженерного инструмента отдельное окружение; Python не входит в приложение.
Для сборки испытательного embedding на Mac:

```sh
cargo build --locked --release -p ori-core --no-default-features --features serial \
  --example benchmark_background
# Скопируйте полученный бинарник из build-кэша в неизменяемый испытательный каталог.
python -m benchmarks.ori_bench.macos_rc \
  --candidate /absolute/immutable/ori-rc-benchmark \
  --output-dir /absolute/new-private-results/rc1-load
```

Инструмент создаёт **отдельный пустой архив**, не регистрирует SMAppService,
не открывает USB и не затрагивает рабочий каталог RC. Ядро обозначено replay,
поскольку вход синтетический. Профиль явно исключает научный worker и PCM.
В течение 1800 реальных секунд предлагаются 18 000 свипов по 4096 точек и
18 000 наблюдений. Сохраняются прежние очередь, offered-ledger, сроки 10/600/60
секунд и проверка каждого предложенного источника, включая отказы и потери.
Нельзя считать только подтверждённые HTTP-запросы знаменателем успешности.

Одновременно читаются ограниченные страницы исходной истории и выполняется
online backup через существующий архивный слой. Каждая возвращённая запись
проверяется по ID, целочисленным Гц, UTC, единицам и битам исходных float.
Backup проверяется и восстанавливается в **новый каталог**. Отдельно фиксируется,
наблюдались ли одновременно работающий backup и запрос истории; короткий smoke
не может заменить такую проверку. Предварительная оценка места использует
фактические сериализованные размеры fixture, запас SQLite и три одновременно
существующие копии: исходник, backup и restore. Ничего не удаляется автоматически.

`--smoke-seconds 5` — только функциональная проверка инструмента. Она не закрывает
30-минутный gate. Прежний полный профиль с 48 кГц PCM и тремя Web-клиентами не
меняется; его прежний неуспех остаётся открытым до собственного успешного прогона.

**Нативная производительность — отдельная обязательная проверка на Mac.**
Headless harness не измеряет SwiftUI/Metal и всегда оставляет `rc1_accepted=false`.
Отдельно сохранить трассу фактически показанных кадров с исходными ID и границами
commit→presentation, ответы постановки команд в очередь, реакции интерфейса и
кадры при панорамировании/масштабировании. Worker ACK и завершение GPU-команды
не считать показом кадра. Неизмеренные показатели остаются `unmeasured`.

| Показатель на фактическом Mac | Требование |
|---|---|
| Все предложенные исходники | 18 000 / 18 000, без потерь, повторов и изменений |
| Реакция UI, p95 | ≤100 мс |
| Подтверждение очереди, p95 | ≤200 мс; выполнение прибора отдельно |
| Commit→показанный кадр, p95 | ≤250 мс |
| Панорамирование/масштабирование | ≥30 fps |
| История и backup одновременно с приёмом | Успешны, исходники совпадают |

## Восемь часов tinySA Ultra + AR-DV1

Подключить оба прибора непосредственно к Mac/питаемому USB-хабу и выбрать
проверяемые профили. USB AR-DV1 используется для управления и показаний;
аудиотракт в RC1 отсутствует. S-meter остаётся исходными отсчётами, не dBm.
Подтверждённый режим приёмника и сведения декодирования записывать раздельно.

Мастер требует подтверждения антенны/места/тракта, проверяет диапазон, модель,
прошивку, `input`, RF/CAL off и архив. Подтверждение команды не заменяет
физический RF readback. Эталон: ≥60 секунд и ≥20 полных совместимых свипов,
затем явное подтверждение оператора. Охрану включать отдельным действием.

До охраны измерить фактический поток записи и проверить бюджет на **12 часов**
(8 часов +50%) вместе с резервом существующего архива и будущего backup.
Неизвестная скорость или недостаток места блокируют готовность. Автоудаление
исходников выключено. Проверки заполнения делать только на отдельном тестовом
архиве/томе; логическая квота и реальный ENOSPC — разные испытания.

| Интервал | Сценарий и проверяемый результат |
|---|---|
| 00:00–01:00 | Подготовка, эталон, охрана; реальные свипы и версия эталона сохранены |
| 01:00–02:00 | Обычный фон/новое излучение; событие связано с исходной панорамой |
| 02:00–03:00 | Очередь AR-DV1, занятый/исчезнувший сигнал; tinySA продолжает обзор |
| 03:00–04:00 | Исследование, исходник ≤2 действий, поиск источника и возврат; пауза широкого покрытия видна |
| 04:00–05:00 | Закрытие окна и Command-Q; непрерывная запись, повторный UI — тот же instance ID |
| 05:00–06:00 | Контролируемое USB-отключение/возврат каждого прибора; разрывы и причины видны |
| 06:00–07:00 | Ручной сон, крышка, пробуждение; старый USB-транспорт блокируется, явная повторная подготовка |
| 07:00–08:00 | История, backup/restore отдельно, остановка/повторный запуск и сверка исходных ID/времени/единиц |

Проверить, что автоматический idle sleep предотвращается именно во время охраны.
Ручной сон и закрытие крышки не блокируются этим обещанием. После сна нельзя
молча считать прежний профиль готовым. Вход в систему не запускает охрану по
умолчанию. Переход в «Исследование» не снимает охрану.

## Итог и следующие RC

Для каждой строки записать `не выполнен / пройден / не пройден`, фактический
интервал UTC, исходные ID, числа предложенных/сохранённых записей, измеренные
p50/p95/max, ошибки и ссылки на приватные исходники/контрольные суммы. Секреты,
серийные номера и частные измерения не коммитить.

Успех RC1 требует одновременно установки, общих/Swift/Xcode-проверок, полной
30-минутной нагрузки с нативным UI и принятого восьмичасового протокола именно
на macOS 27.3. Сборка DMG и headless smoke недостаточны. Исправления поставляются
следующими RC с повторением затронутых проверок. Аудио — следующий RC, недельный
автономный прогон — до заявления о подтверждённой работе 24/7. После успеха Mac
переходить к Pi/Windows с отдельной аппаратной приёмкой каждой платформы.
