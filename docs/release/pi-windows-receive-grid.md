# Обзор 0,1–1300 МГц на Raspberry Pi и Windows

Общий Rust worker последовательно измеряет выбранные поддиапазоны tinySA и сохраняет каждый ответ прибора отдельным исходным свипом. AR-DV1 работает в своём исполнителе. Перестройка приёмника по событию и явно выбранный сегмент используют его собственный порт.

В проекте с возможностью `features.scan_plan_grid_10khz` можно сохранить, например, такой план через `POST /api/v1/monitoring-projects/{project_id}/scan-plan`.

```json
{
  "name": "Обзор 0,1–1300 МГц",
  "bands": [{
    "id": "wide",
    "name": "Широкий обзор",
    "start_hz": 100000,
    "stop_hz": 1300000000,
    "step_hz": 10000,
    "points": 129991,
    "rbw_hz": 30000,
    "max_revisit_seconds": 3600
  }]
}
```

Обе граничные частоты включены. В полном проходе 449 аппаратных окон. В одном текстовом `scan` от 2 до 290 отсчётов. Когда остаток равен одному отсчёту, последние два окна содержат 289 и 2 отсчёта. Служба проверяет каждую возвращённую частоту, число отсчётов и конечность значений. Запрошенная полоса RBW составляет 30 кГц для быстрого обзора или 10 кГц для детального. Шаг сетки в обоих случаях 10 кГц. В старом формате без `step_hz` сохраняются 2–290 точек и серийный предел 800 МГц.

Для серийного плана, включающего частоты выше 800 МГц, исполнитель проверяет на своём соединении модель ZS405, непустой `deviceid`, прошивку `tinySA4_v1.4-235-gea71dfd` и строку `HW Version:V0.4.5.1`. Ошибка идентификации завершает подготовку до команд настройки. Исполнитель подтверждает `output off` и `mode input`, задаёт LNA, аттенюацию, RBW, обработку и приёмный тракт Ultra. Во время прохода он меняет тракт и RBW при переходах между требующими этого окнами. Ошибка ACK или некорректная сетка завершает измерение без записи свипа. ACK характеризует команду, физический readback RF отсутствует.

Для автоматической охраны по серийному профилю используются только окна, полностью попадающие в диапазон до 800 МГц включительно. На общей сетке из примера это 275 из 449 окон. Все полученные ответы сохраняются в исходных единицах. Статус пригодности для эталона и состояние фактически измеренного покрытия показаны отдельно. [Полосы, критерии и приёмка выпуска](0.4.0.md)

Каждый исходник содержит собственные ID, UTC начала и конца, целые частоты в Гц, исходные дБм, версию и ID плана, ID поддиапазона, `scan_window_index` с нуля, `scan_window_count` и `scan_step_hz`. В серийном режиме сохраняются также `scan_serial_baud`, `scan_ultra_input`, его источник и сведения об идентификации. Поле `scan_rx_evidence` сохраняет SHA-256 ответа `deviceid` без крайних пробелов и подтверждённые режим входа, LNA, аттенюацию, обработку, Ultra и RBW. Для сопоставления используется идентификатор, который сообщает прибор. При настройке `period_s` пауза применяется после логического поддиапазона. Между его окнами исполнитель сразу обслуживает очередную команду или начинает измерение. Новый план с сеткой без `period_s` работает без искусственной паузы.

При поиске по высокочастотному событию проект с сеткой создаёт отдельный узкий план с RBW 10 кГц. Он берёт архивную версию плана и поддиапазон исходного события. В обзор входят лишь точки этой сетки в пересечении исходного поддиапазона с запрошенным интервалом. Для такого обзора нужны минимум две точки.

Статус `current.scan_coverage.bands[]` показывает количество наблюдавшихся окон и завершённых проходов. До первого полного прохода возможны состояния `not_observed` и `partial`. Значение `age_seconds` указывает возраст самого старого из последних измерений по окнам. `last_window` содержит собственные ID и UTC последнего записанного окна. `current.scan_timing` показывает монотонные длительности последнего опроса, архивной записи и интервала от окончания предыдущего опроса до начала текущего. Опрос включает вызов адаптера и подготовку исходника для записи. Для сравнения с прямым serial используйте прошедшее время полных проходов, одинаковые точки, RBW, тракт, скорость порта и паузы. Порог RC составляет 90% напрямую измеренной скорости.

Для подтверждения эталона оператор собирает минимум 20 проходов каждого окна за интервал от 60 секунд. Служба выбирает до 20 последних исходников окна и при необходимости добавляет ранний исходник для длительности. Ссылки на окна пополняются в той же транзакции, что и исходник. При открытии старого архива установка этой таблицы не читает исторические свипы. Одна команда подтверждения поддиапазона сохраняет все оконные эталоны и активирует их в одной транзакции. Статистика, интервалы повторения, контрольные точки детектора и сравнения в истории привязаны к конкретным окнам и версии плана. При постановке на охрану сеанс получает ссылки на действовавшие в тот момент эталоны. Они сохраняются в истории после нового подтверждения. Исходные ссылки ведут к соответствующим свипам в архиве.

## Проверка

```sh
cargo test --locked -p ori-monitoring -p ori-instruments --test grid
cargo test --locked -p ori-archive --test grid_confirmation
cargo test --locked -p ori-guard --test grid_windows --test scan_plan
cargo test --locked -p ori-core --features serial --lib devices::scan
```

Программные проверки используют фиксированные синтетические данные, симулятор и двунаправленный байтовый транспорт с ответами прибора. Аппаратная скорость на Pi/Windows, фактическая полоса RBW, физический RF-выход, USB disconnect/reconnect и длительный приём проверяются на целевом стенде. Исторические измерения на macOS описаны отдельно в [протоколе ZS405](../tinysa-hardware-acceptance.md).
