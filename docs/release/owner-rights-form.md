# Приватная форма решения о происхождении и правах

**Пустой образец.** Хранитель копирует форму в уже разрешённое приватное хранилище. Заполненный экземпляр, таблица объектов, приложения и подписи остаются там. [Проект решения и критерии проверки](owner-rights-proposal.md)

## Создание реестра

В checkout проверяемой ревизии задайте `PRIVATE_RIGHTS_DIR` путём к существующему приватному каталогу владельца вне репозитория. Пример для POSIX создаёт строки только по уже учтённым Git ID. Он не читает содержимое объектов и не печатает идентификаторы. Запуск сохраняет существующий реестр при повторной попытке.

```sh
umask 077
python - "$PRIVATE_RIGHTS_DIR" <<'PY'
import csv
import os
from pathlib import Path
import re
import sys

root = Path.cwd().resolve()
dest = Path(sys.argv[1]).resolve(strict=True)
if not dest.is_dir() or dest == root or root in dest.parents:
    raise SystemExit("Требуется приватный каталог владельца вне checkout")
if dest.stat().st_uid != os.geteuid() or dest.stat().st_mode & 0o077:
    raise SystemExit("Нужен каталог текущего хранителя с закрытыми правами доступа")
ids = (root / "tools/release/blocked-blobs.txt").read_text(encoding="ascii").splitlines()
if not ids or len(set(ids)) != len(ids) or any(not re.fullmatch("[0-9a-f]{40}", x) for x in ids):
    raise SystemExit("Проверьте исходный список для зафиксированного SHA")
with (dest / "objects.csv").open("x", encoding="utf-8", newline="") as handle:
    rows = csv.writer(handle)
    rows.writerow(("case_id", "git_blob_oid", "category", "origins_record", "evidence_record", "decision_record", "status"))
    for number, oid in enumerate(sorted(ids), 1):
        rows.writerow((f"R-{number:03}", oid, "", "", "", "", "pending"))
print(f"Создано строк: {len(ids)}")
PY
```

Зафиксируйте снимок и версию перечня. Сохраняйте присвоенные номера при его расширении. У одного `case_id` могут быть несколько записей происхождения и несколько решений для разных каналов.

| Приватная запись | Заполняемые поля |
|---|---|
| Снимок | Идентификатор и дата UTC, полный commit SHA, источник списка, число известных и дополнительно найденных объектов, хранитель и доступ. |
| Происхождение | `case_id`, категория, формат/версия, точные пути и срезы refs, копии и производные материалы, как получено, SHA-256 проверенных байтов, связь с исходником, статус персональных данных. |
| Основание | Идентификатор доказательства, правообладатель или автор, полномочия выдавшей стороны, версия и дата договора/лицензии или подтверждения собственного авторства, точный пункт, место оригинала, проверяющий и дата. |
| Одна операция и канал | Строка или перечисленная группа, действие (хранение, частная резервная копия, анализ, публикация истории Git, исходный архив, конкретный установщик, руководство, магазин), аудитория/территория/срок, исключения, условия, свидетельство их выполнения, исход `allow`, `exclude` или `pending`, основание и ответственный. Для пакета добавить платформу, канал и SHA-256 конечного файла. |
| Нерешённый вопрос | Чего именно не хватает, какая операция приостановлена, кто получит документ или исключит материал, срок следующего рассмотрения. |

## Лист решения владельца

- Статус формы — **проект**. Идентификатор, версия, UTC, владелец решения и основание его полномочий — ______.
- Выбранный вариант и перечень одобряемых операций и каналов — ______. Список охваченных `case_id`, дополнительных находок и исключённых областей — ______.
- Контроль полноты — ______ из ______ строк исходного списка учтены. Дополнительных ______. Для каждого канала разрешено ______, исключено ______, ожидает ______. Реестр проверил ______, UTC ______.
- Идентификатор ведомости проверенных пакетов и снимка refs, версии приложений к решению, хеш итогового набора документов — ______. Неурегулированные остатки и затронутые ими каналы — ______.
- Срок и условия пересмотра, исполнитель публикации и пределы его полномочий — ______. Лицо, полномочное утвердить решение, подтверждение и время — ______.

Хранитель замораживает реестр, ведомость пакетов и решение. Владелец либо уполномоченное лицо проверяет набор и подтверждает точную версию подписью или записью в защищённой системе согласования с идентифицируемой учётной записью, хешем набора и датой. Для бумажного решения в подписанном экземпляре указывают тот же хеш. Хранитель связывает подтверждение с неизменными приложениями. Пустая отметка, вывод скрипта и наличие файла оставляют статус проекта.

## Отдельное поручение на изменение сервера

Оформляется отдельным документом **только после** проверки разрешённого комплекта резервных копий, автономного восстановления, свежих refs и локальной репетиции. Передача на другое устройство и обращение в поддержку имеют свой объём разрешения. [Проверки перед применением](history-cleanup.md#условия-серверного-применения)

- Идентификатор поручения, связь с решением владельца, полномочия подписанта, адресуемый репозиторий и срок — ______.
- Идентификаторы приватной резервной копии, отчёта восстановления и репетиции, кто проверил и когда — ______.
- Приватная карта разрешённых refs с ожидаемыми старыми и новыми SHA, список PR, соответствие открытых работ и обработка остаточных объектов — ______.
- Конкретная операция, временное окно UTC, исполнитель, проверяющий, условия остановки и восстановления — ______.
- Подтверждение владельца и уполномоченного администратора с привязкой к байтам поручения, карте refs и времени — ______.
- После действия проверенные refs и каналы, результаты свежего клона и проверки вложений, оставшиеся области, дата и ответственное лицо — ______.
