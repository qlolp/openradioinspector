Актуальные результаты ревизии и следующий план: [../repository-audit.md](../repository-audit.md).

представлением спектра, защитой архива, runner и упаковкой. Старые утверждения

Состав и ограничения: [integration.md](integration.md).

## Проверки и уборка

- Перед удалением веток создан приватный bundle и восстановлен отдельный mirror;
  `git fsck` прошёл, SHA-256 записан приватно. Чужие/локальные данные в Git не добавлялись.
- Ветки классифицируются по ancestry, патчам и действующему поведению. Удаление
  выполняется только с проверкой исходного SHA и зависимостей открытых PR.
- Linux release runner проверяет Python/Node/Tk и семь временных SQLite-архивов;
  серверы останавливаются, содержимое архивов сверяется после прогона.
- Hosted CI проверяет Linux/Windows/macOS × Python 3.10/3.12/3.14, Swift SDK,
  native Swift и unsigned Xcode; отдельно собирает wheel/sdist, EXE и DMG.
  Доказательства относятся к точному SHA каждого PR, а не к старым счётчикам тестов.
- Проверки упаковки включают запуск установленного wheel вне checkout,
  сохранность данных Windows install/update/uninstall и embedded core macOS.
- Административный API защиты `main` недоступен GitHub App (HTTP 403).
  Подготовлены [точные настройки и проверка применения](branch-protection.md).

## Что ещё требуется до выпуска

1. Аппаратная приёмка tinySA + AR-DV1 и двух клиентов на Pi, USB recovery,
   перезапуск, настоящее задание и восьмичасовой прогон: [hardware-acceptance.md](hardware-acceptance.md).
2. Чистые пользовательские установки и обновления, проверка отката.
3. Состав и лицензии фактически поставляемых runtime-компонентов; решение
   открытых вопросов [происхождения](provenance.md).
4. Отдельная очистка опубликованной истории после внешнего приватного backup
   и новой репетиции: [history-cleanup.md](history-cleanup.md).
5. Подтверждённая защита `main` с обязательными проверками.

Коммерческий диск исключён из актуального дерева; опубликованная история
этой уборкой не переписывается. Непроверенные аппаратные сценарии остаются
BLOCKED. Частичная проверка tinySA владельцем не является общей приёмкой.
