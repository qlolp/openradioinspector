# Регламент очистки публичной истории

research.tar находятся в закрытом каталоге облачной машины; это ещё не
проверенная резервная копия на Mac/Pi владельца. Предложенный Pi пока
недоступен через текущую сеть. Нельзя объявлять перенос завершённым.

Bundle проверен восстановлением 234 refs и HEAD. SHA256 исходного bundle:
`d586bc0917c5e50e75e14727c62eaecc684e14e136fd9492830691e09223ce2e`.
Архив research.tar проверен побайтовым сравнением содержимого с исходными файлами.
Внешний архив содержит чужие материалы: хранить приватно, не загружать в
GitHub release или публичные artifacts.

Репетиция `git-filter-repo==2.47.0` обработала 632 коммита. В копии для очистки

## Повторяемая подготовка

В отдельном mirror-клоне, не в рабочем репозитории или единственном backup:

```bash
git filter-repo --force --invert-paths \
  --path 'CD Ligtht 32314/' \
  --path docs/commercial-help-texts.md \
  --path docs/commercial-help.md \
  --path docs/commercial-ui-map.md \
  --strip-blobs-with-ids /path/to/tools/release/blocked-blobs.txt
python3 /path/to/tools/release/check_public_tree.py --repository /path/to/cleaned.git --history
```

Старые версии индекса справки и карты UI удаляются; новые собственные краткие
описания добавляются подготовительным коммитом после переписывания.
Проверка обязана сравнить все собственные файлы, включая пустые __init__.py,
а не только количество файлов или тестов. Хеши исключают известные переименования,
но дополнительные найденные заимствования требуют расширить список и повторить прогон.

## Условия серверного применения

1. Архив реально находится у владельца вне облачной машины; сверены SHA256 и refs,
   проверены восстановление и приватность доступа. Исходный bundle не публиковать.
2. Подтверждено окно без чужих push/merge. Через GitHub доступны PR/reviews/CI,
   issues, releases, artifacts и настройки защиты веток.
3. Повторный `ls-remote` совпадает с зафиксированными старыми SHA. При отличии —
   сохранить новые коммиты, обновить инвентарь, backup, фильтрацию и карту SHA.
4. Перед отправкой все новые подготовительные коммиты и их история также очищены.
   Нельзя смержить старый work SHA в чистую историю: это вернёт удалённые объекты.
5. Сохранены зависимости PR и решения по каждому ref, прогнаны тесты свежего клона.

Отправлять только управляемые refs с **точными** `--force-with-lease=<ref>:<old_sha>`;
по возможности одной atomic-операцией. Не использовать `push --mirror`: он может
затронуть посторонние refs. Отказ atomic/lease — повод остановиться и сверить
состояние, не переходить молча к безусловному force. Удаления веток выполнять
отдельно по доказанным решениям, также с проверкой SHA.

После отправки: проверить серверные SHA и свежий клон; восстановить/пересоздать
PR с новыми базами и связями. Отдельно проверить PR refs, теги, LFS, releases,
Actions artifacts, Pages и кэшированные просмотры. Неуправляемые остатки
передать GitHub Support по процедуре удаления чувствительных материалов.
Отправка запроса Support и переписка выполняются владельцем либо отдельно
авторизованным действием. Чужие форки и клоны автоматически не очищаются.

## Инструкция участникам

После объявленной очистки клонировать репозиторий заново. Старые локальные
изменения переносить патчами после проверки, не merge старых веток. Старый
клон не пушить и не использовать как базу новых PR. До завершения сверки
GitHub не удалять закрытый backup. Резервное восстановление загрязнённой истории
допускается только в закрытом хранилище, а не публичным откатом.

## Повторная репетиция расширенного стека

`tools/release/rehearse_cleanup.py` создаёт только новый приватный mirror вне исходного
репозитория, передаёт явный список всех refs в filter-repo и проверяет сохранность
собственных путей, режимов, blob ID, включая пустые файлы. Известные коммерческие
блобы и пути исключаются; после сравнения очищаются только unreachable-объекты
этой новой копии. Снимок на 8 ноября:195 refs, проверка reachable history прошла,
после GC 2,7 МБ. SHA относятся к срезу до следующих исправлений ревью; повторять
на окончательном снимке, не использовать старые карты для force-push.

Обычный `git filter-repo` переименовывал remote-tracking refs в локальные ветки:
сравнение обнаружило изменение и остановило репетицию. Явный `--refs` сохранил
все195refs. Это проверка инструмента, не очистка GitHub и не подтверждение внешней копии.
