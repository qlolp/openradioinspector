# Приёмка дежурства с тремя источниками панорам

Проверку выполняют на установленной версии ядра и клиента с записанным SHA. Для каждого прогона используют отдельный проект, приватный архив и приёмную антенну в указанном месте. До включения дежурства записывают модель, прошивку, вход, настройки приёма, свободное место, расход по первым записям и время возврата к частоте. При нехватке места выбирают другой локальный том. В публичную ведомость включают агрегаты и результаты проверок, исходные радиоданные остаются на узле.

## Стенд и сценарии

| Основной прибор | Подготовка и критерий |
|---|---|
| tinySA Ultra | Подтвердить профиль и входной режим, выключенный генератор, фактическую RBW и полные свипы. В событиях проверять исходный ID и дБм. |
| RF Explorer 3G Combo | Зафиксировать ответ идентификации, активный SMA и Normal. Проверить последний участок сетки 10 кГц, реальные параметры окон, перекрытия и исходные ID. |
| AOR AR-DV1 | Указать FM, начало, конец и шаг. Сверить частоту и режим по ответу RX прибора. При построении панорамы меньший исходный отсчёт S-метра соответствует более сильному сигналу. Дополнительно пройти полную сетку 100 000–1 300 000 000 Гц с шагом 10 000 Гц и проверить 129 991 уникальную частоту и обе границы в одном проходе. |
| Анализатор и отдельный AR-DV1 | Создать проект с двумя разными портами. При исследовании события и ручном захвате AR-DV1 продолжают появляться новые ID широкого обзора анализатора. |

Для каждой основной конфигурации и для парного сценария провести восьмичасовое дежурство на Mac. Для проверки эталона выбрать диапазон, в котором реально дождаться 20 совместимых посещений за отведённую смену. На полной сетке AR-DV1 отдельно измерить время одного прохода и посчитать время до готовности эталона по фактической скорости. Повторить установку, захват, освобождение портов и хранение на Windows 11 и Raspberry Pi 5.

1. Пройти пять шагов мастера с одним прибором. Проверить причину отказа для занятого порта, несовместимого диапазона и неподходящего архива. Успех первой записи подтверждают ID, UTC и исходные показания.
2. Записать обычный фон, дождаться счётчика готовности и подтвердить эталон. Изменить несовместимый параметр, проверить отказ старого эталона, вернуться к проверенной конфигурации. Прерывание прохода оставляет видимый пробел.
3. В журнале открыть отклонение, проверить исходную запись и переход к каталогу. Одночастотное ручное удержание AR-DV1 должно отразить паузу широкого обзора. После возврата сравнить следующий номер прохода и индекс с последней сохранённой точкой. Пики сравнивают с локальным эталоном того же прибора.
4. Проверить закрытие клиента, явное снятие дежурства и возврат после перезапуска с разрешением и без него. В недельном расписании записать часовой пояс. В журнале видны перерывы охраны, причина и состояние восстановления.
5. По явному выбору оператора отправить пробное сообщение на его канал. Сверить ID и состояние доставки. Смоделировать временный отказ на контролируемом получателе, проверить повтор и отсутствие секретов в экспортированной базе. Прерывание связи с получателем сохраняет архивирование.
6. Закрыть сессию и проверить освобождение портов. Восстановить копию в отдельном каталоге. Сверить исходные ID, целые Гц, единицы, значения, UTC, пропуски и количество оригиналов. Сохранить показатели отдельно по каждому прибору и платформе.

## Воспроизводимые проверки на архиве

Из корня checkout с зафиксированным Cargo.lock запустить последовательно. Нужен временный том с местом для оригиналов, WAL и индексов.

```sh
cargo test --locked -p ori-archive --lib full_grid_remains_bounded_and_its_last_original_is_exact -- --nocapture
cargo test --locked -p ori-archive --test history_scale indexed_million_source_history_uses_bounded_pages -- --exact
cargo test --locked -p ori-guard --test standalone
cargo test --locked -p ori-runtime --test archive_location
```

При оценке интерфейса пять начинающих операторов получают одинаковую задачу без подсказок. Записывают время и затруднения на выборе прибора, сетки, архива, подтверждении эталона, включении дежурства и открытии исходника из события. Цель — самостоятельное прохождение у четырёх из пяти. Программные, стендовые и пользовательские протоколы отмечают отдельно.

[Обзор ARGUS](https://www.rohde-schwarz.com/us/products/aerospace-defense-security/radiomonitoring-software/rs-argus_63493-10783.html) | Начинающий оператор проходит от выбора прибора до первой архивной записи, затем подтверждает фон и включает дежурство. На каждом шаге он видит, какое действие требуется дальше. |
| RF Explorer Touch разделяет настройку частоты, просмотр водопада, работу маркерами и расширенные параметры. [Руководство RF Explorer Touch](https://j3.rf-explorer.com/rfetouch-manual) | Оператор задаёт границы и шаг в привычных МГц и кГц. По водопаду открывает исходное измерение. При просмотре сохранённого прохода настройки прибора сохраняются. |
| Signal Hound Spike позволяет снять фон по серии обзоров. Карточка события хранит частоту, время, уровень и превышение над порогом. [Руководство Spike, раздел 4.11](https://signalhound.com/sigdownloads/Spike/Spike-User-Manual.pdf) | Для события можно восстановить исходную запись и совместимый эталон. Для AR-DV1 уровень и отклонение выражаются в отсчётах S-метра, для анализаторов разница уровней выражается в дБ. |
| RadioInspectorRT сочетает сравнение с эталонной панорамой, порогами и последующий разбор списка сигналов. [Описание RadioInspectorRT](https://www.inspectorsoft.ru/radioinspectorrt) | Оператор видит повторные превышения и одиночные импульсы, открывает исходник и отдельно принимает решение о добавлении источника в каталог или в список разрешённых на объекте. |
