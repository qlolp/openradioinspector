# Модернизация: поставка и проверка

Целевой стек и этапы: [принятый план](plans/2026-11-11-modernization.md).
Рабочие исходники, архивные ID, единицы и публичный API сохраняются.

## Воспроизводимая исходная проверка

```bash
# Явно активированное окружение имеет приоритет.
./run_tests.sh

# Полный синтетический gate с GUI и собственными HTTP-fixtures.
xvfb-run -a python -m tests.run_release_checks --report-dir release-reports

# Создаёт новый синтетический архив и проверяет каждый предложенный свип.
python -m tests.modernization_baseline --report-dir release-reports/baseline \
  --sweeps 512 --bins 290
```

Для Windows/macOS полный runner запускается без `xvfb-run`; Swift/Xcode
проверяются на macOS с `--swift`. Повторный benchmark требует нового каталога:
он никогда не перезаписывает существующий архив. Отчёт содержит версии Python,
NumPy и SQLite, количество предложенных/сохранённых/проверенных источников,
задержку commit, первое чтение истории, RSS и размер архива. Эти значения
характеризуют конкретный узел и синтетический сценарий; UI и приборы здесь
не проверяются. Локальные отчёты хранятся вне Git или в `release-reports/`.

`contracts/fixtures/measurement-v1.json` — общий синтетический источник для
SDK и будущего Rust-кандидата. Он фиксирует UTC-микросекунды, точные целые Гц,
Unicode/специальные символы ID, отрицательный ноль и соседние значения float64.
Старые миграционные fixtures остаются частью полного gate.

## Зависимости и долговечность

Ветка `uv` в `run_tests.sh` устанавливает проект с extras `serial,test` и
зафиксированными зависимостями из `requirements/core.lock`. Активное окружение
и существующая `.venv` сохраняют приоритет. Lock содержит совместимые версии
для Python 3.10/3.11/3.12+; его обновление выполняется явно:

```bash
uv pip compile pyproject.toml --extra serial --extra test --python-version 3.10 \
  --universal --generate-hashes --output-file requirements/core.lock
```

Необязательный SoapySDR использует системные bindings и не входит в этот
набор воспроизводимости. Исследовательский worker получит отдельное окружение.

Рабочий SQLite writer использует WAL и `synchronous=FULL`: успешный commit
предшествует публикации измерения. Пакет сохраняется атомарно; ошибка записи
не публикует событие и не оставляет часть исходников. Единственное соединение
пока сериализуется существующей блокировкой ядра. Проверка остановки процесса
не считается испытанием физического отключения питания SSD.

Закрытие прежнего Tk-клиента также освобождает variable traces во всех
принадлежащих приложению панелях. Эти Tcl callbacks могут удерживать Python
владельца и нативный интерпретатор после `destroy()`. Регрессии проверяют
вложенные переменные, обычное закрытие, прямой `destroy()` и последующую сборку
мусора в worker; тайм-ауты и число повторов проверок не увеличены.
Полный runner запускает реальные GUI-сценарии в отдельных принадлежащих ему
процессах на Linux/Windows/macOS. Это отделяет native Tcl от последующей
сборки мусора в приборных потоках. Tcl-only проверки времени жизни остаются
в процессе, а дочерний процесс обязан выполнить ровно исходный тест с тем же
ID; ошибка, тайм-аут или необъяснённый пропуск проваливают gate.

## Статус приёмки

Воспроизводители и fixtures являются синтетическими. Целевые задержки Pi,
пользовательские испытания, восьмичасовой двухприборный прогон и длительная
аппаратная приёмка отмечаются выполненными только по отдельным протоколам.

## Проверенная копия для восстановления

```bash
python -m radioinspector.recovery_backup create --source data/archive.sqlite \
  --output /mnt/backup/ori-snapshot-001
python -m radioinspector.recovery_backup verify --backup /mnt/backup/ori-snapshot-001
# Сначала остановить службу ядра. Новый путь не должен иметь SQLite sidecars.
python -m radioinspector.recovery_backup restore --backup /mnt/backup/ori-snapshot-001 \
  --output data/restored.sqlite
```

CLI также установлен как `radioinspector-archive-backup`. Копия создаётся через
SQLite Backup API с согласованной read-транзакцией, включая завершённые WAL
commit. Проверяются целостность, внешние ключи, количества записей, watermark
событий и SHA-256 каждого закрытого артефакта, включая аудио. Исходники и
конфигурация не меняются. Манифест публикуется последним; незавершённый каталог
не проходит проверку. Восстановление публикует проверенный файл атомарным hard
link без перезаписи. Существующие `-wal`, `-shm`, `-journal`, включая dangling
symlink, отклоняются до проверки и перед публикацией: они могут изменить базу
при открытии SQLite. Неподдерживающая hard links файловая система даёт явную
ошибку. Рабочие SSD с ext4/APFS/NTFS поддерживают этот способ.

Это **частная копия восстановления** с правами каталога `0700` и файлов `0600`
на POSIX: она содержит настройки, секрет webhook и намерение автозапуска.
Целевой носитель выбирает оператор; для защиты от отказа SSD это другой носитель.
Восстановление само не запускает приборы: действуют preflight и разрешение
автозапуска. Для передачи архива другому человеку используется прежний
`radioinspector.monitoring.archive_backup`, удаляющий секреты и автоматические
действия. Незаписанные в архив текущие аудиобуферы не являются закрытыми
артефактами и не входят в согласованный снимок.
