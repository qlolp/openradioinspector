# Экспорт усреднённого анализа

WebUI, Windows и macOS могут сохранить текущий проверенный результат
сравнения/обнаружения в локальный JSON-файл. Экспорт доступен только после
успешного ответа ядра и относится к конкретному результату: изменение
параметров, очистка или новый запрос не позволяют экспортировать старый
снимок. В файл входят исходные уровни target, производные уровни сравнения,
параметры и области обнаружения, единицы и происхождение источников.

Формат файла:

```json
{
  "format": "openradioinspector-sweep-average-change-detection",
  "format_version": 1,
  "data": {
    "comparison": {},
    "detection": {}
  }
}
```

`data` сохраняет исходный JSON проверенного результата API без повторной
сериализации чисел, ключей и строк. Внешняя оболочка добавляет только format
и format_version. Поэтому большие целые и десятичные numeric settings,
Unicode-ключи и порядок происхождения не теряют точности при экспорте.
Это не нормализованная или канонически отсортированная форма JSON.
Гарантия относится к байтам экспортируемого data. Внутренние модели
отображения JavaScript/Swift по-прежнему используют числа двойной точности
и словари платформы; этот срез не превращает их в lossless JSON-модели.

В `comparison`
частоты остаются целыми Hz; исходные уровни и средняя линейная мощность
представлены в dBm, их знаковая разность — в dB. Поля `reference.source_ids`
и `reference.sources` сохраняют порядок, интервалы UTC и записанные настройки
всех источников. В `detection` остаются порог, минимальная ширина и точные
границы областей. Объект не содержит нового ID измерения или опорного и не
является импортируемым архивным форматом.

Файлы создаются только по действию оператора. WebUI передаёт файл браузеру;
завершение загрузки определяет браузер. Windows и macOS записывают выбранный
путь атомарной записью; отмена диалога не меняет результат и файловую систему.
Перед записью повторно проверяются текущий результат, ревизия/контекст и
отсутствие незавершённого анализа. Смена контекста, параметров, очистка или
закрытие панели во время диалога отменяет сохранение старого результата.
Повторный экспорт не открывает второй параллельный диалог.
Экспорт не передаёт данные серверу, не изменяет SQLite и не создаёт
кандидатов, событий, задач или команд прибору. Включённый формат версии 1
документирован, но отдельные импорт/повторное воспроизведение пока не
реализованы.


## Проверка

Клиентские regression tests: `python -m unittest tests.test_windows_sweep_average`
и `python -m unittest tests.test_webui_sweep_average`; Swift SDK/native:
`swift test --package-path macos/SpektrKomandy` и `swift test --package-path macos`.
Общая синтетическая HTTP fixture и opt-in переменная описаны в
[sweep-change-detection.md](sweep-change-detection.md).

На интеграционной ветке проверены 919 Python/Node, 163 SDK, 108 native-тестов
без пропусков и unsigned Xcode build. Проверены точные numeric/Unicode tokens,
старый результат после нового polling, смена параметров/контекста в диалоге,
повторный вызов, отмена, ошибки атомарной записи и уничтожение скрытого Tk root.
Семь временных SQLite fixtures сохранили полный logical dump до/после.
Это не визуальная или аппаратная приёмка; системные диалоги на Windows OS
и macOS не проверялись вручную.
