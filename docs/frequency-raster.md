# Округление частоты обнаруженных сигналов по таблице сетки

Общее ядро принимает переносимую таблицу частотной сетки и округляет
центральные частоты выбранных архивных кандидатов до ближайшей точки сетки
своей записи. Raspberry Pi WebUI, Windows Tk и macOS SwiftUI позволяют
загрузить или набросать таблицу, отметить кандидатов и получить производные
значения. Запрос read-only: кандидаты, измерения, события и команды приборам
не создаются и не изменяются.

Это пятый срез функционального бэклога: воспроизводимое округление частот
обнаруженных сигналов по таблицам. Исходная `center_frequency_hz` кандидата
возвращается из архива без изменений рядом с округлённым значением — тот же
инвариант, что исходные уровни неизменяемы, а калиброванные значения хранятся
отдельно. Автоматическое применение при обнаружении, правка кандидата и
сверка с нормативной сеткой каналов не реализованы.

## Таблица

1. Переносимый артефакт JSON: `format` = `openradioinspector-frequency-raster`,
   `format_version` = 1, `name` (1–80 символов NFC, без управляющих),
   `frequency_unit` = `Hz`, `entries` — от 1 до 64 записей.
2. Запись: `name` (уникален в таблице, те же правила имени), `start_hz`,
   `stop_hz`, `grid_step_hz`. Целые Гц: `0 <= start_hz < stop_hz <= 2^53-1`,
   `1 <= grid_step_hz <= stop_hz - start_hz`.
3. Диапазоны записей не пересекаются и строго возрастают:
   `start_hz` каждой записи больше `stop_hz` предыдущей. Соприкасающиеся
   диапазоны допустимы (второй начинается после первого).
4. Сетка записи — точки `start_hz + k * grid_step_hz` для
   `k = 0 .. (stop_hz - start_hz) // grid_step_hz`, то есть внутри диапазона
   записи. Абсолютная сетка (кратные шагу от нуля) описывается выбором
   `start_hz`, кратного `grid_step_hz`.
5. Таблица занимает не более 65 536 байт UTF-8.

## Порядок и полнота

1. Запрос: только поля `table_json` (сырой текст артефакта) и `candidate_ids`
   (от 1 до 256 уникальных ID кандидатов сеанса, порядок сохраняется).
   Таблица проверяется до поиска кандидатов: невалидный артефакт отклоняется
   независимо от содержимого архива.
2. Округление: частота привязывается к записи, содержащей её
   (`start_hz <= f <= stop_hz`), и округляется до ближайшей точки сетки
   этой записи. При равном расстоянии берётся более высокая точка
   (round half up в целой арифметике, без деления с плавающей точкой).
   Если ближайшая точка выходит за `stop_hz`, берётся последняя точка
   сетки записи.
3. Результат: по одной строке на каждый ID запроса в исходном порядке —
   `frequency_hz` (как в архиве), `rounded_frequency_hz`, `delta_hz`
   (округлённая минус исходная, знак сохраняется), `grid_step_hz` и
   `entry_name` совпавшей записи.
4. Частоты вне всех записей не округляются: `matched = false`,
   `rounded_frequency_hz`, `delta_hz`, `grid_step_hz` и `entry_name` равны
   `null`. Счётчики `matched_count` и `unmatched_count` сходятся с `count`.

Округление — производное отображение, не правка архива: повторный запрос
возвращает те же значения, а запись кандидата в архиве не меняется. Значение
`delta_hz` может быть отрицательным; округление никогда не выходит за
диапазон записи.

## Совместимость и ограничения

Таблица не является нормативной сеткой каналов, калибровкой или сверкой
с разрешительной документацией: шаг сетки задаётся пользователем, а не
регулятором. Формат архива сеансов не меняется, миграция не требуется:
результат существует только в ответе и в интерфейсе до следующего запроса.
Клиенты не пересчитывают округление сами: проверяется согласованность ответа
(точка на сетке, `delta_hz` равен разнице, совпадение имен записей), а не
подменяются собственные значения.

Старый сервер без маршрута отвечает 404; неизвестный кандидат или чужой
сеанс — 404 `candidate_not_found` / `session_not_found`; невалидная
таблица или форма запроса — 400 `invalid_request`. Размер тела запроса
ограничен 524 288 байтами HTTP-слоем, как у спектральной маски.

## Проверки при интеграции

Обновления состояния соединения не разрешают второй запрос поверх текущего.
Позднее чтение файла не заменяет новый черновик. В Swift отрицательные границы
отклоняются до создания диапазона; имена записей нормализуются так же, как в ядре.
Регрессии: `webui_frequency_raster.cjs`, `FrequencyRasterTests`.
