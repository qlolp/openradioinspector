# Отдельный macOS-кандидат с аудио

Этот срез готовит программный профиль `0.4.0-macos.rc.2`. Он не выпускает
принятый RC2 и не заменяет RC1: аппаратный RC1, macOS 27.3 и реальный
аналоговый тракт пока не приняты.

## Пакеты и служба

По умолчанию `bash packaging/macos/build.sh --personal-rc` по-прежнему
собирает RC1: `serial=true`, `audio=false`, без описания доступа к микрофону.
Отдельный профиль выбирается явно на сборочном Mac:

```sh
bash packaging/macos/build.sh --personal-rc --profile rc2-audio
```

Его результаты находятся в `build/macos/personal-audio-rc`. Сборщику нужны
закреплённые Rust/Xcode; пользовательский пакет по-прежнему не требует Python,
Homebrew, Node или интернета. Python/DuckDB не входят ни в один профиль.

Профиль RC2 требует `serial=true`, `audio=true`; смешанный манифест
отклоняется сборщиком, supervisor и нативным клиентом. Идентификатор службы
связывает профиль, исходный SHA и контрольные суммы обоих helper. Только этот
профиль добавляет `--allow-audio` службе. Окружение и прежний выбор UI не могут
включить аудио в RC1. Оба пакета используют прежний loopback API и отдельное
хранилище `macOS-RC`; перед заменой пакета обязательна подтверждённая остановка.
Откат не восстанавливает старую БД поверх новых измерений.

## Разрешение и источник

В аудиопрофиле панель службы предлагает явный запрос доступа к аудиовходу
Mac. Конструктор, проверка состояния, запуск службы и само разрешение не
выбирают вход и не начинают запись. В RC1 этот код не запрашивает и не читает
разрешение микрофона. При отказе/ограничении есть понятное состояние и переход
в настройки macOS; повторный системный запрос не запускается автоматически.

Разрешение интерфейсу не доказывает доступ LaunchAgent. Его проверяют реальной
записью после явного выбора аудиовхода компьютера ядра в подготовке проекта.
USB AR-DV1 передаёт команды, а не аудио. Аналоговый выход подключается через
совместимый аудиоинтерфейс. Нельзя подставлять встроенный микрофон по умолчанию.

Существующий бэкенд принимает точный mono PCM16 без смешивания каналов,
ресэмплинга или скрытого преобразования float. Автоматическое исследование
использует 24 кГц; выбранный вход должен поддерживать этот формат. Float-only,
стерео-only и другие неподдерживаемые входы недоступны в этом профиле.
Совместимость конкретного интерфейса ещё не подтверждена. Расширение форматов
должно сохранять исходные отсчёты и иметь собственную приёмку.

Сегменты сохраняют существующую привязку к оригинальному подтверждению
настройки, частоте, режиму и эпохе. Предыстория старой настройки не попадает в
новое событие. Закрытие UI не меняет владение ядра аудиопотоком. Потеря входа,
отзыв разрешения, переполнение и неполный захват дают явную ошибку, а не
успешную фонограмму. Обзор tinySA независим от записи AR-DV1.

## Проверки и открытые условия

CI строит оба arm64-профиля, проверяет состав, подпись, офлайн-запуск после
переноса и сохранность восстановленного архива. Нативные тесты разрешений
используют синтетический provider без запроса настоящего микрофона. RC1
сохраняет свой существующий smoke нагрузки без аудио; этот smoke не объявляется
нагрузочным подтверждением RC2.

Остаются открытыми: TCC фоновой службы на установленной macOS 27.3, реальный
вход/уровень/качество, запись после Command-Q, смена настройки, отзыв доступа,
потеря устройства и восьмичасовой двухприборный прогон. После включения аудио
нужен отдельный полный предложенный поток с mono PCM 48 кГц; текущая упаковка
и 24-кГц автоисследование этот критерий не закрывают. Отметки и экспорт
фрагментов, а также научный worker относятся к последующим срезам плана.
