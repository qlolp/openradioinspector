# Протокол наблюдения коммерческого оригинала

Протокол описывает повторную проверку отдельных экранов RadioInspector Light.
Версию приложения, три сеанса наблюдения с приёмником и каталог окон см. в
[инвентаре работающей программы](rinspectorrt-light-runtime-inventory.md).

Справка описывает ожидаемое поведение экранов. Полные тексты, индекс и сводку
хранит владелец исследовательских материалов вне репозитория.

## 1. Условия запуска

| Требование | Значение |
|---|---|
| Операционная система | Windows: штатная поставка оригинала — Windows XP/Vista/7 |
| Ключ защиты | USB-ключ Guardant, номер ключа совпадает с номером пакета 32314; без ключа программа не стартует |
| Сервер баз данных | FireBird 2.5, ставится на рабочую станцию как служба Windows |
| Оборудование | в варианте Light — только сканирующие приёмники AOR и ICOM |
| Лицензия | опции пакета 32314: `SList`, `Sound`, `SimpleDB`; `RemoteMD` и `SoundScaner` выключены, поэтому сетевые сценарии и второй приёмник-аудиоконтроль не проверяются |

Запуск без установленного ключа проверяет ровно одно: какие пункты меню
программа блокирует и каким текстом сообщает об отсутствующих опциях. Полный
набор этих сообщений уже извлечён из бинарника (см.
[`commercial-app-inventory.md`](commercial-app-inventory.md), раздел 4.1) — при
живом запуске их достаточно сверить с фактическим интерфейсом.

## 2. Выбор окна для наблюдения

Оператор выбирает в таблице сценарий и проверяет результат по уже имеющемуся
инвентарю. Для дополнительного свидетельства выделите нужный диалог или
участок окна RadioInspector средствами Windows. В современных версиях Windows
инструмент выделения открывается сочетанием `Win` + `Shift` + `S`.
Сохраните выбранный фрагмент в личном каталоге вне репозитория.
В отчёт внесите действие, состояние элемента и результат. Имена пользователей,
личные пути, номера ключей и серийные номера исключите из публикуемой записи.

| № | Экран | Что проверяем | Ориентир в справке |
|---|---|---|---|
| 1 | Главное окно InspectorRT | состав панелей, семь полей, кнопки запуска программ | `InspectorRT.hlp` — «внешний вид главного окна», «назначение элементов интерфейса» |
| 2 | Панель управления контролем диапазона | параметры задания, единицы уровня (дБмкВ, дБм, дБмкВ, дБВт), состояние анализатора | `InspectorRT.hlp`, `RangeControl.hlp` |
| 3 | Диалог задания на сканирование | диапазон, шаг, полоса, число точек, усреднение, запись в базу | `RangeControl.hlp` — «Введение» |
| 4 | Поле графиков с включённой линией порога | вид порога, точки перелома, подчёркивание сигналов из базы присвоений | `InspectorHelpGraph.hlp`, `ThresholdControl.hlp` |
| 5 | Редактирование линии порога | утроение толщины при захвате, маркеры участка, протяжка кривой | `ThresholdControl.hlp` — «Редактирование линии порога» |
| 6 | Диалог действий при обнаружении сигнала | состав действий, условия срабатывания | `InspectorRT.hlp` — «действия при обнаружении» |
| 7 | Окно сохранения списка сигналов | формат выгрузки, автосохранение, интервал | `SignalsList.hlp` |
| 8 | Окно измерения параметров сигнала | методики, поля результата, сохранение в базу измерений | `MeasHelp.hlp`, `InspectorMeasDB.hlp` |
| 9 | Общие установки | состав вкладок, параметры архива | `I_Purpose.hlp` |
| 10 | Окно авторизации | что именно проверяет лицензионная проверка | `MasterDeviceHelp.hlp` |
| 11 | Просмотр спектрограммы | пределы отображения, разрешение по времени | `InspectorHelpGraph.hlp` |
| 12 | Окно прямого управления анализатором | недоступно в Light без опции `SA` — фиксируем блокировку | `InspectorRT.hlp` |

## 3. Три канала доступа к машине наблюдения

Наблюдение ведётся локальным агентом. Канал выбирается по тому, что требуется
от него: мышь и экран, терминал или файлы.

| Канал | Что даёт | Чего не даёт | Когда брать |
|---|---|---|---|
| Computer Use (плагин клиента) | мышь, клавиатура, чтение экрана | нет прямого доступа к файловой системе и терминалу | когда нужно кликать по кнопкам и смотреть на окно |
| MCP-сервер Desktop Commander | терминал, файлы, запуск и чтение вывода процессов | нет снимков экрана, нет мыши | когда нужно запустить программу, снять её вывод и работать с файлами |
| Терминал самого клиента | то же, что у Desktop Commander, без настройки сервера | — | базовый вариант, если отдельный MCP-сервер не нужен |

MCP-конфигурация MiniMax Code хранится локально в `~/.minimax/mcp.json`
(на Windows — `%USERPROFILE%\.minimax\mcp.json`) и принимает готовые
конфигурации других MCP-клиентов без переделки. Транспорт `stdio`, поля
`command`, `args`, `env`, `enabled`, `description`, `timeout`:

```json
{
  "mcpServers": {
    "desktop-commander": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "@wonderwhy-er/desktop-commander@latest"],
      "enabled": true,
      "description": "Локальный терминал и файлы для наблюдения оригинала"
    }
  }
}
```

Установка сервера: `npx @wonderwhy-er/desktop-commander@latest setup` (нужен Node.js).

Полезные настройки сервера для этой задачи: `allowedDirectories` — сузить до
клона репозитория и каталога снимков; `blockedCommands` — запретить удаление,
форматирование и правку реестра; `telemetryEnabled` — выключить.

Терминал пригоден для запуска приложения и чтения его сообщений. Для
проверки конкретного диалога оператор может передать описание видимого
состояния или отдельно выбранный фрагмент. Для таблицы сверки достаточно
названия элемента, действия и ответа программы.

## 4. Порядок работы с агентом, управляющим экраном

Управление рабочим столом выполняет плагин **Computer Use** на стороне
клиента: в облачной сессии доступа к компьютеру нет, поэтому наблюдение
ведётся из локального интерфейса на машине, где запущено приложение.

```bash
mcode plugin add computer-use@official
mcode plugin enable computer-use@official
mcode --computer-use "открой RadioInspector, сделай снимок главного окна"
```

Ограничения по документации: macOS и Windows, графическая сессия, Linux не
поддерживается, headless-режим (`mcode exec`, ACP, подзадачи) не подходит,
плагин выбирается вручную в каждой сессии, а управление компьютером
освобождается при отмене действия или выходе из TUI. Установка плагина сама
по себе системные разрешения не запрашивает — на macOS их запрашивают
отдельно.

Для выбранного окна сопоставьте ожидаемое действие по справке с наблюдаемым
результатом и запишите расхождение в таблицу.

## 5. Формат результата сверки

По каждому наблюдённому экрану заполняется строка:

| Поле | Значение |
|---|---|
| Экран | название формы и её ресурсное имя |
| Назначение по справке | что сказано в `.hlp` |
| Наблюдаемое поведение | действие и результат, при наличии — имя локального фрагмента |
| Состояние в OpenRadioInspector | реализовано / частично / отсутствует, с указанием модуля |
| Расхождение | существенное или косметическое |
| Действие | что правим в аналоге |

Существенное расхождение — то, что меняет методику измерения, состав
результата или формат архива: например, иной состав полей результата,
другая единица измерения, иной критерий отбора сигнала. Косметическое — цвет,
порядок кнопок, формулировка подписи.

## 6. Что наблюдение закрывает, а что — нет

Закрывает: порядок действий на экране, значения по умолчанию, реакции на
ошибки и на отсутствие опций, состав сохраняемых файлов, поведение при
продолжении записи.

Не закрывает: цифровые демодуляторы (закрытое ПО), измерение параметров
DVB-T на реальном анализаторе (нужен R&S ETL), работу с антенным
коммутатором и I_MasterDevice (в варианте Light эти возможности выключены
лицензией).

## 7. Текст задачи для локального агента

Готовый текст, который передаётся локальному агенту с включённым Computer Use.
Он ссылается на этот же протокол, поэтому наблюдение идёт по нему, а не по
свободному обходу интерфейса.

> Наблюдение коммерческого оригинала RadioInspector Light 32314.
>
> Сверь выбранный оператором сценарий из раздела 2 с инвентарём
> `docs/rinspectorrt-light-runtime-inventory.md`. Если для проверки нужна
> справка, используй выдержку, выбранную владельцем внешних материалов.
> Для выбранного окна запиши, что должно произойти по справке и что произошло
> в действительности. Укажи соответствующий модуль OpenRadioInspector.
>
> Требования к работе:
> * для снимка используй только выбранный фрагмент окна, сохраняй его в личном
>   каталоге вне репозитория;
> * при описании лицензионного сообщения приведи название опции и видимый
>   результат без частных идентификаторов;
> * если функция закрыта лицензией (окно прямого управления анализатором,
>   сетевой клиент, работа со вторым приёмником), зафиксировать блокировку и
>   причину, которую показывает программа;
> * ничего не устанавливать, не обновлять и не менять настройки лицензии;
> * внеси проверенное текстовое наблюдение в
>   `docs/rinspectorrt-light-runtime-inventory.md` по полям раздела 5;
> * изменения в репозиторий вносить веткой и запросом на слияние, тесты
>   оставлять зелёными.
>
> Если действие требует подтверждения, остановись и попроси подтверждение.
> Если проверить выбранный сценарий не удалось, укажи причину в таблице.
