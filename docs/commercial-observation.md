# Протокол наблюдения коммерческого оригинала

Документ описывает, как закрыть последний пробел разбора: **поведение** программы
RadioInspector, а не её состав. Состав уже известен — 133 формы, 985 надписей
интерфейса, 397 тем справки, схема восьми баз; поведение живого приложения
известно только по описанию автора.

Источник истины — авторитетная справка: в файлах `.hlp` описаны операции
каждого экрана, а не только его назначение. Полные тексты — в
[`commercial-help-texts.md`](commercial-help-texts.md), индекс и сводка — в
[`commercial-help.md`](commercial-help.md).

## 1. Условия запуска

| Требование | Значение |
|---|---|
| Операционная система | Windows: штатная поставка оригинала — Windows XP/Vista/7 |
| Ключ защиты | USB-ключ Guardant, номер ключа совпадает с номером пакета 32314; без ключа программа не стартует |
| Сервер баз данных | FireBird 2.5, ставится на рабочую станцию как служба Windows |
| Оборудование | в варианте Light — только сканирующие приёмники AOR и ICOM |
| Лицензия | опции пакета 32314: `SList`, `Sound`, `SimpleDB`; `RemoteMD` и `SoundScaner` выключены, поэтому сетевые сценарии и второй приёмник-аудиоконтроль не проверяются |

Запуск без установленного ключа проверяет ровно одно: какие пункты меню
программа блокирует и каким текстом сообщает об отсутствующих опциях. Полный
набор этих сообщений уже извлечён из бинарника (см.
[`commercial-app-inventory.md`](commercial-app-inventory.md), раздел 4.1) — при
живом запуске их достаточно сверить с фактическим интерфейсом.

## 2. Снимки экрана и запись экрана

Снимки делаются штатными средствами Windows (`Win` + `Shift` + `S`), запись
экрана — любой доступной утилитой. Требуется разрешение 1440×900 и более, как
рекомендует оригинал.

Минимальный набор снимков, закрывающий тему:

| № | Экран | Что проверяем | Ориентир в справке |
|---|---|---|---|
| 1 | Главное окно InspectorRT | состав панелей, семь полей, кнопки запуска программ | `InspectorRT.hlp` — «внешний вид главного окна», «назначение элементов интерфейса» |
| 2 | Панель управления контролем диапазона | параметры задания, единицы уровня (дБмкВ, дБм, дБмкВ, дБВт), состояние анализатора | `InspectorRT.hlp`, `RangeControl.hlp` |
| 3 | Диалог задания на сканирование | диапазон, шаг, полоса, число точек, усреднение, запись в базу | `RangeControl.hlp` — «Введение» |
| 4 | Поле графиков с включённой линией порога | вид порога, точки перелома, подчёркивание сигналов из базы присвоений | `InspectorHelpGraph.hlp`, `ThresholdControl.hlp` |
| 5 | Редактирование линии порога | утроение толщины при захвате, маркеры участка, протяжка кривой | `ThresholdControl.hlp` — «Редактирование линии порога» |
| 6 | Диалог действий при обнаружении сигнала | состав действий, условия срабатывания | `InspectorRT.hlp` — «действия при обнаружении» |
| 7 | Окно сохранения списка сигналов | формат выгрузки, автосохранение, интервал | `SignalsList.hlp` |
| 8 | Окно измерения параметров сигнала | методики, поля результата, сохранение в базу измерений | `MeasHelp.hlp`, `InspectorMeasDB.hlp` |
| 9 | Общие установки | состав вкладок, параметры архива | `I_Purpose.hlp` |
| 10 | Окно авторизации | что именно проверяет лицензионная проверка | `MasterDeviceHelp.hlp` |
| 11 | Просмотр спектрограммы | пределы отображения, разрешение по времени | `InspectorHelpGraph.hlp` |
| 12 | Окно прямого управления анализатором | недоступно в Light без опции `SA` — фиксируем блокировку | `InspectorRT.hlp` |

## 3. Порядок работы с агентом, управляющим экраном

Управление рабочим столом выполняет плагин **Computer Use** на стороне
клиента: в облачной сессии доступа к компьютеру нет, поэтому наблюдение
ведётся из локального интерфейса на машине, где запущено приложение.

```bash
mcode plugin add computer-use@official
mcode plugin enable computer-use@official
mcode --computer-use "открой RadioInspector, сделай снимок главного окна"
```

Ограничения по документации: macOS и Windows, графическая сессия, Linux не
поддерживается, headless-режим (`mcode exec`, ACP, подзадачи) не подходит,
плагин выбирается вручную в каждой сессии, а управление компьютером
освобождается при отмене действия или выходе из TUI. Установка плагина сама
по себе системные разрешения не запрашивает — на macOS их запрашивают
отдельно.

Рабочий цикл: один экран — один снимок, снимок сверяется с текстом справки,
расхождения записываются в таблицу сверки, следующий экран. Без сверки со
справкой снимок даёт картинку; со сверкой — проверенное утверждение о
поведении.

## 4. Формат результата сверки

По каждому наблюдённому экрану заполняется строка:

| Поле | Значение |
|---|---|
| Экран | название формы и её ресурсное имя |
| Назначение по справке | что сказано в `.hlp` |
| Наблюдаемое поведение | что фактически происходит, снимок как доказательство |
| Состояние в OpenRadioInspector | реализовано / частично / отсутствует, с указанием модуля |
| Расхождение | существенное или косметическое |
| Действие | что правим в аналоге |

Существенное расхождение — то, что меняет методику измерения, состав
результата или формат архива: например, иной состав полей результата,
другая единица измерения, иной критерий отбора сигнала. Косметическое — цвет,
порядок кнопок, формулировка подписи.

## 5. Что наблюдение закрывает, а что — нет

Закрывает: порядок действий на экране, значения по умолчанию, реакции на
ошибки и на отсутствие опций, состав сохраняемых файлов, поведение при
продолжении записи.

Не закрывает: цифровые демодуляторы (закрытое ПО), измерение параметров
DVB-T на реальном анализаторе (нужен R&S ETL), работу с антенным
коммутатором и I_MasterDevice (в варианте Light эти возможности выключены
лицензией).
