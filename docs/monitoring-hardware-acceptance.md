# Приёмка мониторинга: синтетика и отдельный аппаратный протокол

**Аппаратная приёмка не выполнена (`hardware_validation: not_run`).** Пустые поля и флажки ниже заполняет оператор после фактической проверки. Ускоренный прогон не подтверждает семь суток работы оборудования, чувствительность приёмника или статистику реальных городских помех.

## Воспроизводимая синтетическая проверка

```bash
python -m tests.monitoring_endurance --report /tmp/monitoring-7day.json
```

По умолчанию моделируются семь суток UTC: 10 080 минутных слотов, 61 исходная точка на свип. В каждом дне пять слотов намеренно отсутствуют: архив должен содержать 10 045 свипов, а не придуманные измерения. Первые 20 свипов образуют подтверждённый синтетический эталон. Каждый возобновившийся после разрыва поток оставляет отдельную запись качества `data_gap` со ссылкой на исходный свип; разрыв сбрасывает окно подтверждения и не выдаётся за радиособытие. Последний свип сохраняется с несовместимой RBW и должен явно отклоняться детектором; продолжение с изменёнными настройками требует нового совместимого эталона/запуска.

Используются реальные SQLiteSessionStore, SessionService, MonitoringService.analyze, постраничная история и источники событий. Проверяются каждый исходный ID, уровни, частоты, время и настройки; курсор после перезапуска не должен повторно создавать события. Отменённые синтетические задания проверяют ограничение рабочих реестров; команды приборам не отправляются, исполнители и последовательные порты не запускаются. `--archive /new/path/archive.sqlite` сохраняет проверочный архив; путь должен быть новым. `--slots 240` запускает короткую проверку, её нельзя называть семисуточной.

Отчёт JSON содержит seed, длительность логического времени и фактического выполнения, число исходных записей/страниц/пропусков/событий, контрольную сумму проверенных исходников, максимумы рабочих реестров, диагностический пик Python-памяти в начале запуска и на первой странице проверки, фактический пик RSS процесса и размеры SQLite/WAL. Пик RSS охватывает весь процесс, импортированные модули и нативную память. Ограниченные окна tracemalloc не являются пиком Python-памяти за весь прогон и не измеряют нативный кэш SQLite; ограничение окон снижает влияние измерения на длительность CI. Значения являются измерениями конкретного запуска, не прогнозом памяти аппаратного узла.

Сравнение использует прежнюю функцию `automatic_detection.detect_regions` с постоянным порогом и новый `monitoring.detector.Detector.step`. Оба получают одинаковые свипы и каталог разрешённого сигнала. Порог прежнего метода выбирается на отдельном калибровочном seed так, чтобы обнаружить все три появления слабого сигнала, и затем фиксируется. В отчёте сравниваются полнота по эпизодам слабого сигнала, импульса и широкой смены обстановки, число свипов с ложным срабатыванием и число ложных эпизодов с общей политикой закрытия после пяти тихих свипов. Эти эпизоды не равны доставленным уведомлениям. Результат относится только к заданной синтетической обстановке; полевые преимущества устанавливаются отдельной размеченной записью с одинаковой полнотой обнаружения.

## Неисправности и длительный автономный узел

Каждое воздействие выполняется отдельно; в журнале фиксируются UTC, длительность, реакция ядра, восстановление и полнота исходного архива.

- [ ] Отключение USB tinySA: ошибка/потеря покрытия явно видна; AR-DV1 продолжает независимую работу; проверен явный безопасный возврат.
- [ ] Отключение USB AR-DV1: ошибка задания/аудио явно видна; tinySA продолжает запись; старые команды после восстановления не воспроизводятся.
- [ ] Отказ/удаление аудиовхода: ошибка видна, отсутствующая запись не выдается за полученную.
- [ ] Перезапуск ядра: старые выполнявшиеся задания прерваны, ручная очередь сохранена; автозапуск выполняется только при явном включении и успешной подготовке приборов/эталона/архива.
- [ ] Исчерпание логического лимита и отдельно отказ записи/нехватка места проверены на отдельном тестовом носителе; измерения не удаляются автоматически, ошибка и остановка записи видны.
- [ ] Webhook: успешная доставка, временная недоступность, конечный отказ, восстановление, устойчивый ID, подпись, ограничение повторов и подтверждение тревоги проверены; секрет не попал в ответы/журналы.
