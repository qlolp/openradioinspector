# SoapySDR: границы реализации и проверки

Интеграция PR #81 устраняет `NameError` направления RX. Исходный тест этого PR
сначала воспроизвёл ошибку на базе PR #84. Его fake затем заменён: настоящий
Python API принимает непрозрачный stream handle в методах **Device**, а не
предоставляет `stream.activate()`, `stream.close()` или `stream.readStream()`.

## Реализовано

- Создание через `SoapySDR.Device(args)`, настройка RX channel 0, CF32 stream,
  проверка кода `activateStream` (успех только 0).
- `gain_db` задаёт ручное усиление. Если `hasGainMode` поддерживается драйвером,
  AGC выключается **перед** `setGain`; автоматическое усиление не включается.
- Повторный `connect()` не создаёт второй прибор. Повторный `disconnect()`
  безопасен. После неуспешного подключения можно повторить подключение.
- При ошибке настройки или подключения освобождаются уже созданные ресурсы.
  Ошибка деактивации не мешает попытке закрытия stream и Python device wrapper.
  `Device.close()` также отмечает wrapper закрытым для его деструктора.
- Ошибка перестройки становится `InstrumentError`, соединение закрывается,
  последнее успешно заданное значение `center_frequency_hz` сохраняется.
- Ошибки cleanup не пробрасываются из `disconnect()`; это best-effort освобождение,
  а не утверждение об успешном выполнении аппаратной команды.

## Sweep намеренно недоступен

`SoapyInstrument.sweep()` выдаёт `InstrumentError` **до** подключения,
перестройки и чтения. Старый код называл некалиброванные IQ-отсчёты физическими
`dBm`, суммировал накопления без усреднения и превращал ошибки чтения в низкий
уровень мощности. Это не корректное измерение мощности. Новая реализация не
подменяет единицу на неподтверждённую `dBFS` и не меняет масштаб молча.

Эта гарантия относится к самому методу `sweep()`. Legacy CLI `scan` сначала
открывает архив и через context manager подключает прибор, затем вызывает sweep
и получает отказ. Этот CLI-путь не следует использовать для Soapy-съёмки;
CLI и общий базовый API в данном срезе не изменялись.

Калибровочный профиль, нормализация IQ, подтверждённый диапазон и усиление,
состояние AGC, settling после перестройки, обработка short reads/timeouts и
метаданные качества измерения требуют отдельного среза с аппаратной проверкой.
Python API чтения возвращает `StreamResult.ret`, а не целое число непосредственно;
его восстановление должно следовать исходникам bindings. Пока чтение не запускается.

Три клиента общей платформы не получают новый физический Soapy-адаптер.
Этот срез касается только legacy-драйвера и не заявляет поддержку аппаратуры.

## Проверка

`python -m unittest tests.test_soapy_connect -v` проверяет искусственный модуль
с непрозрачным stream handle: RX constant, аргументы, ручное усиление,
идемпотентность, ошибки создания/настройки/активации/cleanup/перестройки,
повторное подключение и отказ sweep без I/O. Fake проверяет программный контракт,
не заменяет настоящий SoapySDR или устройство. Библиотека не устанавливалась,
приборы не перечислялись и не подключались, реальные архивы не использовались.

Официальные источники API:

- [Python binding source](https://github.com/pothosware/SoapySDR/blob/soapy-sdr-0.8.1/python/SoapySDR.in.i):
  `Device(args)`, `Device.close()`, destructor и `readStream(...).ret`.
- [Device API 0.8.1](https://github.com/pothosware/SoapySDR/blob/soapy-sdr-0.8.1/include/SoapySDR/Device.hpp):
  `setupStream`, `activateStream`, `deactivateStream`, `closeStream`, return codes.
- [Python support guide](https://github.com/pothosware/SoapySDR/wiki/PythonSupport).
