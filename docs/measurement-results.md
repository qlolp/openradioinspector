# Результаты измерений с явной методикой

Общее ядро принимает результат измерения с явно указанной методикой и
отдельным кодом результата и сохраняет его в архиве с привязкой к сеансу,
потоку прибора и интервалу UTC. Raspberry Pi WebUI, Windows Tk и macOS
SwiftUI позволяют выбрать методику из каталога, ввести значения и просмотреть
записанные результаты.

Это шестой срез функционального бэклога: база результатов измерений с
раздельными методиками. Вывод каталога методик
([measurement-methods.md](../main/docs/measurement-methods.md) §3): методика
должна быть полем результата, а не свойством формата хранения, а код
результата (признак годности) — отдельной сущностью, как таблицы
`*_RESULT` / `*_RESULTCODE` оригинала. Не реализовано: автоматический расчёт
результатов из свипов, нормативные вердикты, методики из раздела «не
реализованы» каталога и клиент-сущность заказчика.

## Каталог методик

1. Каждая методика имеет `methodology` (стабильный id), название, таблицу
   оригинала (`original_table`), единицу (`unit`) и точный набор числовых
   полей значений (`fields`). Каталог реализованных методик — 7 записей:
   `beta2_bandwidth`, `bandwidth_at_level`, `control_bandwidth`,
   `power_over_threshold`, `complex_center_frequency`, `signal_to_noise`,
   `coordinates`.
2. Каталог доступен без сеанса: `GET /api/v1/measurement-catalog`.
   Клиенты показывают его как список выбора; неизвестная методика отклоняется.

## Запись результата

1. Запрос `POST /api/v1/sessions/{id}/measurement-results` принимает только
   поля `methodology`, `result_code`, `frequency_hz`, `interval`, `values`
   и `stream_id` (поток того же сеанса).
2. `result_code` — один из `norm`, `not_norm`, `not_measured`. Код хранится
   отдельно от значений: `not_measured` не допускает значений вообще,
   остальные коды требуют ровно поля методики с конечными числами.
3. `frequency_hz` — целое Гц в безопасном диапазоне; `interval` —
   `started_at`/`ended_at` в UTC, начало не позже окончания.
4. Значения неизменяемы после записи: результат — производная запись,
   исходные измерения архива не изменяются. Повторная запись создаёт новую
   запись с новым `id`, существующие результаты не редактируются.

## Хранение

Таблица `measurement_results` SQLite-архива (schema v4, аддитивная миграция
из v3): `methodology`, `result_code` и `values_json` разделены, присутствуют
`session_id`, `stream_id`, частота и интервал. Индексы — по сеансу/времени и
по сеансу/методике. Запись и событие `measurement_result.saved` выполняются
в одной транзакции; `list_measurement_results` читает по сеансу с
необязательной фильтрацией по методике.

## Совместимость и ограничения

Методика определяется явно и не выводится из формата хранения; добавление
новой методики — новая запись каталога без изменения схемы архива. Код
результата — признак годности по принятым правилам, а не нормативное
заключение: клиенты не сверяют значения с нормативами и не подменяют
значения. Значения хранятся как JSON-объект с точными полями методики;
неизвестные поля и лишние ключи отклоняются до записи.

Старый сервер без маршрута отвечает 404; чужой поток или сеанс — 400/404;
невалидная методика, код или значения — 400 `invalid_request`. Старые архивы
(schema v3) мигрируют без потери измерений, событий и кандидатов.
