# Отметки и экспорт фонограммы события

Это программный срез этапов 3–4. Он работает с уже сохранённой фонограммой:
не открывает аудиовход, не запускает запись и не включает аудио в RC1.
Реальный аналоговый тракт, разрешения фоновой службы и нагрузка с аудио
по-прежнему требуют приёмки на Mac. Запись остаётся собственностью ядра.

В Web/Tauri и macOS откройте событие с фонограммой. Рядом с прослушиванием
доступны сведения о записи, выбор диапазона, подпись отметки и экспорт WAV.
В macOS сведения загружаются отдельной кнопкой. Диапазон задаётся целыми
номерами отсчётов; рядом показано соответствующее время в секундах.
Начало включается, конец не включается: `[start_frame, end_frame)`.
Выбор всей записи и последнего отсчёта поддерживаются без потери края.

Отметка — отдельная неизменяемая операторская запись. Она хранит проект,
событие, исходный ID аудио, SHA-256, диапазон, частоту дискретизации, подпись
и UTC создания. Она не изменяет техническую классификацию или оригинал.
Страницы содержат до 64 отметок (по умолчанию 32); эксклюзивный курсор —
исходный ID в порядке UTF-8. Запись отметки и её журналирование коммитятся
одной транзакцией. Отметки используют существующую таблицу monitoring_records.
Добавочный индекс `(kind,project_id,event_id,id)` и его версия 1 в
`ori_archive_query_schema` устанавливаются одной миграционной транзакцией.
Версии основных таблиц v6, мониторинга v4 и точности v1 сохраняются для отката;
исторические измерения не пересчитываются. Индекс обеспечивает ограниченный
поиск страницы внутри события, независимо от числа отметок других событий.

Экспорт копирует исходные mono PCM16 отсчёты без ресэмплинга, нормализации,
смешивания или перекодирования. Перед чтением проверяются полный RIFF,
формат, размеры, единственность fmt/data, выравнивание и SHA-256 исходника.
Неподдерживаемый или повреждённый WAV отклоняется. Результат — обычный PCM WAV
с дополнительным RIFF-блоком **`ori `** (четыре ASCII-байта, включая пробел).
Этот блок содержит UTF-8 JSON `ori-audio-clip-v1`:

- исходные artifact/session/stream/event ID и SHA-256 оригинального WAV;
- точные start_frame/end_frame и общее число исходных отсчётов;
- частоту дискретизации, mono PCM16 little-endian и неизменённый source_context.

Контекст сохраняет только сведения, уже записанные у исходника. Отсутствующий
режим, эпоха настройки, источник времени или аппаратная проверка не
восстанавливаются предположениями. Синтетический источник остаётся
синтетическим. Чужой редактор WAV может удалить неизвестный RIFF-блок;
сохранённый в архиве оригинал и отметки остаются опорными данными.

Размер исходного/экспортированного WAV ограничен 16 МиБ, JSON контекста —
64 КиБ. Экспорт не создаёт скрытых производных файлов в архиве. Web/Tauri
скачивают отдельный файл, macOS предлагает NSSavePanel и записывает файл
атомарно вне UI-потока. Смена узла/проекта/события отбрасывает устаревшие
ответы. Обе операции требуют ID и SHA-256 выбранного оригинала: даже
одинаковая тишина из другой настройки не подменяет выбранную запись.
При замене ссылки на аудио сервер возвращает 409; нужно обновить сведения.

## Добавочные ресурсы API

При `features.audio_evidence_export=true`:

```text
GET  /api/v1/monitoring-projects/{project}/events/{event}/audio/info
GET  /api/v1/monitoring-projects/{project}/events/{event}/audio/marks?limit=32&after=...
POST /api/v1/monitoring-projects/{project}/events/{event}/audio/marks
GET  /api/v1/monitoring-projects/{project}/events/{event}/audio/clip
     ?start_frame=0&end_frame=8000&source_artifact_id=...&source_sha256=...
```

POST принимает ровно `start_frame`, `end_frame`, `label`, `source_artifact_id`
и `source_sha256`; подпись — 1–200 Unicode-символов. При отсутствии записи —
404, неправильных параметрах/формате — 400, изменении источника — 409.
Неизвестные параметры отклоняются. Clip возвращает `audio/wav`,
`Cache-Control: no-store`, размер и ETag с SHA-256 экспортированных байтов.
Старый маршрут полного `/audio` сохраняет прежнее поведение.

Регрессионные проверки используют временный SQLite, известные PCM-значения,
повторное открытие, пагинацию, разные проекты и устаревшую ссылку. Они
подтверждают программную целостность, а не качество реального приёма.
