# Архитектура

## Общая схема

```
                     ┌──────────────────────────────┐
                     │     Веб-интерфейс (web/)     │
                     │  HTTP + REST + SSE, canvas   │
                     └───────────────┬──────────────┘
                                     │ ApplicationState
 ┌──────────────┐   ┌───────────────┼───────────────┐
 │   devices/   │   │               │               │
 │ SCPI / Soapy │──▶│  panorama.py  │  signals.py   │──▶ export/
 │ RTL / SIM    │   │  (SQLite)     │  threshold.py │    CEF/SigMF/CSV
 └──────────────┘   └───────┬───────┴───────┬───────┘
                            │               │
                     ┌──────┴──────┐  ┌─────┴──────────┐
                     │ trace.py    │  │ occupancy.py   │
                     │ units.py    │  │ assignments.py │
                     └──────┬──────┘  └─────┬──────────┘
                            │               │
                     ┌──────┴───────────────┴──────┐
                     │  measurements.py  geoloc.py  │
                     │  interference.py  wifi.py    │
                     └──────────────┬──────────────┘
                                    │
                     ┌──────────────┴──────────────┐
                     │       reporting.py           │
                     │       keywords.py            │
                     │       cli.py (точка входа)   │
                     └─────────────────────────────┘
```

Модули пакета `radioinspector` (плоская структура, без подпакетов
`core`/`persist`):

| Модуль | Назначение | Внутренние зависимости |
|---|---|---|
| `units.py` | Единицы измерения и преобразования | — |
| `trace.py` | Спектральная трасса, децимация | — |
| `jsonio.py` | Сериализация в JSON без `NaN`/`Infinity` | — |
| `keywords.py` | Словарь 317 ключевых слов протоколов | — |
| `tasks.py` | Плановые задания и профиль контроля частот | — |
| `assignments.py` | База данных частотных присвоений | — |
| `geoloc.py` | Пеленгование, триангуляция, радиовидимость, компас | — |
| `wifi.py` | Разбор кадров 802.11 | — |
| `audio.py` | Демодуляция и звуковой контроль | — |
| `threshold.py` | Линии порога | `trace` |
| `measurements.py` | β/2, −N дБ, контрольная полоса, поле, центр тяжести | `trace` |
| `interference.py` | Выявление помех | `trace` |
| `panorama.py` | База данных панорам (SQLite) | `trace` |
| `signals.py` | Обнаружение и реестр сигналов | `threshold`, `trace` |
| `occupancy.py` | Загрузка диапазона, эффективность использования | `panorama`, `trace` |
| `reporting.py` | Протоколы измерений, запись DOCX | `keywords`, `measurements` |
| `scheduler.py` | Планировщик заданий по времени | `tasks` |
| `cli.py` | Командный интерфейс — точка входа | все прикладные модули |

Подпакеты: `devices/` (драйверы приборов), `export/` (форматы обмена),
`web/` (веб-сервер и клиентская часть).

Зависимости между модулями односторонние. `reporting` читает результаты
`measurements`. `scheduler` читает модель `tasks`. `devices`, `export` и
`web` знают о прикладных модулях, но не вызывают друг друга.

## Модель данных

Модель оригинала — амплитуда–частота–время–географические координаты.
В OpenRadioInspector она реализована так:

| Сущность | Описание | Где хранится |
|---|---|---|
| `Trace` | Спектральная трасса: массив частот и массив уровней, шаг перестройки, единица измерения | в памяти |
| `PanoramaRecord` | Снимок трассы с меткой времени и координатами | таблица `panorama` |
| `ScanSettings` | Параметры задания на сканирование; определяют имя файла базы | таблица `panorama_meta` |
| `ThresholdLine` | Линия порога: частоты, уровни, единица | таблица `threshold_line` |
| `SignalRecord` / `SignalEvent` | Обнаруженный сигнал и отдельное событие его появления | таблица `signal_event`, файл `signals.json` |
| `Assignment` | Частотное присвоение передатчика | база данных присвоений |

### Схема базы данных панорам

```sql
panorama_meta (key TEXT PK, value TEXT)      -- параметры сканирования
panorama (
    id INTEGER PK, recorded_at TEXT, latitude REAL, longitude REAL,
    altitude REAL, speed REAL, heading REAL,
    levels BLOB,        -- float64, little-endian
    start_hz REAL, stop_hz REAL, step_hz REAL, unit TEXT
)
threshold_line (line_index INTEGER PK, frequencies BLOB, levels BLOB)
signal_event (
    id INTEGER PK, panorama_id INTEGER FK, recorded_at TEXT,
    frequency_hz REAL, bandwidth_hz REAL, power_over_w REAL, level_db REAL
)
```

Уровни панорам хранятся в `BLOB` в виде плотного массива `float64`: это
компактно (801 точка × 8 байт ≈ 6,4 КБ на панораму) и позволяет выполнять
агрегирование целиком на стороне SQL.

### Именование файлов

Имя файла базы данных панорам формируется из параметров сканирования
по схеме оригинала:

```
DevSim AntLOG-ANT TractCABLE-3m BW100.0 DemodNone Step125.0 Att0 RLev0
Points801 DetMaxPeak VBW100.0 SweepT0.0 From30.0 To130.0.pan
```

* `From`/`To` — границы диапазона в МГц (режим контроля диапазона);
* `Cnt`/`Span` — центральная частота и полоса обзора в МГц (режим
  исследования одного сигнала).

Правило продолжения записи: при открытии базы вычисляется ключ набора
параметров (`ScanSettings.key`); если в каталоге уже есть файл с таким
именем, запись продолжается в него, иначе создаётся новый.

## Поток обработки

1. **Получение данных.** Драйвер прибора (`devices/`) возвращает `Trace`.
2. **Децимация.** `trace.decimate()` приводит трассу к заданному числу
   точек методом максимума в ведрах (метод бакетов) — так пик сохраняется
   даже при сильном прореживании.
3. **Сравнение с порогом.** `threshold.exceeded_intervals()` выделяет
   интервалы превышения; `power_over_threshold()` вычисляет превышение
   мощности в ваттах.
4. **Регистрация сигнала.** `signals.SignalList.update_from_trace()`
   сопоставляет новый интервал с существующими сигналами и обновляет реестр.
5. **Запись.** `PanoramaStore.append()` сохраняет панораму и события.
6. **Отчётность.** `measurements.measure_signal()` рассчитывает параметры
   сигнала; `reporting.build_context()` собирает контекст протокола;
   `export/` выгружает данные в CEF/SigMF/CSV.

## Обработка ошибок и предупреждения

Результаты измерений возвращаются как `MeasurementResult` / `BandwidthResult`
с полем `warnings: list[str]`. Предупреждения фиксируют отклонение условий
измерения от условий применимости методики — например, недостаточное число
точек в полосе обзора для оценки центра тяжести или невозможность
определения уровня шума. Предупреждения не подавляются, а выводятся в
консоль, веб-интерфейс и протокол.

## Потокобезопасность

Веб-сервер работает на `ThreadingHTTPServer`, поэтому соединение SQLite
создаётся с `check_same_thread=False`, а обращения к нему сериализуются
замком `threading.RLock` внутри `PanoramaStore` и `AssignmentDatabase`.
