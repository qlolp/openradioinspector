# Калиброванная узкополосная RMS-оценка поля

`field_strength` сохранён с прежними числом, единицей `dB` и именем для
совместимости. Новые ответы содержат `deprecated=true`, `physical_field=false`
и предупреждение. Web, CLI и шаблон отчёта обозначают некалиброванную оценку
уровня. Старые архивные записи не изменяются.

## Метод v2

`POST /api/v1/sessions/{session_id}/field-strength-rms-v2` принимает только
`sweep_id`, `frequency_hz` (целые Гц) и `calibration` (объект). Ответ имеет
обычную оболочку `/api/v1`. Расчёт читает единственный исходный бин; он не
меняет архив, охрану, курсор событий и настройки прибора. Capability:
`features.field_strength_rms_v2=true` означает наличие метода, а не наличие
подходящей калибровки у подключённого прибора.

Условия применимости первой версии — узкополосный CW и подтверждённый RMS
детектор. В `sweep.settings` должны быть записаны `instrument_profile`,
`measurement_chain_id`, `reference_plane`, `impedance_ohm`, `detector=RMS`,
`waveform=CW`, `rbw_hz`, совпадающие с калибровкой. ID тракта связывает конкретные
прибор/антенну/кабель/усилитель и их конфигурацию; общий профиль модели его
не заменяет. При смене компонентов требуется другой подтверждённый ID. Отсутствующие
сведения не заполняются по умолчанию. Пиковый/широкополосный/импульсный сигнал
не объявляется RMS-полем. dBFS, S-meter и относительные dB не поддерживаются.

Профиль содержит:

- `id`, положительную целую `version`, `instrument_profile`, `measurement_chain_id`;
- `reference_plane`: точное описание плоскости отсчёта;
- `impedance_ohm`, `detector`, `rbw_hz`, `waveform`;
- `valid_from`, `valid_until`: UTC, покрывающие весь исходный интервал;
- `uncertainty_basis`: описание принятого бюджета погрешности и коэффициента охвата;
- `points`: 1–128 точек строго возрастающей целочисленной частоты.

В каждой точке заданы `frequency_hz`, `antenna_factor_db_per_m`,
`cable_loss_db`, `preamp_gain_db`, `level_correction_db`, `uncertainty_db`.
Последнее поле допускает `null`: неизвестная погрешность не заменяется нулём.
Внутри диапазона профиля коэффициенты и объявленная совокупная погрешность
интерполируются линейно по частоте. Применимость этой модели должна быть
обоснована составителем профиля; за пределами диапазона расчёт запрещён.
Профиль оператора не является метрологическим сертификатом или физическим
RF-readback. Заводских калибровок приложение не выдумывает.

Для мощности: `U_RMS = sqrt(P_W * R_ohm)`.
`E_dBuV/m = U_dBuV + AF_dB/m + cable_loss_dB − preamp_gain_dB + level_correction_dB`.
Если исходник уже имеет физическую единицу поля, антенный и трактовые
коэффициенты повторно не применяются. Условия профиля всё равно обязательны.

Ответ содержит V/m, dBuV/m, погрешность в dB либо `null`, исходный ID/бин/интервал/
семь настроек применимости (остальные исходные метаданные доступны по ID), полный
профиль, применённые коэффициенты и SHA-256 канонического
UTF-8 JSON профиля (сортированные ключи, без пробелов). Клиенты не пересчитывают
физику. Тестовый пример: [общий контрактный fixture](../tests/fixtures/field-strength-rms-v2.json);
это синтетический тракт, применять его к физическому прибору нельзя.

В трёх клиентах: исследование → «Поле RMS», выбрать свип/исходную частоту и
ввести JSON своего профиля. Ошибка совместимости показывается как недоступность.
Изменение источника, черновика или подключения отменяет устаревший результат.
Web передаёт исходные токены JSON-профиля строгому декодеру ядра: повторяющиеся
ключи не исчезают при пересериализации, а неконечные числа не превращаются в null.

## Единицы и HTTP

`0 dBmV = 1 mV = .001 V`; `1 mV = 60 dBuV`; `0 dBm` на 50 Ом соответствует
`.22360679774997896 V RMS`. В `units.convert` антенный коэффициент определён
как E/U: `E_dBuV/m = U_dBuV + AF_dB/m`. Это исправляет прежний неверный знак
и потерю коэффициента. Значение AF=0 по умолчанию — лишь численное допущение
общего конвертера, не калибровка. Новые преобразования проверяются независимой
матрицей физических примеров, а не только взаимно обратными тестами.

Запрос v2 ограничен 64 КиБ и общим 10-секундным сроком чтения тела.
Неизвестный исходник — 404, несовместимость — 409 `field_strength_unavailable`,
неверный профиль/JSON/параметры — 400; превышение тела — 413.

## SCPI

TCP, VXI-11 и serial ASCII не пропускают повреждённые токены, пустые значения,
NaN/Inf или несовпадающее число точек. Частотная сетка не подгоняется под
неполный ответ. До выдачи Trace проверяются заявленная и запрошенная длины;
предел — 600 000 точек и 16 МиБ ASCII-ответа. TCP и serial требуют полный терминатор,
ограничивают суммарное чтение сроком, размером и отвергают неоднозначный хвост.
VXI-11 проверяет END, ограничивает каждый device_read и оборачивает чтение
RPC-сокета абсолютным сроком и лимитом байтов до декодирования. Контракт
библиотеки проверен по python-vxi11 0.9; это не аппаратная совместимость.

Ошибка содержит `scpi_invalid_response`, причину, длину и SHA-256. У адаптера
остаётся `last_quality_issue`. `diagnostic_directory` включает приватную запись
JSON с превью отвергнутого ответа, запрошенными настройками и идентификацией
вместе с отдельным `.response`, сохраняющим исходные байты (в том числе
не-ASCII). При обрыве лимита RPC отмечены область wire-prefix и фактически
прочитанное число байтов. Ошибка записи артефакта остаётся в `artifact_error`,
исходный `ScpiDataError` сохраняется. CLI scan
автоматически пишет её в `<output>/scpi-diagnostics`; исходная панорама туда
не добавляется. При усечении oversized-ответа это явно отмечается. Сохранение
диагностики не скрывает исходную ошибку и не считается удачным измерением.
Конкретные команды и единицы каждой модели ещё требуют принятого профиля.
