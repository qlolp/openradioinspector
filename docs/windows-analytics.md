# Windows: сводка всего архива по явному запросу

`AnalyticsWindowsApp` добавляет в Windows GUI отдельную кнопку «Запросить сводку всего архива». Установленный launcher использует `SchedulerWindowsApp`, который наследует этот слой и сохраняет независимую панель TaskBook.

## Поведение

- Обычный `PlatformClient.snapshot()` не вызывает `/api/v1/sessions/{id}/analytics/summary`: archive-wide агрегация не выполняется каждые 2 секунды и не удерживает lock измерительного архива ради фонового UI polling.
- Нажатие кнопки вызывает `PlatformClient.analytics_summary()` ровно для захваченного `session_id`. Повторное действие блокируется существующим `_action_running`, пока операция не завершится.
- Смена сеанса сбрасывает прежний текст результата. Поздний ответ отбрасывается общей revision-проверкой Windows action-канала.
- Результат показывает счётчики sweeps/observations, исходные `dBm` и `s_meter_count`, долю открытого шумодава и фактический пик последнего sweep в видимом `Label` рядом с кнопкой.
- Ошибка аналитики отображается в том же видимом `Label` и не останавливает live-измерения, scheduler или другие политики.

Панель только читает архив через `/api/v1`. Она не создаёт измерения, не открывает приборные порты и не выполняет классификацию сигнала или точное измерение занимаемой полосы.

## Проверка

`tests.test_windows_analytics` проверяет отсутствие analytics-вызова в routine snapshot, явный HTTP-запрос, захват session ID, форматирование исходных единиц, изоляцию ошибки, наличие видимого `Label` и наследование установленного launcher. Полный AppKit/аппаратный стенд к этому Windows-срезу не относится.
