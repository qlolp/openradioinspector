# Общая платформа: Raspberry Pi, Windows и macOS

## Решение

OpenRadioInspector развивается как одно измерительное ядро с тремя пользовательскими оболочками:

- **Raspberry Pi WebUI** — автономный узел непрерывного наблюдения;
- **Windows GUI** — локальное рабочее место и клиент удалённого узла;
- **macOS SwiftUI GUI** — существующее нативное приложение и стенд проверки AR-DV1/tinySA Ultra.

Ядро владеет драйверами, сеансами, архивом, заданиями, обнаружением и отчётностью. Клиенты не открывают приборные порты напрямую при работе через общий сервер.

```text
AR-DV1 / tinySA Ultra / другие приборы
                    │
          независимые device workers
                    │
       общее ядро и единственный писатель
                    │
          REST /api/v1 + события SSE
                    │
       ┌────────────┼─────────────┐
       │            │             │
 Raspberry Pi     Windows       macOS
 WebUI            GUI           SwiftUI GUI
```

## Режимы развёртывания

1. **Локальный:** ядро и приборы находятся на Windows или macOS.
2. **Автономный:** ядро и приборы находятся на Raspberry Pi, управление ведётся браузером.
3. **Удалённый:** Windows/macOS подключается к ядру Raspberry Pi по сети.

Один экземпляр ядра является единственным владельцем каждого прибора. Несколько UI могут наблюдать один сеанс, но команды проходят через серверную очередь.

## Технологические решения первого этапа

- Сохраняется существующий HTTP/SSE-сервер на стандартной библиотеке Python. Дополнительная серверная зависимость на Raspberry Pi не требуется.
- Существующие маршруты `/api/*` сохраняются. Общие платформенные возможности добавляются в `/api/v1/*`.
- Доменный контракт не зависит от HTTP и может использоваться нативными клиентами, CLI и будущими адаптерами хранения.
- Первый срез службы сеансов работает в памяти и прямо сообщает об этом через capabilities. Это не постоянный архив: SQLite-персистентность добавляется отдельным срезом.
- Существующее macOS-приложение не переносится и не переписывается в рамках серверного этапа.

## Общие сущности

- `MonitoringSession` — сеанс, объединяющий приборы и измерения;
- `DeviceStream` — независимый поток одного прибора;
- `Sweep` — спектральный свип с исходной единицей уровня;
- `ReceiverObservation` — настройка/наблюдение приёмника;
- `Candidate` — обнаруженный кандидат на исследование;
- `Investigation` — очередная или выполняемая проверка кандидата;
- `SessionEvent` — версионированное событие для SSE.

Частоты представлены целыми Гц. Все отметки времени UTC. Свип и наблюдение содержат интервал начала/окончания, поэтому потоки приборов связываются по времени, а не по номеру измерения.

## Ограничения и безопасность

- `dBm` tinySA и `s_meter_count` AR-DV1 не сравниваются и не преобразуются друг в друга автоматически.
- Профиль устройства содержит только подтверждённые возможности. Непроверенные команды не включаются по умолчанию.
- Генератор tinySA не входит в мониторинговый сеанс.
- Отключение одного потока не должно останавливать другой.
- Постоянный архив должен иметь одного писателя SQLite и отдельные пакетные очереди приборов.
