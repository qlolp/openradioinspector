# Эталон и разность архивных свипов

Первый срез эталонной панорамы: оператор закрепляет один записанный свип как
эталон и явно сравнивает с ним другой свип того же потока. Расчёт выполняется
один раз в общем ядре. Raspberry Pi WebUI, Windows Tk и macOS SwiftUI показывают
его результат. Выбор эталона хранится только в текущем окне клиента.

## Расчёт и совместимость

Для каждой частоты `delta_levels[i] = target.levels[i] - reference.levels[i]`.
Исходные уровни остаются в `dBm`, разность возвращается в `dB`: например,
`-55 dBm - (-70 dBm) = +15 dB`. Это изменение записанного уровня, а не оценка
помехи, автоматический кандидат или результат метрологической калибровки.

Сервер требует:

- один сеанс и один поток для обеих записей;
- исходную единицу `dBm` у обеих записей;
- одинаковые целочисленные частоты, число и порядок точек;
- одинаковые записанные настройки измерения, кроме верхнего поля `sequence`;
- непустой объект настроек после исключения `sequence`, корректные конечные
  значения и не более 16 384 точек.

Проверка настроек учитывает вложенные объекты, массивы и неизвестные расширения.
Числа JSON `1` и `1.0` эквивалентны, а логическое `true` не равно числу `1`.
Значение `null`, в том числе вложенное, означает неизвестные настройки и
отклоняется; исключение составляет игнорируемое верхнее поле `sequence`.
Отсутствующие настройки,
изменение RBW или другого записанного параметра не разрешают сравнение.
Совпадение метаданных не доказывает, что физический тракт, антенна или реальный
режим прибора не изменились. За сопоставимость условий отвечает оператор.

Интерполяции, подбора ближайших частот и перевода `s_meter_count` в `dBm` нет.
При превышении ограничения сервер отказывает целиком, а не обрезает результат.
Сравнение записи с самой собой допустимо и даёт нулевую разность.

`max_increase` содержит алгебраический максимум разности, который может быть
отрицательным. `min_change` содержит минимум. При равенстве выбирается первая
точка в порядке массива. Клиенты обозначают их как максимальное и минимальное
изменение, не обещая наличие роста сигнала.

## HTTP API

```text
GET /api/v1/sessions/{session_id}/sweep-comparison?reference_id=...&target_id=...
```

Оба ID обязательны, передаются ровно по одному и кодируются как query values.
ID сеанса кодируется как один сегмент URL. Запрос не выбирает «последний» свип
на сервере: клиент фиксирует ID сравниваемой записи в момент действия.

Ответ имеет обычную оболочку `api_payload` версии 1. Объект `data`:

```json
{
  "session_id": "session-1",
  "stream_id": "spectrum-1",
  "reference": {
    "id": "reference-1",
    "interval": {"started_at": "2026-11-08T00:00:00Z", "ended_at": "2026-11-08T00:00:01Z"},
    "levels": [-70.0, -60.0],
    "level_unit": "dBm",
    "settings": {"rbw_hz": 10000, "sequence": 1}
  },
  "target": {
    "id": "target-2",
    "interval": {"started_at": "2026-11-08T00:00:02Z", "ended_at": "2026-11-08T00:00:03Z"},
    "levels": [-55.0, -65.0],
    "level_unit": "dBm",
    "settings": {"rbw_hz": 10000, "sequence": 2}
  },
  "frequencies_hz": [100000000, 101000000],
  "delta_levels": [15.0, -5.0],
  "delta_unit": "dB",
  "max_increase": {"frequency_hz": 100000000, "delta_db": 15.0},
  "min_change": {"frequency_hz": 101000000, "delta_db": -5.0},
  "points": 2
}
```

- `400 invalid_request`: отсутствующий, пустой, повторный или неизвестный
  query-параметр.
- `404 session_not_found` / `sweep_not_found`: сеанс или запись не найдены
  в указанном сеансе. ID записи из другого сеанса не раскрывает её содержимое.
- `409 comparison_incompatible`: несовместимость, неизвестные настройки,
  слишком большое число точек или неконечная вычисленная разность.

`features.sweep_comparison` в `/api/v1/capabilities` сообщает поддержку.
Старые серверы могут вернуть `404`; клиент показывает ошибку только в панели
сравнения. API доступен и при заполненном архиве, поскольку не пишет измерений.

## Поведение клиентов

1. Выберите сеанс и спектральный поток с записанными `dBm` sweeps.
2. Закрепите отображаемую запись как эталон.
3. После появления другой записи нажмите сравнение. График разности имеет
   отдельную единицу `dB`; исходный график и водопад остаются в `dBm`.
4. Сверьте ID и UTC-время обеих записей. При необходимости сбросьте эталон
   и закрепите новый.

Эталон остаётся доступен, когда его запись вышла за пределы последних свипов
в текущем снимке: сервер ищет точный ID в архиве. Смена сервера, сеанса или
потока сбрасывает выбор; закрытие/отключение отменяет или обесценивает ожидающий
ответ. Непрерывные SSE и polling не запускают сравнение автоматически.
Повторное нажатие не создаёт конкурирующих результатов для старого выбора.

Windows и WebUI ограничивают ожидание результата восемью секундами, macOS
шестью. Windows не может принудительно прервать выполняющийся urllib-запрос:
поздний результат отбрасывается, новая попытка доступна после завершения
предыдущего транспорта. В очередь устаревшие сравнения не накапливаются.

Клиентские ограничения HTTP остаются в силе, включая 2 МБ для Windows.
Необычно большие метаданные могут превысить их даже при допустимом числе точек.

## Хранение и пределы среза

SQLite получает ровно две записи по их ID, без загрузки всего архива. Memory
backend ищет их в уже находящемся в памяти списке. Ответ содержит все точки
пары, и память расчёта пропорциональна их числу. Новых событий, записей,
индексов, миграций или сохранённых профилей эталона не создаётся. Исходные
уровни, единицы, интервалы, настройки и журнал событий не изменяются.

Пока нет усреднённой эталонной панорамы из нескольких измерений, сравнения
разных приборов/сеансов, сохранения именованных эталонов, адаптивного порога,
автоматического обнаружения по разности и экспорта производного результата.
Это отдельные продолжения этапа 5 дорожной карты.

## Воспроизводимая проверка

```bash
python -m unittest tests.test_sweep_comparison
python -m unittest discover -s tests -t .
swift test --package-path macos/SpektrKomandy
swift test --package-path macos
xcodebuild -project macos/DvoynoyObzor.xcodeproj -scheme DvoynoyObzor \
  -configuration Debug -destination 'platform=macOS' \
  -derivedDataPath macos/DerivedData CODE_SIGNING_ALLOWED=NO build
```

Программные проверки используют синтетические sweeps. Аппаратная проверка
двух приборов, метрологическая валидация и запуск GUI на Windows не заявляются.

Проверка среза 8 ноября 2026: 416 Python/Node-тестов, 68 Swift API-тестов,
21 native-тест и сборка Xcode без подписи прошли. Реальный локальный API и
Swift DTO проверены на синтетической паре из 101 точки: +20 dB на 103 МГц,
−10 dB на 107 МГц. Проверка создания, обновления и закрытия Tk-окна выполнена
на macOS. Визуальная проверка браузера и SwiftUI не выполнена: экран машины
был заблокирован. Это не проверка Windows OS или аппаратного стенда.
