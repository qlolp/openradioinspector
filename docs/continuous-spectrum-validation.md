# Проверка непрерывного наблюдения, 15 ноября 2026

Срез: `feat/continuous-spectrum-monitoring`, поверх `9621e2d` (PR #193).
Реализация шести пунктов описана в [руководстве](continuous-spectrum-monitoring.md).
**Готовность к длительному автономному наблюдению не подтверждена:** настоящий
tinySA дважды не завершил ответ `scan`. Изменение публикуется как черновик.

## Автоматические проверки

| Проверка | Результат |
|---|---|
| Xcode BuildProject, 10:02 MSK, включая исправление LIVE-слежения | Успешно |
| macOS, полный программный набор в рабочей копии | 204 XCTest, 5 пропусков; 44 Swift Testing; ошибок нет |
| macOS, чистая копия коммита `8148130` | 203 XCTest, 5 пропусков; 44 Swift Testing; ошибок нет |
| Swift SDK, рабочая и чистая копии | 311 XCTest, 8 пропусков; 25 Swift Testing; ошибок нет |
| Python/Node/Tk release runner, рабочая и чистая копии | 2265 тестов, 0 assertion failures, 26 ошибок подготовки PTY; общий результат FAILED |
| Целевые Python-тесты прибора/API/worker/OpenAPI | 79 тестов успешно |
| Watch: 24 часа синтетического времени | 21 600 свипов после обучения, состояние ограничено, ложных событий на постоянном фоне нет |

В чистой копии SDK первоначально выбрал системный Python без NumPy;
повтор полного набора с Python окружением проекта в `PATH` прошёл.
Чистый macOS-набор содержит на один XCTest меньше: незакоммиченные
пользовательские изменения в этот срез не включены.

Ошибки PTY возникают в `pty.openpty()` (`out of pty devices`); проверка
`/dev/ptmx` также получает `Operation not permitted`. Повтор с расширенными
правами процесса не устраняет ограничение. Это не 26 найденных дефектов
детектора, но и не успешная проверка POSIX-транспорта. Тесты не удалялись и
не переводились в фиктивный успех. Tk и локальные HTTP/Node-проверки в полном
прогоне работали. Сборка генератора контрактов отдельно не подтверждена:
в среде отсутствует `rustfmt`.

Синтетические проверки включают подтверждение устойчивого превышения,
одиночный импульс, шум, исключение известной частоты, закрытие события,
разрыв данных, несовместимость настроек, независимый фон двух полос,
ссылку события на сохранённый оригинал, отказ записи журнала после сохранения
свипа, проверку всех настроек до первой команды и отдельную семантику VBW.
24-часовой тест использует 9 частотных отсчётов; это ускоренная проверка логики
и ограниченности состояния, не сутки USB-наблюдения и не измерение RSS.

## Аппаратная проверка

tinySA Ultra ZS405 HW0.4.5.1, прошивка `tinySA4_v1.4-235-gea71dfd`.
Портом владел только исполнитель ядра, GUI работал через API. Генератор
и калибровочный выход выключались подтверждёнными командами; физический
readback выхода не заявляется. Частные спектры и локальные журналы в Git
не включены.

| Сценарий | Фактический результат |
|---|---|
| Настройки тракта из GUI | 101 точка, аттенюатор 10 дБ, LNA off, Ultra off применены, получены новые свипы; возврат к 201 точке |
| VBW | `1/3` → repeat 3 и возврат auto → repeat 1 подтверждены; это эквивалент повторений прошивки |
| Одиночный Zero Span | 450 точек; offset 174 прочитан из ответа прибора; UTC-интервал сохранён |
| Непрерывный Zero Span | 100 МГц, 201 точка; последовательные артефакты примерно через 1,16 с, ошибок в коротком прогоне нет |
| Две полосы | 88–98 и 98–108 МГц, 201 точка, RBW 30 кГц; 30 свипов (15 на полосу), затем таймаут `scan`; обучение не завершено |
| Длительная одна полоса | 88–108 МГц, 201 точка, RBW 30 кГц; 285 свипов наблюдения, затем таймаут; запланированные 30 минут не пройдены |
| Обнаружение | Фон из 21 свипа за 60,7 с; 12 открытий событий на естественном эфире; доступ к исходному 201-точечному свипу проверен |
| Масштаб после перестройки | Новый реальный свип 94,4–104,4 МГц полностью виден на пересчитанной шкале |
| Слежение за пиком после выбора в истории | На последней сборке «Пик» → ИСТОРИЯ, «Следить» → LIVE; курсор нового свипа на P1, управление измерением разблокировано |

Меню «Измерить» открывается, однако выбор его пунктов через доступную
автоматизацию AX/клавиатуры не удалось подтвердить. Пакетная перестройка
через API с последующим новым свипом проверена; это не заменяет проверку
клика «центрировать по маркеру» в GUI. Аппаратный smoke этой кнопки остаётся
неподтверждённым.

Длительный watch начат в 06:42:02 UTC. Последний полный свип завершён
в 06:56:28 UTC, примерно через 14 минут 25 секунд. Сбой зарегистрирован
в 06:57:59 UTC по истечении 90-секундного ожидания завершающего `ch>`.
До сбоя connection/revision/run оставались неизменными; отладчик не
останавливал процесс и настройки не менялись. Всего worker сохранил
309 измерений, из них 285 относятся к watch. Фон после обучения остался
21-элементным. После ошибки worker остановился, API продолжал отвечать.
GUI показал остановку обнаружения, устаревшие данные и текст таймаута.
Повторный Start в том же ядре закончился ошибкой синхронизации без новых
свипов. Перезапуск приложения и принадлежащего ему ядра восстановил
приём в 06:59:39 UTC; физический перезапуск прибора не потребовался.

После заключительного исправления слежения приложение снова собрано и
перезапущено. Контроль 07:03:50–07:08:51 UTC (300,5 с): worker достиг
50 измерений, 0 ошибок, последняя запись 07:08:47 UTC; 88–108 МГц,
RBW 10 кГц, 201 конечный отсчёт dBm. Это обычный LIVE-приём (`watch=null`),
а не повтор успешно завершённого длительного watch. Приложение оставлено
работать с прибором. Финальный программный набор после UI-исправления:
204 XCTest (5 пропусков) и 44 Swift Testing, без ошибок.

Два диапазона дали такой же класс ошибки ранее, в 06:39:42 UTC.
По имеющимся данным нельзя разделить причину между прошивкой, USB и
транспортом хоста. Полного wire-журнала нет; успешные подтверждения
предшествующих команд не доказывают исправность следующего `scan`.
Автоматическая отправка новой команды после незавершённого ответа не
добавлена: поздний ответ без идентификатора транзакции нельзя выдавать
за подтверждение следующей настройки.

12 событий на естественном эфире доказывают работу пути «измерение →
детектор → журнал → исходник», но не точность классификации. Контролируемый
источник тестовых RF-сигналов не использовался. Неизвестный сигнал означает
изменение относительно обученного фона; идентификация передатчика,
протокола и оценка вероятности пропуска этим тестом не подтверждены.

## Воспроизведение

```sh
# Активировать окружение Python проекта с установленными зависимостями.
TMPDIR=/private/tmp python -m tests.run_release_checks --report-dir /tmp/ori-release
swift test --package-path macos/SpektrKomandy --disable-sandbox
swift test --package-path macos --disable-sandbox -Xswiftc -disable-sandbox --skip testPhysicalTinySAUltraSmokeIfConnected
```

Физический Swift smoke исключён из общего запуска, чтобы не конкурировать
с ядром за подключённый прибор. Аппаратные проверки выполнялись отдельно.
Для повторного длительного теста: одна полоса 88–108 МГц, RBW 30 кГц,
201 точка, repeat 1, LNA off, attenuate auto, обучение ≥20 свипов/60 с.
Отсчитывать не менее 30 минут **после** завершения обучения; контролировать
свежесть UTC, счётчики, connection/revision/run и доступность оригиналов.
Затем отдельно повторить две полосы и многосуточный прогон. AR-DV1,
аппаратные условные триггеры и контролируемые импульсные RF-сигналы в этой
проверке не подтверждены.
