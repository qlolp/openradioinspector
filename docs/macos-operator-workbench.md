# Рабочее место macOS по образцу RInspectorRT

Ориентир: [наблюдение RadioInspector Light, PR #191](https://github.com/qlolp/openradioinspector/pull/191).
Переносится компоновка рабочего места и связь измерений с историей, а не набор
непроверенных приборных возможностей. UI не владеет USB и не меняет общий контракт.

## Реализовано

- Верхние рабочие вкладки: «Приборы», «Контроль диапазона», «Сигналы», «Архив»,
  «Охрана и исследование». Сеанс выбирается в компактной строке. Диагностика
  вынесена из измерительного поля. Панель AR-DV1 раскрывается отдельно.
- Спектр и водопад разделены перетаскиваемым разделителем (25–75%). Их частотные
  координаты остаются общими. Положение разделителя, временное окно, Min/Max и
  вкладка сохраняются локально. Смена вкладок сохраняет состояние просмотра.
- Временные окна 30 секунд, 2 минуты, 10 минут. Кнопки «Раньше»/«Позже» и ползунок
  до часа назад загружают архивное окно. LIVE и «Продолжить показ» снимают
  паузу и возвращают текущий буфер. Просмотр истории и маркеры не управляют
  приёмом. Водопад рисует фактические интервалы свипов, оставляя промежутки
  пустыми. При потере связи графики показывают последние полученные свипы,
  а состояние архива становится неподтверждённым.
- Частотный масштаб в 2D сохраняет частоту под щипком, а в 3D виден и одиночный
  измеренный отсчёт. Поле RBW сохраняет AUTO из настроек исходного свипа.
- Min/Max включаются отдельно; выбранный свип можно закрепить как локальный
  эталон (фиолетовая трасса). При несовпадающей сетке эталон не рисуется.
  Это наложение исходников, не заключение о метрологической совместимости.
  Проверенное сравнение настроек и именованные опорные свипы остаются в
  существующей панели «Настройки и анализ».
- Порог показа редактируется рядом с графиком, превышающие его отсчёты выделяются
  красным. Этот порог не заменяет политику обнаружения и действий проекта.
- Таблица сигналов показывает исходную частоту/единицу, интервал, число ссылок
  на исходники и состояние кандидата. «Исходный свип» открывает оригинал в
  измерительном поле, «В очередь AR-DV1» использует существующую очередь ядра.
  Число ссылок не называется количеством радиообменов. Управление очередью,
  автоматикой и база частот доступны в раскрываемых панелях этой вкладки.
- Архив ищется по UTC и частотному диапазону, листается страницами; выбранный
  оригинал открывается на графике. Ёмкость и NDJSON-экспорт доступны здесь же.
  Существующие проектные настройки хранения остаются во вкладке охраны;
  автоматическое удаление оригиналов не добавлено.
- Профиль приёма содержит версию, имя, целые Start/Stop в Гц и RBW. Он сохраняется
  локально, импортируется/экспортируется как JSON. Локальный слот хранит один
  профиль; несколько профилей можно хранить файлами. Импорт ограничен 16 КБ,
  версия и диапазоны проверяются. Секретов, адресов портов и команд генератора
  в формате нет. Загрузка только заполняет поля: применение требует кнопки.

## Архивный доступ и ограничения

Используются имеющиеся `/api/v1/sessions/{id}/sweep-summaries` (32 записи,
непрозрачный курсор) и read-only `POST .../sweep-context` с before=after=0.
Последний возвращает полный исходный свип, без интерполяции и децимации.
Источник сверяется по сеансу, потоку и ID; ответ предыдущего поиска после
сброса контекста отбрасывается. Другие клиенты и серверные API не изменены.

LIVE использует существующий ограниченный буфер 40 свипов. «Загрузить окно»
фиксирует время и загружает первую страницу; «Ещё» догружает следующие,
до 128 исходных свипов в одном просмотре. Неполная загрузка явно подписана.
Запросы оригиналов выполняются последовательно; приём работает независимо.
Фильтры summary относятся к началу свипа: свип, начавшийся до нижней границы
поиска, в эту выборку не входит. Пустой участок означает отсутствие доступного
свипа, а не доказанную потерю сигнала.

Открытие оригиналов ограничено существующим контрактом sweep-context: dBm,
валидные сохранённые настройки, до 16 384 точек. Для неподдерживаемых исходников
или старого сервера показывается ошибка, исходные единицы не преобразуются.
Архивный поиск в этой панели ограничен частотами 0–800 МГц, как текущая панель
приёма tinySA. Полный архив можно выгрузить существующим NDJSON-экспортом.

VBW остаётся недоступной для проверенного профиля. IQ, цифровые декодеры,
калиброванный dBm AR-DV1 и управление генератором не добавлены.

## Проверки и следующий аппаратный прогон

Реализовано; основные сценарии проверены с tinySA Ultra. Расширенный прогон,
исправления компоновки и точные ограничения описаны в
[отчёте проверки](macos-workbench-validation.md). Полная приёмка всех режимов
и длительной автономной работы не завершена.

Добавлены Swift Testing проверки временного окна и промежутков, геометрии
разделителя, переносимых профилей/неверных версий, архивных курсоров,
сохранения исходных значений, отклонения чужого потока и запоздавшего ответа.

При проверке: Xcode BuildProject проходит. Библиотека: 311 XCTest (8 skipped),
22 Swift Testing без ошибок. Приложение: 38 Swift Testing без ошибок;
204 XCTest (5 skipped), три метода Keychain/WebKit с шестью failed assertions
в текущем окружении запуска. Эти участки не менялись данной доработкой;
полный прогон приложения не считается успешным. Проверки xcode_sources и
webui_spectrum_view проходят. Общий release runner завершается на проверке
зависимостей с exit -6; это не успешная release-приёмка.

Перед приёмкой на Mac:

1. Проверить компоновку 1200×792 и меньшего окна, отсутствие обрезанных полей,
   высоту графиков и перемещение разделителя. Цель 65% измерительного поля
   требует визуального измерения, пока не заявляется подтверждённой.
2. tinySA: Start/Stop, Center/Span, RBW, чтение/применение и ошибки частичного
   применения; импорт профиля не должен перестраивать прибор сам.
3. Новый и старый сеанс с большим перерывом: LIVE, окна, архивные страницы,
   пустой интервал, два маркера, повторное открытие того же свипа, возврат LIVE.
4. Поиск/открытие архива при отключённом приборе, переподключение к ядру,
   смена сеанса во время загрузки, ошибка API без остановки приёма.
5. С подключённым AR-DV1: выбранный сигнал → очередь → исследование; исходные
   отсчёты S-метра и независимость tinySA. Аудио проверять отдельно при
   подготовленном и подтверждённом аудиотракте.
