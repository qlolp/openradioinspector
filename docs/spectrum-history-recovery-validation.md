Расширенный прогон использовал Rust/Cargo 1.99.1, Node 26.13.0, Swift 6.4.2,
основной Python 3.15.2 и отдельный research Python 3.15.1. В первом прогоне
существующий тест history worker превысил 10-секундный deadline. Полный повтор
прошёл с теми же лимитами; причина единичного превышения не установлена.
Межклиентская проверка использует синтетические исходники и Canvas renderer;
она не подтверждает аппаратный приём, WebGPU или производительность.

Физический Swift smoke намеренно не входит в программный набор: сериал-порт
может открывать только владеющее прибором ядро. Ускоренные семь суток проверяют
логику на синтетических источниках, а не семь суток USB-приёма.

Целевые проверки покрывают ошибки и завершение текстового обмена, сохранение
ограниченной диагностики после закрытия, запрет восстановления работающего
исполнителя, владение проектом и независимость второго прибора. История проверена
на SQLite и в памяти: реальные ближайшие бины, исходные единицы, пропуски,
изменения сетки/настроек, поздние вставки между страницами, привязка курсора к
выборке, неверные запросы, реальные HTTP-маршруты, версии наборов и перезапуск.
Swift-проверки покрывают чужие session/stream, недопустимые JSON/частоты,
неявные команды в файле, различающиеся UTF-8 идентификаторы, отменённые запросы,
повторные страницы и предел кэша. После независимого ревью добавлены регрессии
для микросекундного порядка внутри страницы и между страницами, обратного
интервала, чужого окна времени и точного import → MHz → save/export выше
800 МГц вплоть до предела архивного контракта. Воспроизводящие тесты сначала
упали, затем прошли после исправлений.

В интеграционных тестах исправлена изоляция двух искусственных транспортов:
собственный URLProtocol handler у набора истории и отдельный pending-registry
на каждый PTY-тест. Производственный реестр незавершённых ответов не очищается.
Счётчики межъязыковых контрактов учитывают 141 legacy API operation.

## Проверено в интерфейсе

Собранный клиент подключался к отдельному временному синтетическому ядру.
Окно 860×680 вмещает выбор до четырёх частот, диапазон UTC, график, таблицу и
сохраняемые наборы. Проверены первая страница из 100 свипов и следующая до 120,
загрузка набора, частота вне диапазона без выдуманного уровня и переход к
сохранённому исходному спектру. Ось графика выводит UTC явно, независимо от
локального часового пояса. Отдельные интервалы не соединяются линией.

## Аппаратная приёмка остаётся открытой

Эта ветка не проходила 30 минут после обучения для одной и двух полос и
восьмичасовое наблюдение tinySA + AR-DV1. Во время программных проверок другой
сеанс разработки перезапускал общее ядро и проводил аппаратные измерения.
Его процессы, сеансы и исходные данные не изменялись; его результаты не
считаются приёмкой этой ветки.

ASCII `scan` остаётся штатным транспортом. Новый recover — явная безопасная
попытка нового соединения после остановки, не доказанное устранение таймаута
из [предыдущей аппаратной проверки](continuous-spectrum-validation.md).
Успешный ответ API не означает свежий приём: требуется новое сохранённое
измерение. Незавершённый старый обмен остаётся препятствием; поздний prompt
не должен подтверждать новую команду. Watch и ручная аренда не возобновляются.

Продолжение аппаратной приёмки на свободном стенде:

1. Только через ядро-владельца проверить одну полосу по закреплённому профилю,
   затем две полосы; в каждом случае отсчитать 30 минут после обучения.
2. Проверить UTC исходников, диапазон/сетку, ревизии соединения, ошибки,
   остановку и явное восстановление; отдельно подтвердить новое измерение.
3. После успешных коротких прогонов провести 8 часов с двумя приборами,
   сохраняя исходные единицы AR-DV1 и проверяя независимость исполнителей.
4. Отдельно сравнить ASCII и `scanraw` на той же прошивке и настройках:
   реальные бины, длительность, полноту кадров и восстановление после отказа.
   Не менять default по одному удачному бинарному обмену.

## Воспроизведение программного прогона

Использовать окружение Python проекта в `PATH`, включая процессы, которые
запускаются Swift-тестами через `/usr/bin/env python3`. Для генерации контрактов
нужен закреплённый `rustfmt`.

```sh
TMPDIR=/private/tmp python -m tests.run_release_checks --swift --report-dir /tmp/ori-history-release
python -m tests.run_release_checks --modern --swift --research-python /path/to/isolated-python-3.15.1 --report-dir /tmp/ori-history-modern
```

Второй профиль требует закреплённых Rust/Node, установленных зависимостей обоих
клиентов и Chromium для межклиентской проверки. Локальные журналы, частные
измерения, временные окружения и инструменты в Git не включаются.
