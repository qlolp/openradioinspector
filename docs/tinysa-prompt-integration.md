# Интеграция ожидания prompt tinySA

## Источник и объём

Из [PR #89](https://github.com/qlolp/openradioinspector/pull/89), head
`4a4384f03442fb2b389386c772003e8b1483b533`, взяты изменение общего serial framing
и регрессии относительно PR #87 (`2afba069263785e7dbdc79f8d26c8b99a7532bc6`).
Они применены поверх локальной стабилизации `b5482a49612773c2bb9abb8015c51e8390285648`.
Другие параллельные измерительные PR в этот срез не включены.

Quiet не завершает shell-ответ: transport ждёт полного `ch>` или исходного
общего deadline. Его имя `read_until_quiet` сохранено для совместимости.
Проверки всего frame и точек scan остаются в адаптере; suffix `ch>` сам по себе
не означает принятие команды. После неполного ответа stash не очищается,
адаптер помечает соединение `restart_required` и не читает/отправляет новые
команды. Автоматических retry, flush или resync нет. `generator_output=off`
остаётся только результатом command ACK, без RF readback. Общий путь POSIX/COM
не меняет отдельное построчное чтение и ACK AR-DV1.

## Проверка без приборов

Собственные PTY и fake COM проверяют паузы после эха и строк, запаздывающее
эхо, раздельные `c`/`h`/`>` с паузами больше quiet, отсутствие ответа,
непродлеваемый deadline при поступающих байтах, сохранение неполного stash,
непрочитанный поздний prompt и запрет повторного poll на tainted connection.
Существующие тесты сохраняют отказ на неверный ACK/frame и AR-DV1 parity.

Воспроизводимый полный локальный gate: `python -m tests.run_release_checks --swift`.
Runner сам владеет семью synthetic fixtures, временными HOME/TMP и архивами,
проверяет logical dump hashes и завершает только свои процессы.
Focused проверки не заменяют полный gate и CI.

## Граница аппаратных утверждений

PR #89 отдельно описывает аппаратную проверку tinySA ULTRA ZS405,
firmware tinySA4_v1.4-235-gea71dfd на macOS. Это результат исходного PR,
не повторная проверка этой интеграции. Здесь реальные порты, USB/Soapy,
аппаратные архивы и производственный сервер не используются. Hosted CI,
физический Windows COM и AR-DV1 этим локальным срезом не подтверждены.
`hardware_validation=not_run` сохранено. Данные аппаратных измерений и
локальные журналы в Git не включаются.


## Результат локальной интеграции

Полный runner завершился успешно: 1068 Python/Node/Tk тестов без пропусков,
164 Swift SDK и 108 native Swift тестов, unsigned Xcode BUILD SUCCEEDED.
Семь полных logical dump SHA-256 совпали, все собственные серверы остановлены,
временный корень удалён. Stale Tcl commands и ошибки native lifetime не
воспроизвелись. В логе есть два ConnectionResetError от loopback HTTP-клиентов
без провала тестов и прежние build/deprecation warnings; весь лог не считается
warning-free. Локально использованы Python 3.12.15 и Tcl/Tk 9.0.4.

79 профильных serial/tinySA/AR-DV1/fake-COM/PTY проверок прошли без пропусков.
Новые регрессии падают при подстановке прежнего framing только в памяти.
Независимый review подтвердил точное совпадение production framing с PR #89
и сохранение отдельного ACK-пути AR-DV1. Hosted CI этого итогового дерева
пока не выполнялся. Четыре добавленных PTY-регрессии являются POSIX-only;
их платформенные пропуски на Windows не означают отключение live HTTP/Tk.

## Существующие ограничения framing

Общий deadline ограничивает время, но не объём stash: отдельного byte cap
в serial transport нет. Не следует описывать чтение как memory-bounded.
Распознавание окончания сохраняет предположение о terminal suffix `ch>`;
отдельно приходящий legacy opening prompt и поздний пробельный хвост после
`>` этими регрессиями не покрыты. Эти ограничения не объявляются исправленными
или проверенными на всех firmware.
