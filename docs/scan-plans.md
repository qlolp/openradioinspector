# Последовательный план обзора

План — сохраняемая версия из 1–16 приёмных поддиапазонов одного анализатора.
Прибор обходит их последовательно; это не одновременный приём всей полосы.
Существующий проект без плана сохраняет прежний однодиапазонный сценарий.

## Подготовка

В Web/Windows откройте «План обзора», в macOS — «План последовательного
обзора» внутри подготовки проекта. Задайте название, границы в целых Гц,
число точек, RBW и предельное время возврата для каждого поддиапазона.
Сохранение не подключает приборы. Изменение запрещено во время подготовки,
охраны и ручного владения прибором.

Нативный tinySA пока ограничен подтверждённым программным приёмным профилем:
0,1–800 МГц, 2–290 точек, RBW 10/30 кГц. Нельзя включить охрану 2,4/5 ГГц
просто изменением числа в форме. Новые Ultra-профили требуют идентификации
ревизии/прошивки и отдельной аппаратной приёмки. Симулятор допускает более
широкие диапазоны и явно помечает измерения как синтетические.

Запустите сбор приёмных данных явной кнопкой. Каждому поддиапазону нужны
не менее 20 полных совместимых свипов за интервал не менее 60 секунд и
отдельное подтверждение обычной обстановки оператором. Только после
подтверждения всех эталонов доступна постановка проекта на охрану. Проверка
готовности приборов не требует уже созданного эталона, чтобы первый сбор
можно было выполнить.

Новая версия плана сохраняет старую версию и её исходники, но требует новых
эталонов. Эталоны и адаптивные состояния из разных поддиапазонов не
смешиваются, даже если частотная сетка совпадает. Историческое сравнение
выбирает эталон соответствующей версии и поддиапазона.

## Покрытие и исходники

Исполнитель меняет только приёмные настройки и использует одну принадлежащую
ядру USB-сессию. Новый метод обзора допускается только после явной подготовки
input; output/unknown/ошибка обмена запрещают сканирование. RF-генератор не
включается. Работа AR-DV1 независима от последовательности поддиапазонов.

Каждый исходный свип содержит в `settings` поля `scan_plan_id`,
`scan_plan_revision` и `scan_band_id`. Частоты, уровни, единицы, ID и UTC
остаются исходными. Метки добавляются до транзакционной записи; публикация
и переход к следующему поддиапазону происходят после commit.

`current.scan_coverage` в состоянии исполнителя содержит возраст последнего
сохранённого измерения, исходный ID/UTC, фактический и максимальный интервалы
возврата, заданный предел и состояние `not_observed/fresh/stale/paused`.
`deadline_missed` указывает на просроченное измерение либо превышение срока
при последнем возврате. Предел — проверяемая цель, а не обещание скорости
прибора. Наблюдения до commit не считаются покрытием.

Выбор поддиапазона над графиком локален для клиента. Он не перестраивает
прибор. Водопад и счётчики показанных кадров разделяются по версии плана и
поддиапазону. Узкий поиск источника приостанавливает широкий циклический
обзор; его временный сеанс не наследует широкий план.
Возврат к широкому покрытию требует свежего совместимого свипа каждого
поддиапазона, записанного после перезапуска исполнителя. Совпадения UTC со
старым кадром недостаточно: проверяется граница приёма архива. Новый сеанс,
возврат из ручного режима и изменение параметров детектора сбрасывают
подтверждения и адаптивное состояние всех поддиапазонов.

## API и совместимость

Функции объявляются через `features.monitoring_scan_plans` и
`features.scan_plan_coverage`. `GET /api/v1/monitoring-projects/{id}/scan-plan`
возвращает текущую версию или `null` для прежнего однодиапазонного проекта.
`POST` этого ресурса принимает конфигурацию и возвращает новую версию (201):

```json
{
  "name": "Объект",
  "bands": [
    {"id": "fm", "name": "FM", "start_hz": 88000000,
     "stop_hz": 108000000, "points": 201, "rbw_hz": 10000,
     "max_revisit_seconds": 15}
  ]
}
```

Также поддерживается `configure` с полем `scan_plan`. Для создания эталона
через прежний ресурс `baselines` добавляется `band_id`. Идентификаторы
поддиапазонов уникальны в версии, содержат 1–64 ASCII-символа `[A-Za-z0-9_-]`.
Названия — 1–200 символов, срок возврата — 1–3600 секунд. Применяются прежние
строгие JSON/framing-проверки, срок чтения и предел тела 64 КиБ.

Версии хранятся как добавочный вид записи `scan-plan` в существующем
транзакционном архиве. Формат исходных таблиц и правила старых курсоров
сохранены; новая таблица или миграция схемы не требуется. SDK TypeScript,
Swift и Rust генерируются из общего runtime-контракта.

Python-вариант для отката явно отказывает в запуске проекта с таким планом,
включая унаследованный профиль сеанса. Для приёма на Python выберите
совместимый однодиапазонный проект; архив и новые измерения сохраняются.
Автоматического переключения сервера или молчаливого сокращения плана нет.

## Проверки

Штатные синтетические тесты проверяют версии и восстановление после
перезапуска, атомарный отказ неверной конфигурации, изоляцию эталонов и
детекторов, последовательность RX-команд, независимость занятого приёмника,
переход к узкому поиску и разделение графических кадров. Это не аппаратная
приёмка: физические диапазоны, фактический период, зеркальные сигналы,
антенна, macOS 27.3 и восьмичасовой прогон остаются открытыми.
