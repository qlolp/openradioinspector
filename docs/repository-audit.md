# Ревизия репозитория и следующий план

Срез уборки: 8 ноября 2026. Исходный `main`: `d522bd49e5e767a93b0c7d724d62c0cd46733528`.
Исходное дерево уже совпадало с проверенным интеграционным коммитом #105;
локальная `work` была его старым предком. Оценивать проект по `work` было неверно.

## Что исправлено при объединении

Восемь функциональных срезов перенесены поверх актуальной платформы через
PR #106–#113. Исходные PR #88, #91–#95, #97–#98 содержали 41 незакрытое
замечание; исправления и регрессии находятся в соответствующих новых PR.
Повторное ревью добавило проверки гонок импорта файлов, восстановления каталога,
ограниченного чтения архива, сброса устаревших подписей, разделения экспорта
по потокам и сохранения живого аудио после лимита записи. Windows-регрессия
проверяет отмену чтения сокета и доставку PCM после паузы.

| Область | Результат | Доказательство |
|---|---|---|
| Таблицы сетки | Пакетное округление; исходные частоты неизменны; старый API профиля сохранён | `test_frequency_raster`, Node и Swift raster tests |
| Результаты | Методика и код отделены от значений; UTC; аддитивная миграция v3→v4; одинаковое окно последних результатов | `test_measurement_results`, клиентские регрессии |
| Частотомер | Только архивные dBm; шаг сетки учитывается без интерполяции; недостаточные данные отклоняются | `test_frequency_counter` |
| DVB-T | Сверка введённых параметров; изменение формы сбрасывает вердикт | Python/Node/Tk/Swift DVB tests |
| Фонограммы | Согласованные статусы; принятые буферы независимы от производителя; последовательные команды | `test_phonogram`, клиентские тесты |
| Список сигналов | Переносимый JSON; атомарная запись кандидатов и событий; публикация после commit | rollback/retry и Swift null/wire-key regression |
| Карта | Границы включают полигоны; GeoJSON результата доступен отдельно | geometry и клиентские map tests |
| Сетевое аудио | Отмена без блокировки Tk; старые байты не попадают в новый контекст; idle EOF освобождает слот | настоящие сокеты и повторные подключения |

Старые реализации планировщика и DOCX заменены действующими `TaskScheduler`
и `docx_report`; безопасная реализация SoapySDR сохранена. Устаревшие подписи
интерфейса и старые исходные SHA не служат доказательством отсутствующей функции.
Решения по каждой исходной ветке записаны в `release/git-inventory.json`,
по PR — в `release/pr-decisions.json`. Журналы и полный backup остаются приватными.

Ревизия функционального стека — `98be9f3a2899fc8a5b15c824d3ce9f1ebbe806e5`.
На документационном срезе `875d07df8b3b2c3b9411a3a436fda32a9dbadec4`
Linux/Python 3.12 runner выполнил 1422 Python/Node/Tk тестов без пропусков;
семь временных архивов неизменны, собственные HTTP-фикстуры остановлены.
Отдельный тест сверяет реальный набор Xcode sources с файлами приложения:
SwiftPM обнаруживает файлы автоматически и не заменяет эту проверку.

Параллельный коммит `e8711943307bce34399353a624ba2c155b5e8ac8` из `main`
сохранён во всех оставшихся срезах. Он меняет macOS serial/UI/SDK и добавляет
локальный runner; его сообщение о tinySA не заменяет отчёт общей аппаратной приёмки.
Объединённый код функционального стека — `98be9f3a2899fc8a5b15c824d3ce9f1ebbe806e5`.

## Приоритетный план продолжения

Порядок строк задаёт следующий цикл: данные и жизненный цикл → установки и
аппаратная приёмка → развитие функций. Открытые риски ниже не считаются
воспроизведёнными дефектами там, где ещё требуется измерение или реальный стенд.

| Приоритет | Работа и основание | Приёмка и способ проверки | Зависимость |
|---|---|---|---|
| P1.1 | Ограничить загрузку старых кандидатов: `SessionService` ещё материализует candidates/investigations целиком | Сначала измерить RSS и время старта на 100 000 кандидатов; затем пагинация с неизменными handoff, порядком и повторным открытием SQLite; сравнить профиль до/после | Сохранение текущего контракта списков и событий |
| P1.2 | Приёмка жизненного цикла на длительном сеансе: короткие синтетические тесты не доказывают восстановление после восьми часов | Учёт пропусков/дубликатов, RSS, размера архива и recovery после перезапуска; сверка исходных Hz/UTC и событий в SQLite | Синтетический восьмичасовой прогон доступен без приборов; аппаратный повтор — после P1.4 |
| P1.3 | Чистые установки и обновления: CI использует временные runner-ОС | На чистых Windows/macOS/Pi проверить install/update/uninstall/rollback, сохранность измерений, завершение embedded core и systemd после reboot; приложить журнал и хеш пакета | Кандидатные пакеты из CI |
| P1.4 | Аппаратная приёмка tinySA + AR-DV1: полный отчёт стенда отсутствует | Два независимых потока, handoff, USB disconnect/reconnect, остановка одного прибора без остановки другого; заполнить `release/hardware-acceptance.md` на точном SHA; затем восьмичасовой Pi + Windows/macOS прогон | Реальный стенд и P1.3 |
| P1.5 | Состав поставок и происхождение: `release/provenance.md` содержит открытые пункты | Сверить фактические wheel/EXE/DMG, библиотеки, лицензии и уведомления; закрыть пункты документами владельца | Реальные пакеты и документы владельца |
| P1.6 | Защита `main`: GitHub App получает HTTP 403 административного API | Администратор применяет `release/main-protection.json`, сохраняя более строгие действующие правила; GET подтверждает 13 обязательных checks, strict и resolution | Доступ Administration; инструкции в `release/branch-protection.md` |
| P2.1 | Очистка опубликованной истории: исключённые материалы остаются в старых объектах | Проверенная восстановлением внешняя приватная копия, новая репетиция на свежих refs, карта SHA; проверка свежего клона и PR refs | Отдельная согласованная операция; текущая уборка историю не переписывает |
| P2.2 | Снизить связанность GUI и сервиса: крупные `ContentView`, Windows app и SessionService | Вынос законченных панелей/маршрутов без изменения контрактов; существующие lifecycle и HTTP тесты проходят | После работ с данными; отдельные небольшие PR |
| P2.3 | Реальный аудиоисточник и воспроизведение: реализован транспорт PCM | Один проверенный источник, ограниченная очередь, отмена/смена потока без зависания; одинаковые счётчики и воспроизведение в клиентах | Возможности прибора подтверждены на стенде |
| P3 | M1/M2, диапазон и UTC водопад: полного инструментария ещё нет | Общие fixtures трёх клиентов; реальные интервалы UTC, пропуски видимы; pause влияет только на просмотр | Зафиксированный контракт представления спектра |

Работать отдельными вертикальными срезами от свежего `main`. Для каждого:
модель/логика → контракт → необходимые клиенты → регрессии → документация → CI.
Следующий проверяемый шаг — профиль старта и памяти P1.1; затем длительный
синтетический сеанс P1.2. Новые функции не подменяют аппаратную приёмку.

## Границы готовности

Версия остаётся `0.4.0.dev0`. Выпуск или RC этой уборкой не публикуются.
Успешный CI подтверждает синтетические сценарии и сборки; аппаратные строки
остаются BLOCKED до фактического отчёта владельца оборудования.
Фонограммы — runtime-состояние; карта использует введённые координаты; DVB-T
сверяет введённые числа; аудиоклиенты пока подтверждают доставку PCM.
