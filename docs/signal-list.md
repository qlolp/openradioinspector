# Список сигналов: выгрузка и загрузка

Переносимый JSON-список сигналов для обмена между приборами и
экземплярами — то, что в оригинале делают «Save RadioInspector signal's
data to file» и «Load from network (from other instrument)» в ISBDViewer.
Клиенты экспортируют архивных кандидатов выбранного потока; импорт создаёт новых
кандидатов через обычный жизненный цикл. Raspberry Pi WebUI, Windows Tk
и macOS SwiftUI показывают черновик списка и управляют обменом.

Это двенадцатый срез функционального бэклога: загрузка списка сигналов
по сети. Не реализовано: прямой сетевой обмен с приборами (список
переносится файлом или API), автоматическое сопоставление с присвоениями
и правила дедупликации списка §7.2.

## Артефакт

1. `format` = `openradioinspector-signal-list`, `format_version` = 1,
   `name` (1–80 символов), `frequency_unit` = `Hz`, `entries` — от 1 до
   256 записей.
2. Запись: `frequency_hz` (целое Гц), `bandwidth_hz` (целое Гц или
   `null`), `interval` (`started_at` / `ended_at` UTC), `level_unit`
   (`dBm` или `s_meter_count`), `peak_level` (число или `null`).
   Неизвестные измерения остаются `null` — они не додумываются.
3. Экспорт возвращает ровно эти поля: сохранённый файл можно загрузить
   обратно без изменений. Метаданные сеанса живут в ответе, не в
   артефакте.

## Обмен

1. `GET …/signal-list/export?name=…&stream_id=…` — сериализация архивных кандидатов
   сеанса; исходные записи не изменяются. Пустой сеанс — ошибка: пустой
   список не создаётся.
2. `POST …/signal-list/import` (`stream_id`, `list_json`) — явная запись:
   каждая запись становится кандидатом в состоянии `new` на выбранном
   потоке, с собственным событием `candidate.created`. Частоты, полосы и
   интервалы копируются без изменений.
3. **Единицы измерения не конвертируются никогда**: запись с
   `level_unit`, отличающимся от единицы потока, отклоняется целиком —
   как инвариант «dBm и s_meter_count не преобразуются друг в друга».

## Совместимость и ограничения

Импортированные сигналы всегда начинаются с состояния `new`; состояния и
связанные исследования не переносятся. Записи с `null` в неизвестных
полях остаются `null` после цикла экспорт → импорт. Старый сервер без
маршрута отвечает 404; невалидный артефакт — 400 `invalid_request`;
несовпадение единиц — 409 `signal_list_error`.

## Атомарность и переносимость

Весь импорт валидируется до первой записи. Кандидаты и их события сохраняются
одной транзакцией; публикация SSE и изменение памяти происходят после commit.
Ошибка любой строки или записи не оставляет импортированный префикс.
Экспорт соблюдает те же ограничения числа записей и байтов, что и импорт.
Swift использует snake_case и явно кодирует неизвестные значения как JSON null.

Клиенты передают выбранный `stream_id` при экспорте: dBm и S-метр остаются
в независимых списках, пригодных для импорта в поток с той же единицей.
Для совместимости API без `stream_id` по-прежнему экспортирует весь сеанс;
смешанный список нельзя импортировать целиком в один поток. Неизвестный
`stream_id` отклоняется до формирования артефакта.
