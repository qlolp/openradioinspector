# Shared client transport and pairing

This client uses the versioned core API; it has no device or database access. The original modern UI and its Windows compile correction remain separate from this integration branch.

## Lossless wire boundary

Browser HTTP and the parsing worker use the generated strict contract codec. Arbitrary-size metadata integers remain `bigint`; explicit finite float64 values, negative zero, Unicode and literal serde-reserved metadata keys survive parsing. Known sweep/observation positions use generated adapters. Unknown metadata is never classified by object shape. Original sweep downloads use the generated typed encoder, including extreme finite float64 values and first-point peak ties.

Only display fields enter the bounded rendering buffer. Settings/metadata are excluded from that copy, avoiding class-prototype changes across `postMessage` and retaining the original HTTP evidence/export separately. Decimation preserves original source IDs, original point indices and the first global peak. It never changes archived data.

Native IPC carries strictly encoded JSON **text**, validates syntax, unique keys, finite float tokens, nesting and byte limits, then sends those same bytes. It does not parse/reencode requests through `serde_json::Value` or reqwest `.json()`. SSE text also passes through unchanged. Native request/response JSON is capped at 8 MiB; audio reads at 32 MiB; in-flight native requests at 16.

Event cursors are `number | bigint`, validated through unsigned 64-bit range. Native IPC sends the cursor as a decimal string, then parses it to `u64`; it never routes a large JS number through JSON. UI sequence arithmetic uses exact integers.

## Every committed event participates in sequence order

The browser uses an authenticated same-origin streaming fetch and a bounded SSE decoder. It accepts **all named event types**, including `audio_segment.received` and future additions. Filtering by a static list previously omitted committed event IDs and caused a false gap/resync at every audio segment. `EVENT_TYPES` is documentation only.

The decoder handles fragmented UTF-8, LF/CRLF, multiline data, comments, and an 8 MiB frame budget. Browser delivery awaits worker parsing and application before consuming another frame or advancing the reconnect cursor. Native delivery has one outstanding frame and a capacity-one acknowledgement channel; stream IDs reject stale cleanup/ACK commands, and decimal delivery IDs reject duplicate acknowledgements. `ack_event` is the only additional IPC permission. Cancellation interrupts a pending native acknowledgement and rejects the pending worker application; obsolete generations cannot apply a later reply. The native reconnect cursor advances only after acknowledgement.

Incomplete or unapplied frames replay from the last **applied** event. Real sequence gaps stop delivery and reconnect from that same synchronous cursor, without replacing history with a latest-one seed or jumping to health's high-water mark. The core's durable SSE replay is required for recovery beyond its memory tail. A lower high-water mark explicitly clears the old archive epoch and reseeds; changing nodes also clears the epoch. A seed is provisional and cannot overwrite live rows. The render ring retains the newest 256 matching sweeps; every replay event is applied in order before that display retention policy. A 30-second network-idle watchdog is suspended while application backpressure is active. Cookies remain same-origin; redirects and cross-origin mode are refused.

Opening connection settings or returning to pairing unmounts the workspace and stops its subscription. A volatile checkpoint retains its exact applied cursor, the existing bounded 256-row display ring and receiver display state. It contains no settings/unknown metadata/credentials and is never serialized to storage. Returning to the same connection reuses that checkpoint, hydrates the current project/search scope before replay, and avoids another latest-one measurement read for an already seeded scope. A different normalized native origin gets a fresh connection identity; a lower archive watermark clears the retained view. A page reload creates a new reader as before. Checkpoints are consumed after React commits the mount; parser workers are created only when delivery starts, preventing an interrupted render from discarding recovery state or allocating an abandoned worker.

The real-core regressions include source A → complete WAV/audio event → source B with pixel evidence, plus a disconnect spanning 1,205 committed sweeps and a deliberately slow worker. They verify ordered application without omissions/duplicates, one in-flight parser item, bounded rendering, unchanged reconnect cursor and no latest-one recovery fetch. Unit/socket cases cover exact cursors above JS safe integers, future types, invalid/gapped frames, cancellation, obsolete generations and acknowledgement bounds.

Connection-gate regressions also cover A → settings → committed B/C → return: all three rows survive at the original cursor without measurement refetch. A controlled source-scope fixture delays the ordinary search-status response while real temporary archived events change scope; startup hydration prevents consuming those rows under the previous filter. Physical devices and Windows driver execution remain separate acceptance work.

## Negotiated binary measurement stream

The client selects WebSocket only when `features.measurement_binary_stream` advertises the exact version-one Protobuf descriptor, relative `/api/v1/events/ws` path, `ori.measurements.v1.protobuf` subprotocol and a positive frame budget no larger than 16 MiB + 64 KiB. Absent or unsupported descriptors retain SSE. The connection is same-origin `ws`/`wss` with only an exact decimal `after` cursor in its query. Browser authentication uses the existing cookie; native authentication uses its existing bearer header. Credentials never enter the URL.

The server may send one outstanding binary frame. Its ACK is **raw canonical positive u64 decimal text**, 1–20 ASCII bytes, without JSON, whitespace or leading zeroes. The browser transfers the received `ArrayBuffer` to its worker; the shared codec decodes the header and packed integer-Hz/float64 arrays there. Packed arrays never become JSON text or get parsed again as JSON. The worker transfers only bounded display arrays and source indices back. Header metadata stays inside the worker, avoiding structured-clone changes to opaque float wrappers. The existing applied-cursor, source scope, archive epoch, cancellation and 256-row retention rules also govern this transport. A disconnect during parsing waits for the current application before choosing its reconnect cursor.

The Windows bridge reuses the platform-verified reqwest connection for the upgrade, including bytes already buffered after HTTP 101. It validates frames with `ori-stream` without allocating numeric point vectors, forwards the original bytes as bounded base64 IPC and waits for the existing one-frame WebView acknowledgement before sending the core ACK. Decimal native delivery IDs remain monotonic across WS→SSE fallback, preventing a stale acknowledgement from releasing a later frame. No additional IPC command or device access is introduced.

Malformed or oversized frames receive no ACK and do not advance the applied cursor. Proven protocol errors can select SSE at that same cursor; native explicit unsupported-upgrade statuses can also do so. Failed authentication, certificate validation or an otherwise unclassified failed browser open retries without downgrading security. Browser application close codes use the permitted 400x range; server ACK-policy codes remain 1008/1009. Core's one-frame window and 30-second ACK deadline bound delivery, rather than an unbounded browser message queue.

Valid integer-Hz sources outside the exact JavaScript display range remain source evidence. The client advances the valid event, shows an explicit unsupported-display state and provides the original sweep action; it does not cast an unsafe integer into a plot or stall unrelated global events. Research history uses the same classification and keeps original evidence available instead of throwing during selection or requesting an imprecise display comparison. Wire codec fixtures include values beyond u64. This does not claim that the current SQLite indexed schema can archive arbitrary integers beyond its signed-i64 frequency columns. Archived functional fixtures use exact i64 frequencies above JavaScript's safe-integer range.

Portable native socket tests verify coalesced 101/first-frame delivery, exact large sequence ACKs, 1,205-frame slow replay, cancellation while application is blocked, malformed/oversized rejection without ACK, monotonic fallback delivery IDs, unique negotiation headers and rejection of unsolicited extensions. HTTP 401 and a real deliberately failed TLS handshake retry without fallback; the latter is not a trusted-CA/hostname acceptance test. Browser functional fixtures use a clearly synthetic, independent WS router over a real temporary core/archive and actual browser sockets; they do not stand in for the production Rust router's separate integration gate. The legacy history list retains its 20 GHz filter cap; the wider unsafe-Hz history renderer case explicitly injects a list response using the exact real archived original. No binary-stream throughput or Raspberry Pi performance claim follows from these functional checks.

## Pairing and credentials

The public `/api/v1/security/status` is checked before data subscriptions. TLS nodes require the operator's explicit pairing window/code. The client cannot open that window. Browser pairing sends `client: browser` and uses only the server's Secure, HttpOnly, SameSite=Strict cookie; tokens are never stored in local storage or URLs. Native pairing sends `client: native` inside Rust, keeps the returned bearer out of the webview, and persists it per normalized origin in **Windows Credential Manager**. Preferences contain only node URL, screen, theme and other non-secret selections. Generic native API IPC cannot issue credentials, including encoded-route aliases; only the allowlisted pairing command can do so.

Reqwest 0.13.5's `rustls` feature enables `rustls-platform-verifier`. Its default verifier uses platform trust, including an operator-installed local CA. Certificate and hostname verification stay enabled. Remote plain HTTP is rejected. An old security-route 404 is accepted only on an actual HTTP loopback origin, with an explicit visible compatibility checkbox and Continue action. This choice is required on each page; no environment bypass or silent preseed exists.

Connection settings permit revoking the current client. Browser revocation expires its cookie; native revocation removes the local Credential Manager record and requests server revocation. If the server cannot confirm revocation, the UI reports the failure and requires reconnection. Credential values are never logged. A periodic bounded public status read returns an expired/revoked client to pairing without changing the global guard.

Automation follows the real compatibility UI in `e2e/helpers.ts`: check `legacy-compatibility-consent`, click `legacy-compatibility-continue`, wait for `workspace-heading`, then select the owned project ID using `project-select`. These test IDs remain stable across localization. `canvas.spectrum[data-sweep-id]` is set after drawing and two animation-frame acknowledgments; observers must use that attribute, not the visible source footer.

## Verification

Run the existing locked web/unit/Playwright and standalone native Cargo commands in the modern-client workflow. Actions are pinned to immutable repository-approved hashes; the Rust compiler is exactly 1.99.1. The workflow also runs real Windows tests, installs the offline WebView2/NSIS package, and launches it.

Local checks use a real temporary Python core for monitoring, research, history, audio and stream regression workflows. The browser pairing test uses a clearly synthetic HTTPS-origin transport fixture to verify Secure/HttpOnly cookie, API/SSE propagation and revoke behavior; it does not claim a real TLS handshake. Portable Rust socket tests cover raw JSON byte fidelity, credential-route isolation, relative URL enforcement, cancellation and SSE framing. Windows Credential Manager code is cross-typechecked against `windows-sys` and has a Windows-only write/read/delete test; executing it and the full Windows wrapper requires the Windows CI runner. No physical device, production credential, Raspberry Pi throughput or power-loss claim is made.


## Russian and English

Russian is the default, with explicit `locales/ru.json` and `locales/en.json` resources and a language selector before pairing and in the workspace. Primary preparation, monitoring, guard, evidence, history, manual ownership and error flows share the same terminology. Project names, comments, device IDs, raw units and input values remain the operator's data. Language changes are local preferences and do not request a core mutation, reset the selected project or alter guard state. UTC display uses the generated microsecond-preserving normalizer, including offset timestamps. The narrow layout wraps header controls and evidence actions without hiding them.

For a TLS node, the Windows legacy link opens `/modern/?open=legacy` in the system browser. That browser establishes its own HttpOnly session through the ordinary pairing gate, then opens `/` on the same origin. Only a non-secret navigation intent appears in the URL; no native credential or pairing code is transferred. Legacy loopback HTTP still opens `/` directly. Browser fixture tests cover both flows, and the native URL helper has a portable unit test.
