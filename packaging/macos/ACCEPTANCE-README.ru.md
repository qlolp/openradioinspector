# Два теста на Mac Air

Этот комплект проверяет пункты 2 и 4: полную нагрузку окончательной сборки и восемь часов с tinySA Ultra + AOR AR-DV1. Он не подтверждает успешную аппаратную приёмку до завершения реального прогона. Аудио, научный worker, остальные платформы, публичный релиз и полная установочная приёмка отложены.

## Подготовка

1. Нужны Apple Silicon, 16+ ГБ RAM, фактическая macOS 27.3, оба прибора и достаточно свободного SSD. Программа оценит расход по потоку; для прибора требуется восемь часов плюс 50% и отдельный резерв backup. Источники автоматически не удаляются.
2. Из артефакта **одного SHA** возьмите arm64 DMG и `OpenRadioInspector-Mac-Tests.zip`. Проверьте `SHA256SUMS`. Скопируйте приложение из DMG в `/Applications/OpenRadioInspector RC.app`, распакуйте комплект. У пользователя не нужны Python, Homebrew, Xcode или интернет.
3. Откройте приложение штатным способом для ad-hoc RC через разрешение в настройках безопасности macOS. При появлении запроса разрешите его фоновую службу. Developer ID/notarization этим комплектом не заявляются.
4. Закройте запущенный интерфейс RC. Если обычная охрана уже владеет USB, явно остановите её и освободите приборы. Тест использует отдельный архив/службу на `127.0.0.1:8774`; обычная служба на 8772 не останавливается автоматически.

## Запуск

Откройте `StartTests.command` и выберите **3 — оба теста**. Для отдельного повторения доступны 1 и 2. Результаты появляются в новом закрытом каталоге `~/Documents/OpenRadioInspector-Tests/<UTC>-<ID>/`. Не меняйте файлы комплекта или `.app` между тестами. Второй тест требует успешный `load/report.json` той же сборки; короткий smoke его не заменяет.

### Нагрузка — 30 минут

Используется настоящий подписанный `ori-core` из `.app`, отдельный синтетический архив, 18 000 предложенных свипов по 4096 точек и 18 000 наблюдений. Одновременно работают нативный график, чтение истории и online backup. Восстановление выполняется в другом каталоге с проверкой каждого исходного ID и значений.

Держите окно с графиком видимым, не перемещайте и не перекрывайте его. Разрешите **запись экрана** тестируемому RC, если macOS запросит её. Измеритель читает только маленький код в углу того же Canvas-прохода: изображения не записываются. При отказе измерение показа остаётся неподтверждённым и тест не проходит. После первого предоставления разрешения macOS может потребовать закрыть RC и повторить тест в новом каталоге.

Цели: p95 UI ≤100 мс, постановки настоящего задания исследования в очередь ≤200 мс, commit→показ ≤250 мс, панорамирование ≥30 fps. Очередь проверяется в отдельном синтетическом сеансе без запуска приборов. Предварительный прогрев не входит в 36 000 исходников нагрузки. Пропуски не исключаются из знаменателя.

Фоновое обновление состояния сеанса сохраняет обработку уже полученного свипа. Оно не подменяет новый свип предыдущим подтверждённым кадром и не запускает восстановление исправного потока. Смена сеанса, прибора и восстановление архива по-прежнему проверяют принадлежность данных.

### Приборы — восемь часов

В отдельном тестовом UI вручную запустите службу, выберите реальные USB-порты, проверьте модель/прошивку, приём tinySA, диапазон, антенну и место измерения. Создайте проект. Генератор остаётся выключенным; прошивка автоматически не обновляется.

Терминал по очереди предложит: собрать и подтвердить эталон (≥60 секунд **и** ≥20 полных совместимых свипов каждого поддиапазона), включить охрану, получить наблюдения AR-DV1 и новое событие, открыть исходник, выполнить узкий поиск и возврат, Command-Q/повторный запуск UI, отключение/возврат каждого USB и ручной сон/пробуждение. После сна служба требует явного запуска, проверки приборов и возврата охраны.

Нажимайте Enter после действия, оставляя Терминал открытым. Подтверждение оператора не заменяет проверку: контроллер наблюдает службу, наличие устройств, исходные ID и переходы состояния. Command-Q выполняйте минимум на 30 секунд; USB отключайте минимум на 10 секунд. На каждое USB-действие с восстановлением даётся 5 минут, на сон — 15 минут. Остальное время охрана работает без вмешательства. Аудио в этом прогоне отсутствует.

Минимальные интервалы 30/10 секунд выдерживает оператор; автоматический проверяющий подтверждает наблюдённые переходы, без отдельного сертификата этих коротких длительностей. Непрерывный восьмичасовой интервал измеряется Mach continuous clock. Возраст новых исходников проверяется отдельно от heartbeat: для tinySA используется максимум 10 секунд или трёх подтверждённых периодов эталона (для плана — его максимальный период возврата), для AR-DV1 — максимум 10 секунд или трёх периодов опроса плюс длительность исследования. Значения записаны в отчёте; остановившийся поток не считается работающей охраной.

При самопроизвольном тайм-ауте, проблеме архива или потере охраны текущий прогон считается неуспешным даже после восстановления. Сохраняется кольцевой журнал обмена до 64 МиБ на экземпляр ядра; автоматического перезапуска или увеличения тайм-аутов нет. После восьми часов остановите тестовую охрану по запросу: выполняются экспорт, backup и отдельное восстановление с проверкой исходников.

## Результат и остановка

Итоговые файлы: `report.json`, `load/report.json`, `hardware/report.json`; диагностика рядом, включая `core/`, `native-*`, `hardware.jsonl`, исходный SQLite и backup/restore. Успешные критерии называются `point2_passed` и `point4_passed`. `smoke_only: true` не является приёмкой.

При Ctrl-C комплект сохраняет доступную диагностику и запрашивает подтверждённую остановку только своей службы. Если сообщение `service_stop_required` осталось, откройте тестовый интерфейс и явно остановите службу. Не удаляйте `active.json`, пока её остановка не подтверждена; он защищает от запуска следующего теста поверх работающего. Не используйте убийство процессов по номеру порта.

При штатном завершении интерфейс сначала получает подтверждение освобождения ядра и снимает регистрацию именно тестового SMAppService; только после этого удаляется указатель запуска. При сбое откройте сохранённый тестовый профиль явно: `open -n -a "/Applications/OpenRadioInspector RC.app" --args --acceptance-profile "/полный/путь/к/hardware/native-N/profile.json"`, где `N` — последний каталог native. Если служба уже завершилась, используйте её явное снятие регистрации для восстановления; это само по себе не подтверждает освобождение ресурсов. Повторный успешный запуск и штатная остановка должны подтвердить владельца и освобождение. Обычный запуск RC без профиля относится к обычной службе, а не к тестовой.

Сохраните отчёты и журналы для разбора. Исходные спектры и USB-обмен могут содержать данные вашей радиообстановки; они остаются локально и автоматически никуда не отправляются.

## Для повторяемого запуска из Терминала

```bash
./StartTests.command --phase load --output-dir "$HOME/Documents/ORI-load-new"
./StartTests.command --phase hardware --load-report "$HOME/Documents/ORI-load-new/load/report.json" --output-dir "$HOME/Documents/ORI-hardware-new"
```

Путь результата должен быть новым. `--self-check` применяется сборочным CI для короткой проверки перемещённого runtime, владельца процесса, настоящего core, очереди и backup/restore; нативный показ и приборы он не проверяет.
