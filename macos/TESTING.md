# Проверка macOS без оборудования

Полная синтетическая проверка запускается из корня репозитория:

```sh
python -m tests.run_release_checks --swift
```

Runner поднимает собственные HTTP-фикстуры и временные архивы, запускает Python,
Node, Tk, обе Swift-suite и unsigned Xcode build; затем проверяет остановку
серверов и неизменность архивов. Физический tinySA smoke явно исключён.
Оборудование для этого прогона не требуется. Новые тесты `Swift Testing`
требуют Swift 6 / Xcode 16 или новее; это не меняет минимальную macOS приложения.

Для локального измерения покрытия SDK из корня репозитория:

```sh
swift test --package-path macos/SpektrKomandy --enable-code-coverage
```

Без окружения HTTP-фикстур часть интеграционных тестов SDK пропускается;
такой запуск не заменяет полный release runner. Не используйте bare
`swift test --package-path macos` как проверку без приборов: существующий
`testPhysicalTinySAUltraSmokeIfConnected` при наличии USB-порта открывает
прибор и запускает обзор. Явная аппаратная проверка описана в
[hardware-acceptance.md](../docs/release/hardware-acceptance.md).

Если вложенная sandbox SwiftPM недоступна (`sandbox_apply: Operation not
permitted`), для отдельного локального SwiftPM-запуска доступен
`--disable-sandbox`; при ошибке запуска макросов SwiftUI/Testing также доступен
`-Xswiftc -disable-sandbox`. Это локальный обход ограничения вложенной sandbox,
не изменение настроек приложения; результаты учитывайте отдельно от CI.


Путь к JSON-отчёту покрытия библиотеки:

```sh
swift test --package-path macos/SpektrKomandy --show-codecov-path
```

В отчёте учитывайте только файлы `Sources/SpektrKomandy/`: тесты и
генерируемая точка входа не должны входить в процент покрытия продукта.
Локальные отчёты и журналы не добавляются в Git.

## Добавленные проверки

- `SweepOccupancyTests`: общая с Python фикстура ответа ядра, неверные
  сводки, соответствие запросу, точный JSON-экспорт вложенных ключей
  и больших целых чисел.
- `SweepOccupancyModelTests`: единственный запрос, сохранение выбранного
  источника при polling, поздний ответ после изменения порога, отменённое
  и устаревшее сохранение, запись точного результата на диск.
- `FrequencyTextBoundaryTests`: некорректный ввод, точность 10 Гц,
  форматирование единиц, включённые границы диапазона AR-DV1,
  нулевой/отрицательный шаг, неполная сетка, переполнение `Int64`
  и ограничение числа точек. Одна дополнительная точка позволяет
  вызывающему коду обнаружить превышение бюджета сканирования.
- `TraceArchiveContractTests`: имена полей JSON, исходные отсчёты
  S-метра без преобразования в дБм, точное сохранение строк частот
  и уровней tinySA, неразобранные ответы, все комбинации флагов
  подтверждения протокола, пустой сеанс и UTC на границах дат.
  Проверки JSON независимы от обратного декодирования теми же моделями.

Измерено 2026-11-08 на полном наборе библиотеки на базе `e871194`
(до интеграции новых модулей из `adc49b0`): покрытие строк
`FrequencyText.swift` выросло с 86,92% до 100%, покрытие всех исходников
`SpektrKomandy` — с 3503/3765 (93,04%) до 3517/3765 (93,41%).
Проверки архива усиливают контрактные утверждения; его покрытие строк

AR-DV1/tinySA не выполнялась; эти тесты не подтверждают протокол прибора.

## Отчёт качества архивного свипа

`SweepQualityTests` проверяет SDK POST `/sweep-quality`, точный состав запроса,
конечные пороги (>0…200 dB, −200…100 dBm), 2…16384 точки, индексы,
целые частоты до 9007199254740991 Гц, включающие границы ≥, порядок флагов,
неизменность источника и отказ при некорректном/чужом ответе.
`SweepQualityModelTests` проверяет отмену при правке порога, выборе свипа,
смене контекста и тайм-ауте, включая поздний ответ. Тесты используют только
синтетические архивные данные. SwiftUI содержит отдельный выбор архивного свипа,
пороги 20 dB / 0 dBm по умолчанию и предупреждение: эвристика не диагностирует
перегрузку/помехи и не отбрасывает отсчёты. Периодическое обновление snapshot
не запускает расчёт и не заменяет зафиксированный источник.

Целевые проверки без оборудования:

```sh
swift test --package-path macos/SpektrKomandy --filter SweepQualityTests
swift test --package-path macos --filter SweepQualityModelTests
```

В Linux-среде разработки этого среза Swift/Xcode отсутствуют; добавление тестов
и проверка diff не означают успешной компиляции или аппаратной проверки.
