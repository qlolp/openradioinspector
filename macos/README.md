# Двойной обзор

Окно macOS для двух приборов оператора: приёмника AOR AR-DV1 и анализатора tinySA Ultra. Имя программы своё. Чужие товарные названия и чужой контейнер панорам не используются. Файл трассы — JSON с расширением `.trassa.json`.

Цифровой сигнал программа не разбирает: это делает приёмник. Уровень AR-DV1 на графике подписан как отсчёт S-метра. Уровень tinySA Ultra — дБм.

## Как открыть

Нужны macOS 14 или новее и Xcode, который собирает приложения для macOS 14.

Двойной щелчок по [`DvoynoyObzor.xcodeproj`](DvoynoyObzor.xcodeproj), схема **DvoynoyObzor**, Run.

Песочница и hardened runtime выключены, чтобы программа могла открыть `/dev/cu.*`. Подпись в проекте ручная, без команды разработчика: identity «-».

Логика команд лежит отдельно, в пакете [`SpektrKomandy`](SpektrKomandy). Проект Xcode подключает этот пакет. Те же проверки без Xcode:

```bash
cd macos/SpektrKomandy
swift test
```

## Что умеет приложение

Одно окно, два независимых порта.

**AOR AR-DV1.** Поле порта, список скоростей из описания линии (по умолчанию 115200, 8N1), кнопки «Подключить» и «Отключить». Если порта нет или путь пустой, показывается текст ошибки, процесс не падает. После открытия порта уходят `RE1`, `VR`, `RN`; в шапке сеанса видны код ответа, прошивка и номер. Обзор: границы F1–F2, шаг из списка `ST`, режим AM или FM с выключенной цифрой (`MD0F1` / `MD0F0`), цикл `RF`, пауза, `LM`. Ответ на `RF` читается до паузы, чтобы не смешать его с `LM`. Перед циклом один раз выбирается VFO-A (`VFA`). График текущей трассы, минимума и максимума, горизонтальный порог. Список превышений: частота середины, ширина, число попаданий. Выбор строки останавливает цикл и ставит эту частоту; звук остаётся на динамике приёмника. При отключении уходит `EX`. Трасса пишется в `~/Documents/Двойной обзор/`. Под графиком — водопад: строка на каждый законченный свип, свежая сверху, шкала цвета подстраивается под видимые строки.

**tinySA Ultra.** Поле порта (с автоматическим выбором обнаруженного `usbmodem`) и те же кнопки. Проверено и подтверждено на реальном приборе tinySA Ultra (прошивка `tinySA4_v1.4`, плата `ZS405`):
- Конец команды с ПК — байт CR (`0x0D`). Ответ прибора завершается приглашением командной строки `ch> `.
- При подключении опрашиваются `info`, `version` и `deviceid`. Идентификатор прибора сверяется со снимком консоли («tinySA ULTRA» и «tinySA4_»).
- Последовательность настройки обзора: `output off`, `mode input`, `lna off`, `attenuate auto`, `rbw 30`, `calc off`.
- Цикл свипа: `scan 100k 800M 290 3`. Прибор отдаёт 290 точек спектра по 3 столбца на строку (частота в Гц, уровень дБм в экспоненциальной форме, вспомогательное поле).
- Время одного свипа в полосе 100 кГц – 800 МГц при `rbw 30` составляет ~35 секунд.
- Расчёт и отображение текущей трассы, минимальной и максимальной огибающей, порога и списка превышений.
- Под графиком — водопад: строка на каждый принятый ответ `scan`, свежая сверху, шкала цвета по видимым строкам.
- Автоматическое сохранение трассы в файл `~/Documents/Двойной обзор/tinysa-*.trassa.json`.

Если в поле порога число выше +0 дБм, показывается предупреждение про потолок входа. Это линия на графике: программа уровень на прибор не отправляет. Выбор строки списка передаёт частоту в AR-DV1 и не останавливает анализатор.

## Чего в срезе нет

Справочник разрешений, нормы, задания, карта, калибровка в дБм и в напряжённость, запись звука, смена цифры на каждом шаге, TETRA, GSSI, подбор закрытого трафика. У анализатора не включаются LNA и режим ultra, не шлются команды базового tinySA и Ultra+, `scanraw`, `hop`, правка калибровки. Полоса `IF` не шлётся: номер для 8 кГц в источниках расходится. Команда смены скорости `SB` не шлётся.

## Статус гипотез на живых приборах

1. **Конец строки команды Ultra.** Подтверждён один байт CR (`0x0D`), см. `UltraCommand.terminator`. Ответ каждого шага оканчивается маркером `ch>`.
2. **Ширина поля LM (AR-DV1).** В описании одновременно `LMkkc` и `LMkkkc`. Разборщик забирает последним символом код шумодава, остальное считает уровнем и помечает ширину как неподтверждённую до проверки с живым приёмником.
3. **Пауза шага AR-DV1.** Стартовые 25 мс не подтверждены на текущей прошивке. Поле в окне меняется. Серия одинаковых отсчётов (старт — 10) останавливает обзор и не шлёт сброс.
4. **Скорость USB-консоли Ultra.** Является CDC-ACM виртуальным последовательным портом. Для `termios` используется 9600/115200.
5. **Место двух цифр кода `RE1`.** Разборщик ставит их в начало строки, образца целой строки в описании нет.
6. **Раскладка строк `scan` с маской 3 (Ultra).** Подтверждена на реальном приборе: строки содержат 3 столбца (частота, уровень дБм в экспоненциальной записи, вспомогательное поле).
7. **Текст `info` / `version` (Ultra).** Подтверждён на физическом устройстве: `tinySA ULTRA ZS405` / `tinySA4_v1.4-235-gea71dfd`.

## Проверки на Mac

Кроме пакета команд, есть macOS-тесты управления сеансами, закрытия окна и транспорта:

```bash
cd macos
swift test
swift test --package-path SpektrKomandy
```

Тесты используют scripted transport и локальные Unix-сокеты, не открывают `/dev/cu.*`.
Проверка окна посылает уведомление закрытия тестовому окну, а не запускает аппаратный обзор.
При отмене уже отправленной команды программа дочитывает ответ в пределах текущего
тайм-аута. Если ответ не завершён, соединение закрывается и требуется новое подключение.
Это исключает повторное использование запоздалого ответа; кнопка остановки может ждать
ответа до действующего тайм-аута (для Ultra scan — до 90 секунд).
