# Двойной обзор

Окно macOS для двух приборов оператора: приёмника AOR AR-DV1 и анализатора tinySA Ultra. Имя программы своё. Чужие товарные названия и чужой контейнер панорам не используются. Файл трассы — JSON с расширением `.trassa.json`.

Цифровой сигнал программа не разбирает: это делает приёмник. Уровень AR-DV1 на графике подписан как отсчёт S-метра. Уровень tinySA Ultra — дБм.

## Как открыть

Нужны macOS 14 или новее и Xcode, который собирает приложения для macOS 14.

Двойной щелчок по [`DvoynoyObzor.xcodeproj`](DvoynoyObzor.xcodeproj), схема **DvoynoyObzor**, Run.

Песочница и hardened runtime выключены, чтобы программа могла открыть `/dev/cu.*`. Подпись в проекте ручная, без команды разработчика: identity «-».

Логика команд лежит отдельно, в пакете [`SpektrKomandy`](SpektrKomandy). Проект Xcode подключает этот пакет. Те же проверки без Xcode:

```bash
cd macos/SpektrKomandy
swift test
```

`swift test` для пакета команд здесь прошёл: 25 тестов, Swift 6.0.3, Linux. Это не сборка приложения. Xcode и `xcodebuild` на этой машине нет, цель `DvoynoyObzor` не компилировалась. Её нужно собрать на Mac.

## Что умеет первый срез

Одно окно, два независимых порта.

**AOR AR-DV1.** Поле порта, список скоростей из описания линии (по умолчанию 115200, 8N1), кнопки «Подключить» и «Отключить». Если порта нет или путь пустой, показывается текст ошибки, процесс не падает. После открытия порта уходят `RE1`, `VR`, `RN`; в шапке сеанса видны код ответа, прошивка и номер. Обзор: границы F1–F2, шаг из списка `ST`, режим AM или FM с выключенной цифрой (`MD0F1` / `MD0F0`), цикл `RF`, пауза, `LM`. Ответ на `RF` читается до паузы, чтобы не смешать его с `LM`. Перед циклом один раз выбирается VFO-A (`VFA`). График текущей трассы, минимума и максимума, горизонтальный порог. Список превышений: частота середины, ширина, число попаданий. Выбор строки останавливает цикл и ставит эту частоту; звук остаётся на динамике приёмника. При отключении уходит `EX`. Трасса пишется в `~/Documents/Двойной обзор/`. Под графиком — водопад: строка на каждый законченный свип, свежая сверху, шкала цвета подстраивается под видимые строки.

**tinySA Ultra.** Поле порта и те же кнопки. Скорость USB-консоли в описании прибора не задана: для `termios` стоит заглушка 9600, её надо сверить. При подключении читаются `info`, `version` и `deviceid` (пользовательский номер, не заводской серийный). Если текст не похож на снимок консоли Ultra, обзор сам не начинается: сырой ответ остаётся на экране, продолжение — отдельной отметкой. Команды обзора, и только они: `output off`, `mode input`, `lna off`, `attenuate auto`, `rbw 30`, `calc off`, затем повтор `scan 100k 800M 290 3`. График в дБм. Водопад ниже: строка на каждый ответ `scan`, свежая сверху, шкала цвета по видимым строкам. Если в поле порога число выше +0 дБм, показывается предупреждение про потолок входа. Это линия на графике: программа уровень на прибор не отправляет. Выбор строки списка передаёт частоту в AR-DV1 и не останавливает анализатор.

Команды собраны в типах пакета `SpektrKomandy`, их кадры проверяются без приборов.

## Чего в срезе нет

Справочник разрешений, нормы, задания, карта, калибровка в дБм и в напряжённость, запись звука, смена цифры на каждом шаге, TETRA, GSSI, подбор закрытого трафика. У анализатора не включаются LNA и режим ultra, не шлются команды базового tinySA и Ultra+, `scanraw`, `hop`, правка калибровки. Полоса `IF` не шлётся: номер для 8 кГц в источниках расходится. Команда смены скорости `SB` не шлётся.

## Что сверить на живых приборах

Без прибора это не проверялось.

1. **Конец строки команды Ultra.** В описании байт не назван. В коде выбран один байт CR (`0x0D`), см. `UltraCommand.terminator`. Ответ читается до паузы тишины 0,25 с — это тоже выбор программы, не описание прибора.
2. **Ширина поля LM.** В описании одновременно `LMkkc` и `LMkkkc`. Разборщик забирает последним символом код шумодава, остальное считает уровнем и помечает ширину как неподтверждённую.
3. **Пауза шага AR-DV1.** Стартовые 25 мс не подтверждены на текущей прошивке. Поле в окне меняется. Серия одинаковых отсчётов (старт — 10) останавливает обзор и не шлёт сброс.
4. Заглушка скорости 9600 у USB-консоли Ultra.
5. Место двух цифр кода `RE1`: разборщик ставит их в начало строки, образца целой строки в описании нет.
6. Как текст `scan` с маской 3 раскладывается на частоту и дБм. Тест гоняет гипотезу «два поля в строке», это не образец с прибора.
7. Совпадает ли нынешний текст `info` / `version` со снимком консоли.

Если `swift test` на Mac проходит, это проверка сборки кадров и разборщиков, не проверка эфира.
